# Review batch M1: Mod panel

Pages: `/mod` (overview), `/mod/activity`, `/mod/users`, `/mod/users/[username]` and `/mod/trades`, plus the mod access test. Reviewed 2026-10-15 against the seeded review data (`docs/review.md`), signed in as the seeded mod `review_mod` through the fake Twitch.

## Method

- **Access test**: `node scripts/sweep-mod-access.mjs` (runtime) and `scripts/check-staff-guards.mts` (static, in `npm run check`) as a stranger, a mod and an admin: every `/admin` page sends a mod to `/mod`, every `/api/admin` route refuses a mod apart from the activity feed, the `/mod` pages work for the mod. Nobody got anywhere they should not.
- **Sweep** (`node scripts/sweep-admin.mjs /mod ...`) of every mod page, restricted-only list, viewers with restrictions, a viewer with 3,000 copies, the long-named viewer, an unknown viewer and an unknown path, at 390, 768 and 1280 px: first run flagged horizontal overflow on every viewer page at 390 px; clean after the fixes.
- **Hand pass** with screenshots: Overview, a viewer page, Trades, Viewers, Activity.
- **Actions in a browser** as the mod: add a tag, set Block trading with a reason, save, see "Restrictions set by review_mod" and "Tags changed by review_mod" under What staff did, check the viewer really cannot trade ("Trading isn't available on your account."), clear it; Cancel & refund on a viewer's open offer (arms, relaxes, then cancels and refunds); the viewers search and the Restricted-only filter; the activity detail panel (only "Show only them", no gift, grant or remove).

## Findings

### Bugs (fixed)

- **Every viewer page overflowed sideways on a phone** (65 to 149 px), so the whole page scrolled. Three causes: the page's two-panel grid had no explicit single column below `lg` (the Restrictions panel widened it), the tag suggestion buttons did not wrap, and a long username in the page heading could not break. Now `grid-cols-1`, wrapping suggestions, and `break-words` on the shared `PageHeader` heading (which also helps the admin pages).
- **Hydration mismatch on `/mod/activity` (and `/admin/activity`), intermittently**: the feed started its "now" from the browser's clock instead of the server's, so relative times and last-hour counts could differ from the server's HTML by a minute boundary ("Hydration failed because the server rendered text didn't match the client"). The page now passes the server's clock in (`serverNow`), used for the first client render. Seen in about three of five loads before; none in eight after.
- **Dates in the shared viewer panels and the mod viewer page used the machine's locale**: the server (en-US on Vercel) and a UK browser print them differently, which is another hydration mismatch (the trades panel is a client component rendered on the server too) and made "first seen" read as a US date. They now use `en-GB`, like the rest of the site.
- **Cancel & refund acted on a single click** (on the viewer page, shared with the admin user page, and in the trade log detail), although it removes another viewer's offer. It now asks for a second click ("Sure?", relaxing after four seconds) through a small shared `ArmedButton`.
- The Reason field's placeholder said "only admins see this"; mods can read and write it, and the panel says "only seen by staff". It now says "Reason (only staff see this)".

### Improvements (all done afterwards, see the follow-up)

1. "Block from trading" in the trade log used the browser's own `window.confirm`.
2. The admin pages share these panels and several used their own date formatting.
3. The Overview's "Events, last hour" counts from a limited window, not the whole hour.

### Panel

Nothing found.

## Close-out

Sweep clean at all three widths, access test clean, no console errors, `npm run verify` passes.

## Follow-up: the improvements, done (2026-10-15)

1. **Block from trading** now uses `ArmedButton` ("Sure? Block <name>", the explanation in the tooltip) instead of the browser's confirm.
2. **Date formatting in client components**: every client component that printed a Date in the machine's locale (the activity feed and its detail panel, the Unused assets panel, the Overlay Editor's saved versions, the trade log, the users list) now uses `en-GB`, and `scripts/check-locale.mts` (part of `npm run check`) fails if one comes back. Phone-width sweeps of the admin pages themselves are still for batches A1 to A8.
3. **The Overview tile** says "of the latest 200 events" (the window it counts from).
4. **Requested during this batch: a way back to the public site.** The mod panel's top bar has a Public site link (home icon alone on a phone) that goes to `/`; staff stay signed in and the site shows them their panel link as before.
