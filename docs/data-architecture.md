# Data architecture

> Read this when you touch how seasons, packs, cards, collections or user profiles are stored in KV.

Three tiers in Vercel KV: **Seasons → Packs → Cards**.

- **Seasons** (`season:{id}`, index `seasons:list`): metadata + `packIds: string[]`. One season active at a time.
- **Packs** (`pack:{id}`, index `packs:list`): global, not owned by a season; one pack can be in several seasons. Cards live at `pack:{id}:cards`.
- **Collection** (the hash `coll:{collectionName}`, ROADMAP 48.7): one field per viewer, field = lowercase login, value = JSON `number[]`. **The source of truth for user data**, written by the overlay via `/api/collection`. A viewer with no cards has no field. Readers: `getCollection(c)` (HGETALL, the whole season: leaderboard, search, admin lists) and `getUserCards(c, login)` (HGET, one viewer). Writers: `updateCollection(c, logins, fn)` inside `withCollectionLock` writes only the viewers named (HSET the changed ones, HDEL the emptied ones; `fn` returns `{ result, cards?, ctx? }`), and `saveCollection(c, data, ctx?)` takes a whole record but diffs it against the stored one and writes only the viewers that differ. `moveCollectionCards` renames a viewer for the account move. The lock is still `lock:tcg_{c}`, one per season, taken after any trade lock. **Old layout**: the season used to be one JSON string `tcg_{collectionName}` (`{ username: number[] }`). The first read or write of a season that is still a string moves it (`ensureMigrated`): it builds `coll:{c}:new`, checks the viewer and entry counts, `RENAME`s it into place, then renames the string to `tcg_{c}:old` (kept 30 days as the rollback copy; viewers with empty lists are dropped). The move runs under the season's lock, so two instances starting together move it once, and a reader never sees a half-built hash. A season that never existed migrates to nothing. The log of moves is the hash `collmig` (collection -> `{ viewers, entries, at }`), shown in Data health (docs/hosting.md). Duplicates are intentional: each entry is one pull. Unique count is `new Set(array).size`; everywhere that shows cards builds a `Map<number, count>` and shows a `×N` badge when count > 1.
- **User profiles** (`user:{username}:profile`; `getUserProfiles(names)` in `lib/kv.ts` reads many with one `mget` per 100 names, for lists: use it instead of `getUserProfile` in a loop) and **Twitch opaque mapping** (`twitch_opaque:{opaqueId}` → lowercase username). Sign-in also records the Twitch account behind each login (`lib/account-bind.ts`): the hash `acct:ids` (Twitch ID → login, written once) and the hash `acct:conflicts` (login → `{ storedId, newId, seen, count }`, when a different account signed in on a login whose profile holds another ID and the old profile could not be moved aside; otherwise the sign-in moves it aside, see below). Both go through the sandbox-aware `kv`, and a sandbox sign-in records neither. The nightly Twitch check (`lib/account-helix-check.ts`) backfills `acct:ids` with `hsetnx` for profiles that predate it (profiles reached through `acct:ids` or the collections), and saves its last run in the string key `acct:helixcheck` (`{ at, checked, missing, renamed[{from,to}], needsStaff[{login,id,twitchLogin,why}], error? }`, replaced each run, lists capped at 50).
- **Moving an account aside** (`lib/account-move.ts`, admin **Move aside**): the hash `acct:moves` (login -> `{ to, id, reason, startedAt, done[] }`) is the journal of a move in progress, deleted when it finishes; the hash `acct:aside` (new login -> `{ id, login, movedAt, reason, flags?, tester?, declined? }`) records each finished move aside: `flags` is the account's `adminHidden` / `selfHidden` as they were (restored when it moves back), `tester` its tester record (carried back), `declined` set when the owner chose "Keep it separate" on their profile Stats tab. The journal also holds `mode` (`'aside'`, the default, or `'rename'`), `replaceBlank`, and the `flags` / `tester` captured when the move started so a resumed step does the same thing. **Aside** hides the account (admin hidden and private), appends " (former)" to its display name once and writes the `acct:aside` record. **Rename** (a Twitch rename, a restore from the profile Stats tab, or staff) does none of that: nothing is hidden, the tester record moves with the account, and if the source is a `~` login its saved flags come back, " (former)" is stripped and its `acct:aside` record is deleted. `replaceBlank` lets the target hold a profile or settings as long as it has no cards; the moved data overwrites them. The new login is `<login>~<n>` (first free); `acct:ids` is repointed to it. The move re-keys the profile, settings, achievements, buffs, notifications, restore points, Discord link, score history and bonus, the collection entries (`moveCollectionCards`: one HSET writes the target and empties the source, then the source field is deleted, so a resumed step never adds twice) and the copy ledger's live owner hash (`renameOwner`, same copy ids), and rewrites `trades:history`. Open offers are cancelled and refunded first; cooldowns, the tester record and opaque links are dropped; the old login stays free.
- Users are read with `getAllCollectionUsers()` in `lib/kv.ts` (aggregates every season's collection).
- `normalizeSeason` / `normalizePack` in `lib/kv.ts` handle legacy shapes on read, so KV never needs manual migrations.
