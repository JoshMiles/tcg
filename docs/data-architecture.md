# Data architecture

> Read this when you touch how seasons, packs, cards, collections or user profiles are stored in KV.

Three tiers in Vercel KV: **Seasons → Packs → Cards**.

- **Seasons** (`season:{id}`, index `seasons:list`): metadata + `packIds: string[]`. One season active at a time.
- **Packs** (`pack:{id}`, index `packs:list`): global, not owned by a season; one pack can be in several seasons. Cards live at `pack:{id}:cards`.
- **Legacy collection** (`tcg_{collectionName}`): `{ username: number[] }`. **The source of truth for user data**, written by the overlay via `/api/collection`. Duplicates are intentional: each entry is one pull. Unique count is `new Set(array).size`; everywhere that shows cards builds a `Map<number, count>` and shows a `×N` badge when count > 1.
- **User profiles** (`user:{username}:profile`) and **Twitch opaque mapping** (`twitch_opaque:{opaqueId}` → lowercase username). Sign-in also records the Twitch account behind each login (`lib/account-bind.ts`): the hash `acct:ids` (Twitch ID → login, written once) and the hash `acct:conflicts` (login → `{ storedId, newId, seen, count }`, when a different account signed in on a login whose profile holds another ID and the old profile could not be moved aside; otherwise the sign-in moves it aside, see below). Both go through the sandbox-aware `kv`, and a sandbox sign-in records neither.
- **Moving an account aside** (`lib/account-move.ts`, admin **Move aside**): the hash `acct:moves` (login -> `{ to, id, reason, startedAt, done[] }`) is the journal of a move in progress, deleted when it finishes; the hash `acct:aside` (new login -> `{ id, login, movedAt, reason, flags?, tester?, declined? }`) records each finished move aside: `flags` is the account's `adminHidden` / `selfHidden` as they were (restored when it moves back), `tester` its tester record (carried back), `declined` set when the owner chose "Keep it separate" on `/account`. The journal also holds `mode` (`'aside'`, the default, or `'rename'`), `replaceBlank`, and the `flags` / `tester` captured when the move started so a resumed step does the same thing. **Aside** hides the account (admin hidden and private), appends " (former)" to its display name once and writes the `acct:aside` record. **Rename** (a Twitch rename, a restore from `/account`, or staff) does none of that: nothing is hidden, the tester record moves with the account, and if the source is a `~` login its saved flags come back, " (former)" is stripped and its `acct:aside` record is deleted. `replaceBlank` lets the target hold a profile or settings as long as it has no cards; the moved data overwrites them. The new login is `<login>~<n>` (first free); `acct:ids` is repointed to it. The move re-keys the profile, settings, achievements, buffs, notifications, restore points, Discord link, score history and bonus, the collection blobs and the copy ledger's live owner hash (`renameOwner`, same copy ids), and rewrites `trades:history`. Open offers are cancelled and refunded first; cooldowns, the tester record and opaque links are dropped; the old login stays free.
- Users are read with `getAllCollectionUsers()` in `lib/kv.ts` (aggregates every season's legacy collection).
- `normalizeSeason` / `normalizePack` in `lib/kv.ts` handle legacy shapes on read, so KV never needs manual migrations.
