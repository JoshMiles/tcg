# OBS overlay

> Read this when you touch `public/widget.js`, `widget.css`, the Overlay Editor, scenes, overlay properties, the show-off command, quick actions or the only-when-live switches.

## OBS widget data flow
1. Widget calls `GET /api/seasons/active` on load → returns `{ season, packs: [{ pack, cards }] }`
2. A real pull is **rolled by the server** when it is queued (`lib/draw.ts`, `issueDraw`: pack by weight, card by probability, version by the pack's weights); the queue event carries `draw: { packId, cardNumber, variant }` and the event `id` is the pull's one-use **ticket** (KV `draw:<id>`, 12 h). The overlay plays exactly that draw (the pinned-draw path of `pickPackAndCard`); only the test panel and the editor preview roll in the browser.
3. Widget calls `POST /api/collection` with `{ pull: { username, ticket, ... } }`. The server claims the ticket (viewer must match, once only) and saves **what the ticket says**, not what the request says: a request without a valid ticket gets 401 and saves nothing. If a Mix It Up payment is attached (`paid`) it is charged first (docs/admin.md); the reply may be `{ ok: true, revoked: true, owned }` when the payment failed, and the widget just resyncs `owned`. Replacing a collection (`data`) and `DELETE` need a staff session, so the test panel's Reset buttons and "Don't save" off only work from a browser signed in to the admin, never in OBS. Pulls queued before tickets existed have no `draw` and are not saved.
4. Widget reads `GET /api/collection?name={collectionName}` to show mini-list with ×N badge for duplicates. That read requires the overlay key or a staff session (the same check as the queue), so it is not a public dump of every viewer's pulls.

The widget reads per-pack visual settings (accentColor, tearBorderColor, holoMinStars, cardTime, cooldownTime, soundVolume, coverImageUrl) directly from the pack object. Card sounds come from `card.soundUrl` (e.g. `/assets/sounds/1.mp3`).

## The overlay key
The overlay has no login, so the endpoints it uses to take queued pulls (`GET /api/webhooks/queue`), report shown collections (`POST /api/webhooks/notify`), read the on-stream collection (`GET /api/collection`) and check in (`POST /api/overlay/heartbeat`) require the **overlay key** (`lib/overlay-key.ts`, KV `overlay:key`). The OBS address is `/overlay.html?key=<key>`; `widget.js` reads `key` from its own URL and sends `x-overlay-key` on every request. `isOverlayRequest` also accepts a staff session (editor preview, `?dev` tabs while signed in) and a sandbox. Settings → OBS Overlay shows the address and can make a new key (the old OBS addresses then stop working); the Overlay Editor, the sidebar Copy URL button and the palette copy the address with the key. A refused overlay shows "Overlay key missing or changed" on screen. ROADMAP 13.2.

## Overlay status & quick actions
- **Connection indicator**: each overlay page load picks a random id and sends a heartbeat every 10s (`lib/overlay.ts`, KV hash `overlay:clients`); a client counts as connected for 25s after its last heartbeat. `OverlayStatusProvider` (in the admin layout) polls `/api/admin/overlay-status` once every 5s and `OverlayStatus` (sidebar + dashboard header) and `QuickActions` read it. Open the overlay in a normal browser tab and it shows as "browser tab".
- **Live detection**: if OBS grants the browser source *Page permissions → "Read access to OBS status information"*, the widget calls `window.obsstudio.getStatus()` and reports `streaming`/`recording` (and re-reports on the `obsStreamingStarted/Stopped` events). Without that permission those stay `null` and the UI says only "connected". It cannot know the stream is live any other way.
- **Quick actions** (dashboard): `quickAction` in `actions.ts` dispatches on the submit button's `intent` (gift packs, show collection, grant card); `clearQueueAction` empties the overlay queue. Gift/show enqueue the same events the webhooks do (`enqueueEvent`) and are refused with a "queue anyway" option when no overlay is connected, so packs can't pile up unseen. They return an `ActionResult` shown inline via `useActionState`. Keep form fields controlled, React resets uncontrolled fields after a form action. `/admin?gift=<username>` prefills the viewer (the users list 🎁 link uses it).
- **Users list**: rows are one stretched link to `/admin/users/[username]` (profile editing lives there), sortable via `?sort=cards|pulls|active|name`; "last active" comes from the latest 500 activity events.

## Overlay layout (Overlay Editor → Layout)
The overlay is drawn on a fixed **design stage** (default 1280×720, `lib/overlay-layout.ts`) and scaled to fit the real OBS browser source, so a differently sized source never cuts the animation off (the pack opening spans about -425px..+208px around its centre, which `.pack-fit` re-centres). The browser-source size is shared, but **the pack opening and the collection view are placed independently**: `OverlayLayout = { width, height, pack: Placement, collection: Placement }` (`Placement` = `scale`, `offsetX`, `offsetY`, design px) in KV `overlay:settings.layout`; `sanitizeLayout()` upgrades the old single-placement shape (both views inherit it, so nothing moves). `GET /api/overlay/config` serves it and `widget.js` `applyLayout()` writes `--stage-scale` (the fit, on `.container`) plus `--pack-*` / `--col-*`; each theater wrapper gets `.is-pack` or `.is-collection`, which place themselves with the standalone `translate` / `scale` properties (so they stack with the animations' own `transform`s). The editor (the **Layout** category of `OverlayEditor`) has a Pack opening / Collection switch (each with size, X/Y, Center, Reset), numeric X/Y/size (dragging and nudging happen on the canvas, see Editor below), browser-source size presets, and shows the real overlay in an iframe (`/overlay.html?preview`), pushing changes by `postMessage` (`layout`, `static`, `pack`, `collection`). While nothing animates the preview shows a **still** of the settled pack opening or of the collection view (`showStatic()` in `widget.js`, wrapper class `.static-preview`) so it can be sized and moved; **Play** runs the real animation and the still comes back when the queue goes idle. The editor re-sends the layout on every iframe `load` (an iframe starts as a blank page that already reads "complete", so a one-off ready flag races); **preview mode never touches the queue, heartbeat or collections** (no polling, no saving, no sound, fake `preview` user), keep it that way. `sanitizeLayout()` clamps everything, server-side too. The collection grid still wraps at 800px (`.card-wrapper { max-width: 800px }`). **Element layers**: each view's `Placement` can also carry `elements`, single parts moved on their own (`ELEMENT_IDS` in `lib/overlay-layout.ts`: pack `card, label, serial, bar, got, strip, showlabel`; collection `heading, grid`; they match the preview's `data-edit` tags). An entry is `{ scale, offsetX, offsetY }` relative to the part's normal CSS spot, so an empty or absent `elements` is today's look and old layouts need no migration. `sanitizeLayout()` drops unknown ids and ids of the other view, clamps offsets to the stage and scale to 0.25..3, and omits default entries. Positions are global or per scene only (never per pack); scenes carry them inside their layout. `applyLayout()` writes `--el-<id>-x/-y/-s` on the root and `widget.css` applies them with standalone `translate` / `scale` on `.main-card`, `.card-label`, `.serial-badge`, `.card-info-overlay`, and `.user-text` / `.card-mini-list` (per `.is-pack` / `.is-collection`), so they stack with every reveal's keyframes (which animate `transform` / `rotate` only; keep it that way). Parts inside `.card-box` (card, label, serial, bar) move relative to the card; their offsets are divided by `--card-scale` so one design pixel of offset is one design pixel on stage, and a drag follows the pointer at any card size. The show-off reuses the pack opening's positions: its label is the same `.user-text`, so `styleShowLabel()` adds `--el-showlabel-*` to the label's own X / Y nudge instead of the `got` position. The moment banner has no element id yet.

## Overlay scenes (one overlay URL per OBS scene)
A **scene** is a preset (`OverlayPreset` in `lib/overlay-settings.ts`) that may also carry its own **layout** (stage size + pack / collection placement). Every preset has its own overlay URL, `/overlay.html?preset=<id>`: `widget.js` `loadLayout()` passes it to `GET /api/overlay/config?preset=<id>`, which returns the scene's layout (when it has one, else the global layout) and layers the scene's values over the global look and the season's look (pack overrides still win). An unknown id is just the global overlay. Use a different URL in each OBS scene, e.g. a vertical one. Caveats: the queue is shared, so whichever open overlay polls first plays a pull (OBS only keeps the visible scene's source running by default); a scene's values are overrides, so it follows later global changes except for what it sets itself.
- **Editing**: the Overlay Editor's **Editing** menu has a "Scenes" group (`scope = "scene:<id>"`), and the **Scene → Scenes** panel lists every preset with its URL (Copy / Open / Edit) and creates a new scene (Landscape = a copy of the global layout, Vertical = a 1080 × 1920 stage via `sceneLayout()`). A scene's values live beside the pack overrides in the editor state (`packVals["scene:<id>"]`, stored with `keepDefaults`, so one equal to the default still beats a global value) and its layout beside the global one (`layoutMap`); one Save posts `{ layout?, global?, packs, scenes: { id: { props, layout } } }` and `saveOverlayEditorAction` calls `updateScene`. The Layout panel offers vertical size presets (`VERTICAL_LAYOUT_PRESETS`), a Rotate button and, for a vertical stage, a hint with a one-click "4 cards per row" (`collection.perRow`), since the collection grid wraps to the stage width. Scenes are not part of saved versions (those cover the global look only). `scripts/check-overlay.mts` covers it.

## Show off a card (chat command)
A viewer types a chat command (e.g. `!show shiny gouda goat`); the streamer's bot calls `POST /api/webhooks/show-card` with `{ secret, username, card }` and the overlay shows that card. The command name is the bot's, not ours.
- **Parsing is pure** (`lib/showoff.ts`: `parseShowQuery`, `resolveCard`, `pickShowVariant`; `scripts/check-showoff.mts`): an optional version word (shiny / full art / reverse holo / regular…), then a card name or number; empty = their pinned print, else the first showcase pick they still hold, else their most valuable card. Owned cards win over unowned name matches; no version asked = the best owned version.
- **The server decides** (`lib/showoff-prepare.ts`, `prepareShowOff`): the card must be in the active season and owned by the viewer in that version, the serial sent is their lowest copy of it (with its serial-bonus multiplier), and the per-viewer cooldown (`showoff:cd:<user>`, 15 s) is taken LAST so a refused request doesn't spend it. The route answers 200 with `{ ok: false, error, message }` on refusals so bots can say `message` in chat; success returns `{ ok, message, card, variant, serial }` and queues a `card` event (`QueuedEvent`: `cardNumber`, `variant`, `serial`, `serialMult`). It goes through `liveGate('collection')` and logs a `trigger` activity (`kind: 'card'`, shown in the feed / dashboard / Discord).
- **Overlay**: `pollWebhookQueue` → `queueShowCard(user, ev)` → `drawCard(user, { show: ev })`: the card/variant are pinned, nothing is saved or added to the collection, the strip is hidden, and the serial pill comes from the event. Its look is the **Show off** group of the Overlay Editor (all `show.*` keys, below). Test panel: **Show off card [W]** (dry, sample serial). `scripts/check-showoff-server.mts` (mock KV) covers ownership, cooldown, serial, and the bare command: pinned print, else showcase, else best card. A dry run still queues nothing.

## Overlay properties (Overlay Editor)
Every adjustable aspect of the overlay's look is a **property** in one registry, `lib/overlay-props.ts` (`PROPS`, grouped by `PROP_GROUPS`): a dotted key (`collection.perRow`, `reveal.style`, `variant.shiny.holoSpeed`), a type (`number` / `boolean` / `select` / `color` / `colors` / `text`), default, limits, help text, optional `experimental`. **The defaults reproduce the original look exactly**, so an untouched install is unchanged. The editor UI, validation, reset, presets and import/export are all generated from the registry, to add a property: add one entry there, then consume it in `widget.js` (read it with `pv(P, key, fallback)`); add a `dependsOn()` rule in the editor if another switch turns it off.
- **Storage is sparse**: only values that differ from the default are saved (`sanitizePropValues`, which also drops unknown keys / invalid values). Global values: KV `overlay:settings.props`. **Per-pack overrides**: KV `overlay:packprops` (`{ [packId]: values }`, kept off the Pack object because pack forms rewrite the whole pack). These use `{ keepDefaults: true }` because an override equal to the default must survive when the global value isn't the default. Named presets: KV `overlay:presets` (max 30; saving an existing name replaces it). All in `lib/overlay-settings.ts`.
- `GET /api/overlay/config` returns `{ layout, defaults, props, packOverrides, backs, fonts }`; the widget (`loadLayout()`) merges defaults → global → the pack's override in `effectiveProps(packId)`. The **collection view uses global values only** (it isn't pack-specific; the editor hides that group in pack scope). The config is read once at load, so OBS needs a browser-source refresh after saving (the editor says so).
- **Categories** (`PROP_GROUPS`): **Pack opening** (`reveal.*`: animation, card size, label incl. `labelOwned` and `reveal.labelFont`, name/stars bar, "got:" line, start delay, pack size, and the row of cards under the revealed card. Its own `reveal.strip*` settings). **Fonts**: `text.font` (Pack opening, section Text, default site display = today's stylesheet faces) is the overlay font, and a pack override can set its own. Every text layer also has its own select that defaults to `inherit` ("Overlay font") and otherwise offers the same `BACK_FONTS` faces: `reveal.labelFont` (card label), `reveal.serialFont` (edition pill), `reveal.cardNumberFont` (corner numbers), `reveal.nameFont` (name bar), `reveal.gotFont` ("got:" line), `reveal.stripFont` ("?" and ×N in the strip), `show.labelFont`, `moment.*.font` (banners), `collection.headingFont` and `collection.cardFont`. In `widget.js`, `applyTextFont(el, id, P)` resolves `inherit` to `text.font`; site display clears the inline family, any other id loads the card-back file. Not covered: the `#alert` bar and the dev panel (not themed), the card back's own text (set in the Card back editor)., **Variants** (`variant.regular|reverse|full|shiny|golden.*`, each `PropDef` carries `variant`: label, a per-variant **reveal animation override**, holo, glow, pop, 3D tilt, rocking, **light burst** (on/off, strength, size, ray count, spin time, colour, hue cycle), sparkles, time and sound; pack workspace links directly via `/admin/overlay?pack=<id>&group=variants`) and **Collection** (`collection.*`, the "show collection" view, global only). The strip and the collection view deliberately do NOT share keys. Group membership is metadata only, stored values are keyed by the dotted key, so regrouping never migrates data (note: `collection.*` card-look values saved before the strip got its own keys no longer affect the strip).
- **Reveal styles** (`REVEALS` in `widget.js`): classic (the original), simple (zoom), slide, flip (card back = the pack cover, `.card-back`, edge-on at 55% of the keyframes), and the experimental **rip-shake** (pack trembles, tear strip flies off, card bursts out) and **rip-peel** (tear strip peels back from one end). Each style names its keyframes plus when (seconds at 1×) the card is revealed / info / label appear; `reveal.speed` divides every duration *and* timeout. Hold time = `label time + 0.8s + pack.cardTime` (classic = the old `cardTime + 4s`). More styles: **rip-slice** (tear strip slides straight off sideways), **rip-explode** (pack swells, flashes white, bursts), and the pack-less **drop**, **spin**, **impact** and **deal**. `variant.X.style` (default `inherit`) overrides the pack opening's style per variant (e.g. Full Art Holo always rips); `reveal.startDelay` adds seconds to every animation delay and timeout (`D` in `drawCard`); `reveal.packScale` uses the standalone `scale` on `.package-container`. The light burst is per variant: `burstSpec()` / `buildRays()` rebuild the rays (`--ray-step`) and size the container (`reveal.showBurst` / `reveal.burstOpacity` no longer exist; unknown keys are dropped on read, so old values vanish harmlessly).
- **Per-version looks are CSS variables** written on each theater wrapper by `applyLook()` (`--label-bg`, `--holo-*`, `--glow-*`, `--pop-*`, `--rock-amt`, `--burst-a/b`), and `mainCardAnimation()` composes the card's `animation` list from the generic keyframes (`variantPop`, `variantGlow`, `variantRock`, rock uses the standalone `rotate` so it layers on the pop). The website uses the same resolved shimmer, glow and rock values via `holoVars()` across tiles, dialogs, binder and ceremonies. Holo: `--holo-gradient` is built from up to 8 colours cycled into the original 8-slot geometry; loop mode uses `rainbowLoop` (slides exactly one gradient tile so it joins seamlessly).
- **Editor (a Photoshop-style workspace)**: there is no category rail: **Properties** follows the selection. With nothing selected it is the **Document** (search, then **Layout** = stage size + per-view placement, global so hidden in pack scope, then the list of registry categories with changed counts; a category opens under a `← Document` breadcrumb and never selects anything on the canvas). Selecting a layer (canvas click, Layers row) shows just that layer's settings: its header names the layer (`LAYER_NAMES`), `← Document` (or Esc on the canvas) clears the selection, and the category/section it maps to (`TARGET_SECTIONS`) is expanded and scrolled to with the category's other sections collapsed; the card opens its Variants category. In a global or scene layout (not a pack override) a **Layer** block (`LayerBlock.tsx`) sits above the settings: X, Y and Size % number fields (Up/Down step 1, Shift step 10), an **Opacity** slider plus number, and **Reset**; every edit goes through `editLayer()` (the drag/resize clamps) as one labelled History step (Move / Resize / Fade <part>). `Placement.elements[id].opacity` (0 to 1, `ElementPlacement`) is clamped by `sanitizeLayout()` and omitted at 1, so old layouts are unchanged; the widget applies it as `filter: opacity()` via `--el-<id>-f` (set only when below 1) on the part node itself (the show-off label sets it inline in `styleShowLabel`), because filter composes with the opacity the reveals and fade-ins animate on those nodes instead of replacing it. Search ("Find a setting") spans every setting in both modes. **Multi-select and lock**: Shift+click (canvas or a Layers row) adds a part to the selection or takes it out; `selection` (editor context) holds them, `selected` is the last one and drives the single-part Properties. Only one view's parts can be selected together (Shift+click in the other view starts a new selection). Drag, arrow keys and the corner handles act on every unlocked selected part as one History step ("Move 3 layers"); Properties shows "N layers selected" with Lock and Reset position instead of look settings. A press on a part inside a multi-selection drags them all and only collapses to that part on a click without a drag. Shift+drag still moves the whole view when nothing was selected before the press; with a selection, Shift+click toggles instead. The widget gets `{ type: 'selected', selection, locked }` and outlines each (`.edit-sel`). **Lock** (lock button per Layers row, Lock / Unlock in the right-click layer menu) stops canvas drags, nudges and resizes of that part (a click still selects it); locks are an editor aid in localStorage `tcg:overlay-locks:<layoutKey>`, never saved to the overlay. **Align and distribute** (Layer menu and the Move tool's options bar, global or scene layouts only; locked parts are skipped): the editor posts `{ type: 'measure', ids, seq }`, the widget (`EDITOR` only) replies `{ type: 'boxes', boxes: { id: { x, y, w, h } } }` in design px, and `alignOffsets()` / `distributeOffsets()` in `lib/overlay-layout.ts` (same maths as the card back editor) give each part's box move, divided by the view's scale like a drag and added to its offset. One part aligns to the stage; two or more align to the selection's bounding box (left, centre, right, top, middle, bottom); distribute spaces the centres evenly between the outermost two and needs 3 unlocked parts. Each action is one History step ("Align left", "Distribute horizontally"). **Shortcuts** (never while typing in a field; `?` or Help > Keyboard shortcuts lists them): V / H / Z tools, Space, Ctrl+S save, Ctrl+D deselect, Tab canvas-only (only when the canvas has focus, so keyboard users can still tab through the panels; View > Canvas only does it too), H on a focused Layers row toggles that layer's eye. **Unsaved draft recovery**: while anything is unsaved the whole editor state (global, packs, scenes, layouts) is written to one localStorage entry `overlay-editor-draft` (1s debounce, with the newest saved version id it was made against); it is removed as soon as the editor is clean again (Save, Revert, Discard). On open a banner offers **Restore / Discard** ("Restore unsaved changes from 14:02?"); a draft that already equals the saved state is dropped silently, and one made against an older saved version says so and opens Review after restoring. Writes pause while an offer is unanswered; every storage access is in try / catch (it may be blocked). One **Save** posts only what changed (`saveOverlayEditorAction`, payload `{ layout?, global?, packs? }`) plus `expectedVersion`, the id of the newest `overlay:versions` entry the editor loaded. If a newer version exists (someone else saved meanwhile; scenes ride the same check) nothing is written, the action returns `{ conflict }` and a banner offers **Review their changes** (their version against the editor's current state), **Overwrite** (resends with `force=on`) and **Load theirs** (loads that version and adopts its id); the check is `versionConflict()` in `lib/overlay-versions.ts`. A **menu bar** (`EditorTopBar.tsx` feeding the generic `MenuBar` in `app/admin/components/workspace/`, which has no overlay imports so the card back editor can reuse it; Escape closes, Left / Right move between menus, Up / Down between items, a press outside closes; each item shows its shortcut where one exists): **File** (Save, Revert, Looks = presets and season looks, Versions, Import / Export, Save options), **Edit** (Undo Ctrl+Z, Redo Ctrl+Shift+Z, Pack tools in pack scope), **View** (Before / after, Guides / zoom / background), **Scene** (the Scenes list and New scene), **Help** (show the first-use hint again). Looks, Versions, Import / Export, Save options, Pack tools, Guides and Scenes are flyouts (`SubMenu`) holding the same panels the popovers had. **Layer** (Align, Distribute, Lock / Unlock, Reset position for the selection) sits between Edit and View; there is no Window menu yet. At the right end sit the notice, **Review** (kept a popover) and Revert / Save; a second row holds Refresh overlay, the scope hint and the conflict / draft banners. **Scope tabs** (`EditorScopeTabs.tsx`, generic `DocTabs` in the same workspace folder) sit above the canvas, replacing the old scope select: Everything (never closable), plus a tab for each open scene and pack override; a dot marks a scope with unsaved changes, × closes a tab (closing the active one returns to Everything) and the "+" select at the end opens any scope not yet open. Any route that changes the scope (a tab, the Scenes panel's Edit, the URL) opens its tab, and the open set is kept in localStorage `tcg:overlay-tabs` (an editor aid only; tabs whose pack or scene no longer exists are dropped). Switching calls the same `setScope` the select did. A **status bar** (`EditorStatusBar.tsx`, generic `StatusBar` in the same folder) under the workspace shows the canvas scale, the stage size, the load rating, the unsaved count (a button that opens Review; "Saved" when clean), the last saved time (newest version) and a "Save conflict" flag while the save conflict banner is up. A **tool strip** left of the canvas (generic `ToolStrip` in `app/admin/components/workspace/`): **Move (V)** is select / drag, **Hand (H)** drags to pan, **Zoom (Z)** clicks in and Alt+click out; holding **Space** is a temporary Hand. Hand and Zoom put a clear sheet over the preview so presses never reach the widget. A **canvas** that fits the whole stage into the available space (Fit is the default; zoom is a multiple of Fit, shown as the real % in the status bar and clamped to 10% to 800%; past fit it pans inside the canvas box only: Hand / Space-drag, wheel, Shift+wheel; **Ctrl+wheel** zooms at the pointer, **Ctrl+0** fits, **Ctrl+1** is 100%, **Ctrl+= / Ctrl+-** step; the preview frame forwards wheel and these keys to the editor only when loaded as `?preview&editor` (the pack workspace preview, plain `?preview`, forwards just the arrows and Escape);  View: Pack opening / Collection, "Show as" version, Play) with an **options bar** under the menu bar that shows Fit / 100% / the zoom % for Hand and Zoom and Refresh overlay plus the scope hint for Move, and a **right column of collapsible panels** (`PropertiesDock.tsx` feeding the generic `PanelStack` in `app/admin/components/workspace/`, which has no overlay imports: a panel is one `{ id, title, icon, content, weight, hidden }` entry, open panels share the height by `weight` and scroll inside themselves, a chevron title bar collapses one to its title, and the collapsed ids are kept in localStorage `tcg:overlay-panels`; Properties on top, Layers below, hidden in pack scope) whose top panel is the **properties** dock (category rail, search across every setting; **Variants** opens a picker (one card per variant, "Previewing" marked) and then edits that variant under a `← Variants / Full Art Holo` breadcrumb with "copy the look of…", collapsible sections with changed counts, per-property and per-section reset, `inherit` in pack scope). One `version` state drives both which variant is edited and which the preview shows. **Clicking an element in the preview opens its settings**: the widget (preview only) tags the still's elements with `data-edit` (card, label, serial, bar, got, strip, showlabel, heading, grid), highlights them on hover and `postMessage`s `{ type: 'select', target }`; the editor maps that to a category + section and scrolls it into view ; the same press also **drags**: past 3 px the widget sends `{ type: 'drag', target, dx, dy, alt }` (design px, cumulative from the press, divided by `--stage-scale`) and `{ type: 'dragend' }` on release. The editor maps the target to a view (`heading` / `grid` belong to the collection view, everything else the pack opening), moves that part's own placement in `Placement.elements` (Shift+drag, sent as `shift: true`, moves the whole view instead; part moves are divided by the view's scale) with the snapping below, and treats the whole drag as one undo step (`drag` ref suppresses the 500ms timer; `dragend` commits). Dragging is a no-op in a pack override (layout is global). The selected target is kept in `selected` state and echoed to the widget as `{ type: 'selected', target }` (solid outline plus a name tag via `body[data-selected]`); arrow keys nudge it (1 px, Shift 10 px) and Esc clears it, whether focus is on the canvas box or inside the iframe (the widget forwards those keys as `{ type: 'key', key, shift }`); arrows move the selected part, not the whole view. The Layout panel has Reset <part> (for the selected, moved part) and Reset all elements for the current view; Review lists moved parts and the Layout count includes them. The **Layers** list (`LayersPanel.tsx`, its own panel under Properties, hidden in pack scope) lists the parts in two groups, Pack opening and Collection. A group name opens the Layout category for that view; a row calls the same `selectTarget()` as a preview click, and the selected row follows canvas selection. Hovering a row posts `{ type: 'hover', target }` (cleared with an empty target) and the widget shows the same dashed outline via `body[data-hover]`. An eye toggle (`aria-pressed`) appears only where a show/hide setting already exists: label `reveal.showLabel`, serial `reveal.showSerial`, bar `reveal.showInfoBar`, got `reveal.showGotLine`, strip `reveal.showMiniList`, showlabel `show.showLabel`, heading `collection.showHeading`; card and grid have none. A dot marks a part moved in the current layout, with a per-row reset. No reordering. The Layout category no longer changes canvas behaviour. Messages from the iframe are checked for origin and source. The workspace is `xl:h-[calc(100vh-4rem)]` and `main:has([data-workspace])` is `overflow: hidden` there so the page doesn't scroll; below `xl` it stacks. It **auto-collapses the admin sidebar** while mounted without touching the saved choice: it sets `window.__tcgSidebarForce` and fires a `tcg:sidebar` event that `AdminShell` listens for. the preview gets `postMessage` `props` (unsaved effective values + `packId`), `variant`, `static`, `pack`, `collection`.
- **Glow follows the art's silhouette**: a `.glow-layer` behind the card (inside `.main-card`, whose art is now the `.card-art` child) is a blurred copy of the art, blur on the OUTER element, the `--card-mask` thumbnail mask on the INNER `.glow-fill`s, because CSS applies `filter` before `mask` and masking the blurred layer would cut the halo at the edge. Rounded corners and holes in the artwork therefore stay clear; only opacity/transform animate (no per-frame blur). **3D tilt** animates the card box's standalone `rotate` (`variantTiltx|y|xy`, `perspective` on the wrapper via `.tilt-on`), so it doesn't fight the entrance transform or the 2D rock. `mainCardAnimation()` returns `{ anim, start }`; `--fx-start` delays glow/tilt until after the pop. Card-styling vars, collection `sort`, per-version `holdExtra` / `volume` / sparkle burst (`burstSparkles()`) are as before.
- **Canvas handles and layer menu**: the selected part (or all of a view's parts when a view is selected in the Layout panel) gets four corner handles in the preview; dragging one sends `resize { target, view, factor }` and the editor scales that placement (aspect kept, 0.25..3, one undo step with the drag's `dragend`). While dragging or resizing a small readout shows X, Y and size (design px and % of the stage). Handles, snapping and the menu are off in pack scope. Right-clicking a part in the preview (`context` message), a Layers row or a view heading opens `LayerMenu`: Reset position, Center (whole views only: an element's offset is relative to its normal spot, so it has no meaningful centre) and, when scenes exist, Copy position to other scenes (written into each scene's layout as unsaved changes). A dismissible first-use hint on the canvas is remembered in localStorage (`tcg:overlay-editor-hint`).
- **Rulers and guides** (`RulerBar`, drawn in `PreviewStage` around the canvas box, never in the widget): **Ctrl+R** or View > Rulers (kept in localStorage `tcg:overlay-rulers`; the widget forwards Ctrl+R in the editor frame) shows rulers in design px along the top and left; ticks follow zoom and pan (the stage origin is measured against the scroll box). Dragging from the top ruler makes a horizontal guide, from the left ruler a vertical one; drag a guide to move it, drop it off the stage or back on its ruler to delete it. Guides are thin cyan lines over the canvas whose hit areas take pointer events only on themselves. View > Lock guides stops moving them, View > Clear guides removes all. They are an editor aid kept in localStorage per layout scope (`tcg:overlay-guides:<global|scene:id>`, a pack uses the global ones), never saved to the overlay and not undo steps. The editor sends them to the frame (`{ type: 'guides', x, y }`) and a dragged part snaps to them like the stage edges and other parts.
- **Editor v2 tools**: **Undo / redo** (Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y; a drag or slider burst is one step, 500ms-coalesced snapshots of global + pack + layout state, 60 deep; ignored while typing in text/number fields; each step has a short label set by `tagEdit(label)` where the edit is made, and a coalesced step keeps its first label; saving does not clear the stack), **History panel** (`HistoryPanel`, a collapsed-by-default panel under Layers: the stack oldest first from "Opened", the current step highlighted, steps after it greyed until a new edit drops them; clicking a row calls `jumpTo(i)`, the same restore as undo / redo), **Review** (`lib/overlay-diff.ts`: every setting that differs from what is saved, old → new) and **Before / after** (flips the preview to the saved values). **Saved versions** (`lib/overlay-versions.ts`, KV `overlay:versions`, newest 20): every save snapshots the whole look with an optional note (the first save also records "Before versions were kept"); *Load* puts one into the editor as unsaved changes, Save makes it live. **Live refresh**: `overlay:reload` is a token returned by `POST /api/overlay/heartbeat`; the widget records the first value and reloads when it changes, but only while idle (`checkReload`, nothing animating or queued). The **Refresh overlay** button (`refreshOverlayAction`) bumps it, and Save options (File menu) can do it after every save (`OverlaySettings.autoReload`). **Guides / view**: thirds, 10% grid, safe areas, snapping while dragging (the preview snaps a part's edges and middle to the stage edges / centre and to the other parts within 6 px and draws the guide line; where nothing is near, the editor falls back to its own centre-then-10 px; Alt = free, and the Snap switch turns all of it off), zoom, background (checker / dark / light / green / a local screenshot, never saved), and a preview pack + card picker (`postMessage` `props` carries `packId` and `cardNumber`; widget `previewCardNumber`). **Load rating** (`lib/overlay-perf.ts`, `variantPerf`): a rough per-version cost from the effects switched on (glow size, rays, sparkles, looping shimmer, 3D tilt), shown in the status bar, the variant picker and variant page; a guide, not a measurement. **Pack tools** (pack scope): copy this pack's overrides to other packs, replace them from another pack, list differences from global, clear. **Season looks**: `overlay:seasonlooks` maps a season to a preset; `GET /api/overlay/config` layers the ACTIVE season's preset over the global props (pack overrides still win), set from File → Looks → Season looks. `scripts/check-overlay.mts` (mock KV) covers versions, the token, season looks, diff and perf. Overlay actions re-check admin (`requireAdmin`).
- Testing tip: to inspect an animation at an exact moment, start a draw, then `document.getAnimations().forEach(a => { a.pause(); a.currentTime = ms })` and screenshot (set `PACKS[0].pack.cardTime = 120` first so the card stays up). Screenshots lag by a second or two, so don't time them against the live animation.

## Only-when-live switches
Settings → OBS Overlay has two checkboxes (KV `overlay:settings`, `lib/overlay-settings.ts`): ignore incoming **pack** triggers and/or **collection** triggers unless the stream is live. `liveGate(kind)` is called by `/api/webhooks/pull` and `/api/webhooks/collection` before enqueueing; blocked triggers are dropped (not queued) and answered `{ ok: true, ignored: true, reason }`. "Not live" = no overlay connected, or a connected overlay reports `streaming === false`. If OBS hasn't granted the browser source status permission, `streaming` is `null` and triggers are allowed (we can't tell). Dashboard quick actions deliberately bypass the gate. It fails open on any error.

## Overlay performance
The OBS overlay must stay smooth, so keep these rules when editing `public/widget.js` / `widget.css`:
- **The collection grid uses thumbnails, never the animated WebPs.** `/api/seasons/active` adds `thumbUrl` to every card (`cardThumbUrl()`); the widget maps it to `card.thumb` and `buildMiniList` uses it. `preloadThumbs()` decodes them all on load, and `drawCard` calls `warmImage(card.image)` as soon as a card is picked so the reveal doesn't hitch on decode.
- **Animate only `transform`/`opacity`.** The holographic shimmer slides a pre-painted `::before` layer with `translate3d` instead of animating `background-position` (which repaints every frame). No `filter: blur` on animated layers.
- **Keep images small.** `public/assets/pack-cover.png` is drawn ~287px wide but used 3× per pack theater, so it is stored at 640px wide (~0.4MB). Don't replace it with a full-resolution original.
- `/assets/cards/*` and `/assets/sounds/*` are served with a day of `Cache-Control` (see `next.config.ts`) so OBS refreshes don't re-download the art.
- **Serial number on the reveal (ROADMAP 2.4)**: `POST /api/collection` also returns `uid` (the serial number of the copy just made) and `showSerial()` in `widget.js` reads it. Property `reveal.serialFormat` (Pack opening -> Number shown on the card): stored values stay `edition` (`#7`, the edition number, the default), `uid` (`#1023381`, the serial number) or `both` (the `#7` pill with a small `Serial #1023381` line under it, `.serial-print`). Without a `uid` (older server, untracked ledger) it shows the edition number. The menu calls the pill "Edition number on the card". The test panel's dry runs and the editor preview use a sample number. The chat show-off sends the lowest print's `uid` too (`prepareShowOff` -> queued `card` event -> `drawCard({ show })`).

## Special moments (Overlay Editor -> Special moments)
Three banners for pulls worth a cheer, in priority order, **one per pull, the highest wins** (`pickMoment` in `lib/overlay-moments.ts`, mirrored in `widget.js`; `scripts/check-overlay.mts` runs both over every combination):
1. **First-ever print** (edition #1 of that card in that version): on by default. Keeps its original keys `reveal.firstEver`, `reveal.firstEverText`, `reveal.firstEverHold` (only the group changed, no migration) plus `moment.firstEver.*`.
2. **A viewer's first pull** (`moment.firstPull.*`): they owned nothing in this collection before this pull. Off by default, text `Welcome, {username}!`.
3. **A new card for them** (`moment.newCard.*`): they did not have this card before. Off by default. (The small "new" label is still `variant.regular.labelText`.)
Each has the same controls (`momentProps` in `lib/overlay-props.ts`): text, a small line, banner colours (1 to 4, a gradient when more than one), text colour, size and font, position on the card (top / middle / bottom), sparkles and their colour, an optional sound (an asset address) and its volume, extra hold, and a reveal style override (`inherit` by default). The font select uses the card-back faces (`BACK_FONTS`). Site display is the default and leaves the banner's face alone; any other face loads that card-back file. `momentSpec` reads them and `momentBanner` draws the one banner (`.first-banner`, the stylesheet is the first-ever look and only differences are written inline, so the defaults are today's banner exactly). `{username}` and `{cardName}` work in the text lines.
- **Data**: `POST /api/collection` replies with `isNew` and `firstForViewer` (both from the collection as it was before the pull) besides `serial`. The moment is chosen when that reply arrives (label time), or from the overlay's own copy for dry runs.
- **Style override**: first pull and new card are known before the reveal, so their style applies at once. First-ever is only known after the save, so while `moment.firstEver.style` is not `inherit` that one real pull is saved first and played when the server answers (the `_pre` path in `drawCard`); at `inherit` nothing changes.
- **Preview**: the editor's **Moment: None / First-ever / First pull / New card** (next to "Show as") makes Play force that moment even when its switch is off; the `?dev` test panel has the same **Special moment** picker (and **First-ever pull [1]**).

## Show off look (Overlay Editor -> Show off)
Group `showoff`, all `show.*` keys; every default is the look the show-off always had. Sections: **Entrance and timing** (`show.style`, limited to the pack-less styles, and `show.hold`), **Label** (`show.showLabel`, `show.text` with `{user}` / `{username}` / `{cardName}` / `{variant}`, `show.ownLabelLook` + colours, size, `show.labelFont`, and an X / Y nudge as the position), **Edition number** (`show.showPrint`, `show.printFormat`: inherit / edition / uid / both), **Card and effects** (`show.cardScale` multiplies `reveal.cardScale`, `show.glow` / `show.sparkles`: inherit or off) and **Sound** (`show.sound` on / off / custom with `show.soundUrl`, `show.volume`).
- **How it is applied**: `showOffProps(P, variant)` in `widget.js` folds the show-off keys into a copy of the effective properties (card scale, the version's glow / sparkles, `reveal.showSerial`, `reveal.serialFormat`), so the shared drawing code has no show-off branches; `styleShowLabel` handles the label. The label keeps following the "got:" pill colours until `show.ownLabelLook` is on.
- **Preview**: the editor's View menu has **Show off** (a settled still with a sample viewer and print; **Play show off** runs one). Placement is the pack opening's (the Layout panel is unchanged).
