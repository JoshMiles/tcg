# OBS overlay

> Read this when you touch `public/widget.js`, `widget.css`, the Overlay Editor, scenes, overlay properties, the show-off command, quick actions or the only-when-live switches.

## OBS widget data flow
1. Widget calls `GET /api/seasons/active` on load → returns `{ season, packs: [{ pack, cards }] }`
2. A real pull is **rolled by the server** when it is queued (`lib/draw.ts`, `issueDraw`: pack by weight, card by probability, version by the pack's weights); the queue event carries `draw: { packId, cardNumber, variant }` and the event `id` is the pull's one-use **ticket** (KV `draw:<id>`, 12 h). The overlay plays exactly that draw (the pinned-draw path of `pickPackAndCard`); only the test panel and the editor preview roll in the browser.
3. Widget calls `POST /api/collection` with `{ pull: { username, ticket, ... }, revealInMs }` (`revealInMs` = milliseconds from this save until the card is shown, `at(R.reveal)`; the first-ever pre-save path works it out from the moment's style the same way; the server clamps it to 0..15000 and assumes 3000 when an old cached overlay sends none, and uses it only to time Mix It Up commands on big pulls, docs/admin/mixitup.md). The server claims the ticket (viewer must match, once only) and saves **what the ticket says**, not what the request says: a request without a valid ticket gets 401 and saves nothing. If a Mix It Up payment is attached (`paid`) it is charged first (docs/admin.md); the reply may be `{ ok: true, revoked: true, owned }` when the payment failed, and the widget just resyncs `owned`. Replacing a collection (`data`) and `DELETE` need a staff session, so the test panel's Reset buttons and "Don't save" off only work from a browser signed in to the admin, never in OBS. Pulls queued before tickets existed have no `draw` and are not saved.
4. Widget reads `GET /api/collection?name={collectionName}` to show mini-list with ×N badge for duplicates. That read requires the overlay key or a staff session (the same check as the queue), so it is not a public dump of every viewer's pulls.

The widget reads per-pack visual settings (accentColor, tearBorderColor, holoMinStars, cardTime, cooldownTime, soundVolume, coverImageUrl) directly from the pack object. Card sounds come from `card.soundUrl` (e.g. `/assets/sounds/1.mp3`).

## The overlay key
The overlay has no login, so the endpoints it uses to take queued pulls (`GET /api/webhooks/queue`), report shown collections (`POST /api/webhooks/notify`), read the on-stream collection (`GET /api/collection`) and check in (`POST /api/overlay/heartbeat`) require the **overlay key** (`lib/overlay-key.ts`, KV `overlay:key`). The OBS address is `/overlay.html?key=<key>`; `widget.js` reads `key` from its own URL and sends `x-overlay-key` on every request. `isOverlayRequest` also accepts a staff session (editor preview, `?dev` tabs while signed in); there is no other shortcut, so an overlay inside a sandbox presents that sandbox's own key too (the key lives in the sandbox namespace, made on first use; the Sandbox page's overlay link and the Fake Twitch overlay carry it). Settings → OBS Overlay shows the address (the key as dots until **Reveal**; **Copy** always copies the real address; the Sandbox page's overlay link and the Overlay Editor's Scenes menu hide the key the same way, via `CopyableUrl` / `maskUrlKey` in `lib/mask-url-key.ts`) and can make a new key (the old OBS addresses then stop working); the Overlay Editor, the sidebar Copy URL button and the palette copy the address with the key. A refused overlay shows "Overlay key missing or changed" on screen. ROADMAP 13.2. `getOverlayKey` keeps the key in memory for 30 s per server instance and sandbox (ROADMAP 48.5), so the queue poll and the heartbeat do not read it from KV every time; making a new key clears this instance at once, but **another instance keeps accepting the old key (and refusing the new one) for up to 30 s**, and a restored backup or a sandbox reset shows up after the same wait.

## Queue poll pace
`widget.js` polls `GET /api/webhooks/queue` every 2 s. After a whole minute in which no poll returned an event it polls every 5 s instead (`nextPollDelay`), and goes back to 2 s as soon as one returns an event (a queued pull, a show-off or a collection), so the first pull after a quiet spell can show up to 3 s later. Each poll schedules the next with `setTimeout`. A poll costs one KV command (the `rpop`; the key comes from memory). `scripts/check-polling.mts` runs the widget's own copy of `nextPollDelay`.

## Overlay status & quick actions
- **Connection indicator**: each overlay page load picks a random id and sends a heartbeat every 10s (`lib/overlay.ts`, KV hash `overlay:clients`); a client counts as connected for 25s after its last heartbeat. `OverlayStatusProvider` (in the admin layout) polls `/api/admin/overlay-status` once every 5s (the timer stops while the tab is hidden and starts again, with an immediate poll, when it is shown) and `OverlayStatus` (sidebar + dashboard header) and `QuickActions` read it. Open the overlay in a normal browser tab and it shows as "browser tab".
- **Live detection**: if OBS grants the browser source *Page permissions → "Read access to OBS status information"*, the widget calls `window.obsstudio.getStatus()` and reports `streaming`/`recording` (and re-reports on the `obsStreamingStarted/Stopped` events). Without that permission those stay `null` and the UI says only "connected". It cannot know the stream is live any other way.
- **OBS check and refresh via TCG Bridge** (ROADMAP 55.6b): with TCG Bridge's OBS switch on (see docs/admin/mixitup.md), Admin > Settings > OBS Overlay > Connection also shows what the bridge sees in OBS: the overlay browser source (matched by its `/overlay.html` address on this site) is visible in the current scene, not in it, hidden, or missing, and the **Refresh overlay in OBS** button (shown when a bridge is paired) presses "Refresh cache of current page" on it, which a deploy needs. This is independent of the widget's own heartbeat above: it needs no browser-source permission, and the stream state it reports also feeds the live hint.
- **Quick actions** (dashboard): `quickAction` in `actions.ts` dispatches on the submit button's `intent` (gift packs, show collection, grant card); `clearQueueAction` empties the overlay queue. Gift/show enqueue the same events the webhooks do (`enqueueEvent`) and are refused with a "queue anyway" option when no overlay is connected, so packs can't pile up unseen. They return an `ActionResult` shown inline via `useActionState`. Keep form fields controlled, React resets uncontrolled fields after a form action. `/admin?gift=<username>` prefills the viewer (the users list 🎁 link uses it).
- **Users list**: rows are one stretched link to `/admin/users/[username]` (profile editing lives there), sortable via `?sort=cards|pulls|active|name`; "last active" comes from the latest 500 activity events.

## Overlay layout (Overlay Editor → Layout)
The overlay is drawn on a fixed **design stage** (default 1280×720, `lib/overlay-layout.ts`) and scaled to fit the real OBS browser source, so a differently sized source never cuts the animation off (the pack opening spans about -425px..+208px around its centre, which `.pack-fit` re-centres). The browser-source size is shared, but **the pack opening and the collection view are placed independently**: `OverlayLayout = { width, height, pack: Placement, collection: Placement }` (`Placement` = `scale`, `offsetX`, `offsetY`, design px) in KV `overlay:settings.layout`; `sanitizeLayout()` upgrades the old single-placement shape (both views inherit it, so nothing moves). `GET /api/overlay/config` serves it and `widget.js` `applyLayout()` writes `--stage-scale` (the fit, on `.container`) plus `--pack-*` / `--col-*`; each theater wrapper gets `.is-pack` or `.is-collection`, which place themselves with the standalone `translate` / `scale` properties (so they stack with the animations' own `transform`s). The editor (the **Layout** category of `OverlayEditor`) has a Pack opening / Collection switch (each with size, X/Y, Center, Reset), numeric X/Y/size (dragging and nudging happen on the canvas, see Editor below), browser-source size presets, and shows the real overlay in an iframe (`/overlay.html?preview`), pushing changes by `postMessage` (`layout`, `static`, `pack`, `collection`). While nothing animates the preview shows a **still** of the settled pack opening or of the collection view (`showStatic()` in `widget.js`, wrapper class `.static-preview`) so it can be sized and moved; **Play** runs the real animation and the still comes back when the queue goes idle. The editor re-sends the layout on every iframe `load` (an iframe starts as a blank page that already reads "complete", so a one-off ready flag races); **preview mode never touches the queue, heartbeat or collections** (no polling, no saving, no sound, fake `preview` user), keep it that way. `sanitizeLayout()` clamps everything, server-side too. The collection grid still wraps at 800px (`.card-wrapper { max-width: 800px }`). **Element layers**: each view's `Placement` can also carry `elements`, single parts moved on their own (`ELEMENT_IDS` in `lib/overlay-layout.ts`: pack `card, label, serial, bar, got, strip, showlabel, banner`; collection `heading, grid`; they match the preview's `data-edit` tags). An entry is `{ scale, offsetX, offsetY }` relative to the part's normal CSS spot, so an empty or absent `elements` is today's look and old layouts need no migration. `sanitizeLayout()` drops unknown ids and ids of the other view, clamps offsets to the stage and scale to 0.25..3, and omits default entries. Positions are global or per scene only (never per pack); scenes carry them inside their layout. `applyLayout()` writes `--el-<id>-x/-y/-s` on the root and `widget.css` applies them with standalone `translate` / `scale` on `.main-card`, `.card-label`, `.serial-badge`, `.card-info-overlay`, and `.user-text` / `.card-mini-list` (per `.is-pack` / `.is-collection`), so they stack with every reveal's keyframes (which animate `transform` / `rotate` only; keep it that way). Parts inside `.card-box` (card, label, serial, bar) move relative to the card; their offsets are divided by `--card-scale` so one design pixel of offset is one design pixel on stage, and a drag follows the pointer at any card size. The show-off reuses the pack opening's positions: its label is the same `.user-text`, so `styleShowLabel()` adds `--el-showlabel-*` to the label's own X / Y nudge instead of the `got` position. The moment banner is the `banner` part (pack view, `data-edit` set on it in the preview): `.first-banner` takes `--el-banner-x/-y/-s/-f` through the standalone `translate` / `scale` / `filter` properties (offsets divided by `--card-scale`, it sits inside the card box), so its own `transform` entrance and `firstShine` animation are untouched. It exists only while a moment plays (the editor's Moment picker plays one); the show-off plays no banner. Its settings are the Special moments category. **Layers rows** show an icon per kind (image, text, group; `LAYER_KINDS` in `LayersPanel.tsx`) beside the part's name, and double-clicking a row re-opens its settings.

## Overlay scenes (one overlay URL per OBS scene)
A **scene** is a preset (`OverlayPreset` in `lib/overlay-settings.ts`) that may also carry its own **layout** (stage size + pack / collection placement). Every preset has its own overlay URL, `/overlay.html?preset=<id>`: `widget.js` `loadLayout()` passes it to `GET /api/overlay/config?preset=<id>`, which returns the scene's layout (when it has one, else the global layout) and layers the scene's values over the global look and the season's look (pack overrides still win). An unknown id is just the global overlay. Use a different URL in each OBS scene, e.g. a vertical one. Caveats: the queue is shared, so whichever open overlay polls first plays a pull (OBS only keeps the visible scene's source running by default); a scene's values are overrides, so it follows later global changes except for what it sets itself.
- **Editing**: the Overlay Editor's **Editing** menu has a "Scenes" group (`scope = "scene:<id>"`), and the **Scene → Scenes** panel lists every preset with its URL (Copy / Open / Edit) and creates a new scene (Landscape = a copy of the global layout, Vertical = a 1080 × 1920 stage via `sceneLayout()`). A scene's values live beside the pack overrides in the editor state (`packVals["scene:<id>"]`, stored with `keepDefaults`, so one equal to the default still beats a global value) and its layout beside the global one (`layoutMap`); one Save posts `{ layout?, global?, packs, scenes: { id: { props, layout } } }` and `saveOverlayEditorAction` calls `updateScene`. The Layout panel offers vertical size presets (`VERTICAL_LAYOUT_PRESETS`), a Rotate button and, for a vertical stage, a hint with a one-click "4 cards per row" (`collection.perRow`), since the collection grid wraps to the stage width. Scenes are not part of saved versions (those cover the global look only). `scripts/check-overlay.mts` covers it.

## Show off a card (chat command)
A viewer types a chat command (e.g. `!show shiny gouda goat`); the streamer's bot calls `POST /api/webhooks/show-card` with `{ secret, username, card }` and the overlay shows that card. The command name is the bot's, not ours.
- **Parsing is pure** (`lib/showoff.ts`: `parseShowQuery`, `resolveCard`, `pickShowVariant`; `scripts/check-showoff.mts`): an optional version word (shiny / full art / reverse holo / regular…), then a card name or number; empty = their pinned print, else the first showcase pick they still hold, else their most valuable card. Owned cards win over unowned name matches; no version asked = the best owned version.
- **The server decides** (`lib/showoff-prepare.ts`, `prepareShowOff`): the card must be in the active season and owned by the viewer in that version, the serial sent is their lowest copy of it (with its serial-bonus multiplier), and the per-viewer cooldown (`showoff:cd:<user>`, 15 s) is taken LAST so a refused request doesn't spend it. The route answers 200 with `{ ok: false, error, message }` on refusals so bots can say `message` in chat; success returns `{ ok, message, card, variant, serial }` and queues a `card` event (`QueuedEvent`: `cardNumber`, `variant`, `serial`, `serialMult`). It goes through `liveGate('collection')` and logs a `trigger` activity (`kind: 'card'`, shown in the feed / dashboard / Discord).
- **Overlay**: `pollWebhookQueue` → `queueShowCard(user, ev)` → `drawCard(user, { show: ev })`: the card/variant are pinned, nothing is saved or added to the collection, the strip is hidden, and the serial pill comes from the event. Its look is the **Show off** group of the Overlay Editor (all `show.*` keys, below). Test panel: **Show off card [W]** (dry, sample serial). `scripts/check-showoff-server.mts` (mock KV) covers ownership, cooldown, serial, and the bare command: pinned print, else showcase, else best card. A dry run still queues nothing.

## Overlay properties (Overlay Editor)
Every adjustable aspect of the overlay's look is a **property** in one registry, `lib/overlay-props.ts` (`PROPS`, grouped by `PROP_GROUPS`): a dotted key (`collection.perRow`, `reveal.style`, `variant.shiny.holoSpeed`), a type (`number` / `boolean` / `select` / `color` / `colors` / `text`), default, limits, help text, optional `experimental`. **The defaults reproduce the original look exactly**, so an untouched install is unchanged. The editor UI, validation, reset, presets and import/export are all generated from the registry, to add a property: add one entry there, then consume it in `widget.js` (read it with `pv(P, key, fallback)`); add a `dependsOn()` rule in the editor if another switch turns it off.
- **Storage is sparse**: only values that differ from the default are saved (`sanitizePropValues`, which also drops unknown keys / invalid values). Global values: KV `overlay:settings.props`. **Per-pack overrides**: KV `overlay:packprops` (`{ [packId]: values }`, kept off the Pack object because pack forms rewrite the whole pack). These use `{ keepDefaults: true }` because an override equal to the default must survive when the global value isn't the default. Named presets: KV `overlay:presets` (max 30; saving an existing name replaces it). All in `lib/overlay-settings.ts`.
- `GET /api/overlay/config` returns `{ layout, defaults, props, packOverrides, backs, fonts }`; the widget (`loadLayout()`) merges defaults → global → the pack's override in `effectiveProps(packId)`. The **collection view uses global values only** (it isn't pack-specific; the editor hides that group in pack scope). The config is read once at load, so OBS needs a browser-source refresh after saving (the editor says so).
- **Categories** (`PROP_GROUPS`): **Pack opening** (`reveal.*`: animation, card size, label incl. `labelOwned` and `reveal.labelFont`, name/stars bar, "got:" line, start delay, pack size, and the row of cards under the revealed card. Its own `reveal.strip*` settings). **Fonts**: `text.font` (Pack opening, section Text, default site display = today's stylesheet faces) is the overlay font, and a pack override can set its own. Every text layer also has its own select that defaults to `inherit` ("Overlay font") and otherwise offers the same `BACK_FONTS` faces: `reveal.labelFont` (card label), `reveal.serialFont` (edition pill), `reveal.cardNumberFont` (corner numbers), `reveal.nameFont` (name bar), `reveal.gotFont` ("got:" line), `reveal.stripFont` ("?" and ×N in the strip), `show.labelFont`, `moment.*.font` (banners), `collection.headingFont` and `collection.cardFont`. In `widget.js`, `applyTextFont(el, id, P)` resolves `inherit` to `text.font`; site display clears the inline family, any other id loads the card-back file. Not covered: the `#alert` bar and the dev panel (not themed), the card back's own text (set in the Card back editor)., **Variants** (`variant.regular|reverse|full|shiny|golden.*`, each `PropDef` carries `variant`: label, a per-variant **reveal animation override**, holo, glow, pop, 3D tilt, rocking, **light burst** (on/off, strength, size, ray count, spin time, colour, hue cycle), sparkles, time and sound; pack workspace links directly via `/admin/overlay?pack=<id>&group=variants`) and **Collection** (`collection.*`, the "show collection" view, global only). The strip and the collection view deliberately do NOT share keys. Group membership is metadata only, stored values are keyed by the dotted key, so regrouping never migrates data (note: `collection.*` card-look values saved before the strip got its own keys no longer affect the strip).
- **Reveal styles** (`REVEALS` in `widget.js`): classic (the original), simple (zoom), slide, flip (card back = the pack cover, `.card-back`, edge-on at 55% of the keyframes), and the experimental **rip-shake** (pack trembles, tear strip flies off, card bursts out) and **rip-peel** (tear strip peels back from one end). Each style names its keyframes plus when (seconds at 1×) the card is revealed / info / label appear; `reveal.speed` divides every duration *and* timeout. Hold time = `label time + 0.8s + pack.cardTime` (classic = the old `cardTime + 4s`). More styles: **rip-slice** (tear strip slides straight off sideways), **rip-explode** (pack swells, flashes white, bursts), and the pack-less **drop**, **spin**, **impact** and **deal**. `variant.X.style` (default `inherit`) overrides the pack opening's style per variant (e.g. Full Art Holo always rips); `reveal.startDelay` adds seconds to every animation delay and timeout (`D` in `drawCard`); `reveal.packScale` uses the standalone `scale` on `.package-container`. The light burst is per variant: `burstSpec()` / `buildRays()` rebuild the rays (`--ray-step`) and size the container (`reveal.showBurst` / `reveal.burstOpacity` no longer exist; unknown keys are dropped on read, so old values vanish harmlessly).
- **Per-version looks are CSS variables** written on each theater wrapper by `applyLook()` (`--label-bg`, `--holo-*`, `--glow-*`, `--pop-*`, `--rock-amt`, `--burst-a/b`), and `mainCardAnimation()` composes the card's `animation` list from the generic keyframes (`variantPop`, `variantGlow`, `variantRock`, rock uses the standalone `rotate` so it layers on the pop). The website uses the same resolved shimmer, glow and rock values via `holoVars()` across tiles, dialogs, binder and ceremonies. Holo: `--holo-gradient` is built from up to 8 colours cycled into the original 8-slot geometry; loop mode uses `rainbowLoop` (slides exactly one gradient tile so it joins seamlessly).
- **Highlight tokens** (ROADMAP 38.10 a): `accent: { on?, color?, bold? }` in a wording layer's `TextPatch` (the label, "got:" line, show-off label, collection heading, moment banner and its small line). `color` is a hex or `accent`, the pack's accent colour (`cfg.accentColor`); the default is `accent`. It is edited in the Character panel's "Highlight tokens" group, shown only in the overlay editor and only for those layers, and merges field by field like `fx`. It never becomes CSS on the layer. The widget's `setWording(el, str, ctx, accent, accentColor)` fills the layer: with it off (no `accent`, or `on: false`) it is `textContent = fillTokens(...)` exactly as before; with it on it appends text nodes and `<span class="tok">` for each filled token (`fillRuns`, the TS twin in `lib/overlay-tokens.ts`), `textContent` only, never `innerHTML`. A token with no data stays plain text. `applyTextStyle` on the parent is unchanged and the span's own colour wins over it, so gradient text on the parent shows the accent colour in the token. A strong accent on a light plate (the default yellow "got:" pill) can read poorly: pick a hex there.
- **Light markup in wording** (ROADMAP 38.10 b, `lib/text-markup.ts`): any wording field (the ones with token chips) accepts `**bold**`, `*italic*` and `{color:#rrggbb}word{/color}`. `parseMarkup` turns the string into runs `{t, bold?, italic?, color?}`; `markupRuns` then fills the tokens inside each run (so a token value is never read as markup) and marks filled tokens `tok`. The widget has a port between the `MARKUP` markers (`scripts/check-overlay.mts` runs both on the same cases) and `setWording` renders a styled run as a `<span>` with `textContent` only, never `innerHTML`; wording with no markup (and no highlighted token) is the plain `textContent`, exactly as before. Unbalanced or unknown markup and non-hex colours stay as typed; a `*` opens only before a non-space and closes only after one, so a lone `*` or "2 * 3 * 4" stays literal. Triple stars (`***x***`) are not supported, nest `**` and `*` explicitly. A markup colour wins over the Highlight tokens colour; the highlight's bold still adds. The editor field has B / I / Colour buttons that wrap the selection (the colour applies when the picker closes), and its live result line shows the plain text. The field's character count and `maxLength` count the raw string. The card back free text boxes take the same markup (see docs/serials.md, "Markup in back text").
- **Wording tokens and text fields** (ROADMAP 38.9, `lib/overlay-tokens.ts`): every wording prop (variant label text, `reveal.labelOwned`, `reveal.gotText`, banner text and small line, `show.text`, `collection.headingText`) is filled by ONE `fillTokens(str, ctx)` in `public/widget.js` (between the TOKENS markers; the TS twin in `lib/overlay-tokens.ts` drives the editor's live result, and `check-overlay.mts` runs both on the same cases). `{user}` and `{username}` are aliases everywhere; the set is `{user}`, `{cardName}`, `{variant}` (the version label), `{pack}`, `{edition}` (the serial, banners only, since it arrives from the server after the label and the "got:" line are set) and `{stars}`. A token with no data in that place and an unknown token both stay as typed; the output is always `textContent`. Each wording `PropDef` lists its tokens in `tokens` (the heading has only `{user}`), the preview element it shows in in `fit`, and the size prop that scales it in `sizeKey`. In the editor the field (`TextControl` in `editor-controls.tsx`) has insert chips that insert at the caret (respecting `maxLength`), a "Shows:" line filled with a sample viewer and card, a count against `maxLength`, and a warning "Too long for this size at 1280×720" with "Shrink to fit" (lowers the `sizeKey` prop by the reported factor, down to its minimum; with no size prop it says to shorten the wording). The warning comes from the preview only: `widget.js` (inside `if (PREVIEW)`) measures each `data-edit` wording layer every 600 ms and posts `{ type: 'fit', over, stage }` when a layer is wider than the stage or clipped by its own box (`scrollWidth > clientWidth`); live OBS has no such code. Not done: highlighting tokens inside the field (would need a contenteditable); the banner's small line has no fit warning of its own (the banner is one element).
- **Custom layers** (ROADMAP 38.7 a and b, `lib/overlay-custom.ts`; the shape, gradient and image-URL types and sanitisers live in `lib/shapes.ts`, shared with the card back and re-exported here, and the shape fields UI is `workspace/ShapeFields`): the admin can add text, image and shape layers per view. They are stored as `custom?: CustomLayer[]` on the view's `Placement` (so scenes and versions carry them), at most 16 per view, and an absent `custom` is today's look (`sanitizeLayout` leaves the key out when empty). Every layer has `id`, `kind`, `name`, a box `x / y / w / h` in design px (top left of the stage), `rotate`, `opacity` and `visible`. Text: `text` (tokens and markup as any wording field), a `style` `TextPatch`, `size`, `color`, `font`, `valign` (top / middle / bottom: the box is a flex column and the words sit in their own child, so coloured runs stay inline). Image: `url`, `fit` (contain / cover / fill), `radius` (corner radius in px, default 0) and `fx` (only shadows, glow and stroke are kept; default empty); the url must be a Blob file or a same-site path (`isSafeImageUrl`, re-checked in the widget), an empty url is "nothing chosen yet" and draws nothing, any other bad url drops the layer on save. Shape: `shape` (rect / ellipse / line / polygon / star with `radius`, `radii` (four corners, empty = linked to `radius`), `cap` and `arrows` for a line (default round, none), `sides`, `inner`), `fill` (none / solid / gradient, linear or radial, of 2 to 4 stops), `stroke` (`color`, `width`, `dash`, `pos` inside / center / outside, default inside, which is the original look) and `fx` (only shadows and glow are kept). The widget draws the fill on the box edge and the stroke as a second outline moved in, on the edge or out by `pos`; arrowheads are drawn polygons in the line's colour. `sanitizeLayout` drops unknown kinds, bad or duplicate ids and everything past 16; `diffLayout` lists added, removed and changed layers. The widget (`renderCustom` before `applyLayout`) draws a view's layers in `.custom-layers` boxes over the whole stage (in front by default, see bands below), for as long as that view's theater is on screen; it uses `setWording`, `applyTextFont` and `applyTextStyle` for text, an `<img>` for images and an inline SVG built with `createElementNS` for shapes, with no `innerHTML` from saved data, and a view with no layers adds nothing to the page. In the editor, Layers lists them under each view with **Add layer** (text / image / shape), hide and delete, and selecting one shows `CustomLayerPanel` (name, box, rotate, opacity and one field per kind). **Text tool** (T on the tool strip, `Tool = 'text'`): the preview puts the clear sheet over the frame; a click adds a text layer at that point with the default 400 x 80 box (kept on the stage), a drag draws the box (`toolBox`, at least 20 px each way) with a dashed rubber band, then the tool returns to Move, the layer is selected and its wording field focused. Esc or V leave the tool; it does nothing in a pack override. **Shape tool** (U, `Tool = 'shape'`) works the same way (one shared press / drag path in `PreviewStage`) and makes a shape layer with the default 240 x 160 box; Shift while dragging keeps the box square. **Image tool** (I, `Tool = 'image'`) works the same way (click for the default 200 x 200 box, drag to draw one; the press path is shared with Text and Shape) and makes an image layer with no file yet; the panel's `ImageUploadField` uploads to Vercel Blob (or takes a Blob / same-site url, checked with `isSafeImageUrl`), then Fit, Corner radius and Effects (the shared `EffectFields` with stroke, drop shadows and glow). The widget puts the radius, the stroke (a CSS outline, outside or centred) and the shadows / glow (`drop-shadow` filters, so a transparent logo is lit along its shape) on the `<img>`. A shape layer's panel (`ShapeFields`): shape type, corners (linked radius or four, rectangle only), line caps and arrowheads, sides and star inner radius, Fill none / solid / gradient (type, the shared `GradientStops` editor, angle), Stroke (colour, width, dash, position) and Effects (the shared `EffectFields` with shadows and glow only). A text layer's panel is the shared pieces: the wording field with token chips, B / I / Colour markup buttons and the live result (`TextControl`, tokens by view: the collection view only knows the viewer), the font picker, size, colour, vertical align and the Character panel over the layer's own `style` patch (`TextPatchPanel`, patch mode, with Highlight tokens). No warning when the layer already has an outline of width 1 or more whose colour reads at 3:1 against the text colour. Limits: the built-in text parts have no stage-level colour (their text sits on its own bar, pill or banner, or a fixed colour), so only custom text layers are checked; there is no "Add plate" because a plate needs a box and is not part of an overlay text patch (38.8); the box is the measured text box, so a very short word in a wide box is judged over the whole box.
- **Workspace column (ROADMAP 38.29 g)**: `useColumnLayout` (`app/admin/components/workspace/`, no overlay imports) holds the right column's width (20 to 36 rem, default 26), whether it is folded to an icon strip and the collapsed panel ids (default History) in localStorage `tcg:overlay-workspace` (try / catch, defaults without it); `OverlayEditor` feeds the width to the grid through `--dock-w` and passes the state to `PropertiesDock`. At `xl` only: `ColumnResizer` is a focusable `role="separator"` on the column's left edge (pointer drag, Left / Right arrows 1 rem, Shift 4 rem, Home / End, double-click resets), and a chevron in the first panel header folds the column to a 2.75 rem strip of panel icons; an icon unfolds it with that panel open. Below `xl` the column stays under the canvas and ignores all of this. **Window > Reset workspace** (`resetColumnLayout()`, a window event) clears the storage and restores the defaults. Compact look: 28 px panel headers, 12 px labels, tighter section padding. `ScrubLabel` (same folder) makes a number field's label draggable (4 px per step, Shift x10, clamped); used by the shared `Num` / `Row` (Character panel and the other `Num` fields), `LayerBlock`'s X / Y / Size and `CustomLayerPanel`'s X / Y / Rotate / Width / Height. The maths is in `workspace-math.ts` (`scripts/check-workspace-math.mts`).
- **Pointer readout and Alt-measure** (ROADMAP 38.19; `PreviewPointer.tsx`, `measureGaps` in `lib/overlay-layout.ts`, editor only, nothing stored): in the editor the widget posts `{ type: 'pointer', x, y }` (design px; `x < 0` when the pointer leaves) on every move, and the status bar shows it as X / Y beside the zoom. With Alt held over a part that is not selected (and something selected, not in pack scope) the message also carries `over` and `sel` (that part's box and the selection's union box, `DesignBox`es like 38.5's); `MeasureOverlay` outlines both and draws red lines with the gap in px for each axis they are apart on (nothing on an axis where they overlap). The hook keeps the pointer out of the editor context so a mouse move re-renders only these two components.
- **Resize anchor** (ROADMAP 38.22; a 3x3 grid in the Layer block, `anchor` in `OverlayEditorContext`, editor state only, centre by default, reset on reload): the Size field and the corner handles keep that point of the part still by adding `anchorOffset()` (`lib/overlay-layout.ts`) to the offset as the scale changes. Parts scale about their centre (no part sets another CSS origin), and while the anchor is off-centre the editor measures the selected parts (the `measure` message) to learn each one's size at 100%. Parts only: a whole view's corner handle and Size slider still scale about the view's own origin, and custom layers resize by box.
- **Navigator (ROADMAP 38.20)**: `NavigatorPanel.tsx`, a dock panel between Layers and History shown only while zoomed past fit (`zoom > 1`) and not in pack scope. A mini-map of the canvas scroll box (read from `boxRef`'s scroll size, scroll position and client size, so no second zoom model): the yellow box is the visible part, press or drag the map to centre the view there, and the slider zooms (log scale from fit to the 800% cap, through the context's `zoomTo`). Editor-only, nothing stored.
- **Artboards (ROADMAP 38.17)**: View > Artboards (off by default, not stored; every board is a live iframe) shows `ArtboardStrip.tsx` between the stage and the timeline: a wrapping strip of small stills, one per scope other than the current one (Global plus every scene, also while a pack is open), each at its own stage size scaled to fit 220 x 130 and labelled with its name and size. They are fed the editor's current (unsaved) layout and values for that scope and the Variant / Mode pickers, in the settled still (`static`). Clicking one calls `setScope` like the scope tabs. The current scope stays the normal playable stage. At most 8 boards render; a note says how many are left out.
- **Compare versions (ROADMAP 38.27, part 1)**: each row of Versions has a **Compare** button that opens `CompareDialog.tsx` (state in `EditorTopBar`, so it outlives the menu): two pickers (any saved version, or "Current editor values"; left starts on the clicked version, right on current), each feeding a live settled still (`StillFrame`, exported from `ArtboardStrip.tsx`, fed that look's global layout and global values and the Variant / Mode pickers) with `DiffList` underneath. The difference list is `diffLooks` in `lib/overlay-diff.ts` (layout, global values, per-pack overrides), which `versionDiffs` now shares. **Thumbnails (38.27, part 2)**: each row of Looks (presets) and Versions starts with a 72 x 44 `StillFrame` (`Thumb` in `EditorMenus.tsx`). A version passes its own `layout` and `props`; a preset passes its `props` with its saved `layout`, else the editor's current layout. Nothing is stored or captured; the stills are live iframes that mount only while the flyout is open and only while their row is visible in the flyout's scrolling list (an `IntersectionObserver` in `Thumb`; the still unmounts when scrolled out). There is no separate `MAX_BOARDS` cap here: the lists' max heights (`max-h-48` / `max-h-64`) keep about 4 to 6 iframes alive at once.
- **Editor v2 tools**: **Undo / redo** (Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y; a drag or slider burst is one step, 500ms-coalesced snapshots of global + pack + layout state, 60 deep; ignored while typing in text/number fields; each step has a short label set by `tagEdit(label)` where the edit is made, and a coalesced step keeps its first label; saving does not clear the stack), **History panel** (`HistoryPanel`, a collapsed-by-default panel under Layers: the stack oldest first from "Opened", the current step highlighted, steps after it greyed until a new edit drops them; clicking a row calls `jumpTo(i)`, the same restore as undo / redo), **Review** (`lib/overlay-diff.ts`: every setting that differs from what is saved, old → new) and **Before / after** (flips the preview to the saved values). **Saved versions** (`lib/overlay-versions.ts`, KV `overlay:versions`, newest 20): every save snapshots the whole look with an optional note (the first save also records "Before versions were kept"); *Load* puts one into the editor as unsaved changes, Save makes it live. **Live refresh**: `overlay:reload` is a token returned by `POST /api/overlay/heartbeat`; the widget records the first value and reloads when it changes, but only while idle (`checkReload`, nothing animating or queued). The **Refresh overlay** button (`refreshOverlayAction`) bumps it, and Save options (File menu) can do it after every save (`OverlaySettings.autoReload`). **Guides / view**: thirds, 10% grid, safe areas, snapping while dragging (the preview snaps a part's edges and middle to the stage edges / centre and to the other parts within 6 px and draws the guide line; where nothing is near, the editor falls back to its own centre-then-10 px; Alt = free, and the Snap switch turns all of it off), zoom, background (checker / dark / light / green / a local screenshot picked from a file or pasted with Ctrl+V outside a text field, never saved), and a preview pack + card picker (`postMessage` `props` carries `packId` and `cardNumber`; widget `previewCardNumber`). **Load rating** (`lib/overlay-perf.ts`, `variantPerf`): a rough per-version cost from the effects switched on (glow size, rays, sparkles, looping shimmer, 3D tilt), shown in the status bar, the variant picker and variant page; a guide, not a measurement. **Pack tools** (pack scope): copy this pack's overrides to other packs, replace them from another pack, list differences from global, clear. **Season looks**: `overlay:seasonlooks` maps a season to a preset; `GET /api/overlay/config` layers the ACTIVE season's preset over the global props (pack overrides still win), set from File → Looks → Season looks. **Scheduled looks** (ROADMAP 38.28): `overlay:scheduledlooks` is a list (max 20) of `{ id, presetId, start, end }` (epoch ms UTC), set from File → Looks → Scheduled looks (`addScheduledLookAction` / `removeScheduledLookAction`). While one runs (`getActiveScheduledLook`; of two overlapping the later start wins) `GET /api/overlay/config` layers its preset over the season look and under the scene's values (merge order: global, season look, scheduled look, scene; pack overrides still win in the widget). The heartbeat returns `getReloadSignal()`, the stored refresh token plus the active schedule id (`<token>:<id>`), so an idle overlay reloads by itself at each start and end. Entries that ended over 30 days ago are dropped on the next add. There is no streamer time zone setting: times are typed and shown in the admin's browser time zone, with its short zone name. `scripts/check-overlay.mts` (mock KV) covers versions, the token, season looks, scheduled looks, diff and perf. Overlay actions re-check admin (`requireAdmin`).
- Testing tip: to inspect an animation at an exact moment, start a draw, then `document.getAnimations().forEach(a => { a.pause(); a.currentTime = ms })` and screenshot (set `PACKS[0].pack.cardTime = 120` first so the card stays up). Screenshots lag by a second or two, so don't time them against the live animation.

## Only-when-live switches
Settings → OBS Overlay has two checkboxes (KV `overlay:settings`, `lib/overlay-settings.ts`): ignore incoming **pack** triggers and/or **collection** triggers unless the stream is live. `liveGate(kind)` is called by `/api/webhooks/pull` and `/api/webhooks/collection` before enqueueing; blocked triggers are dropped (not queued) and answered `{ ok: true, ignored: true, reason }`. "Not live" = no overlay connected, or a connected overlay reports `streaming === false`. If OBS hasn't granted the browser source status permission, `streaming` is `null` and triggers are allowed (we can't tell). Dashboard quick actions deliberately bypass the gate. It fails open on any error.

## Overlay performance
The OBS overlay must stay smooth, so keep these rules when editing `public/widget.js` / `widget.css`:
- **The collection grid uses thumbnails, never the animated WebPs.** `/api/seasons/active` adds `thumbUrl` to every card (`cardThumbUrl()`); the widget maps it to `card.thumb` and `buildMiniList` uses it. `preloadThumbs()` decodes them all on load, and `drawCard` calls `warmImage(card.image)` as soon as a card is picked so the reveal doesn't hitch on decode.
- **Animate only `transform`/`opacity`.** The holographic shimmer slides a pre-painted `::before` layer with `translate3d` instead of animating `background-position` (which repaints every frame). No `filter: blur` on animated layers.
- **Keep images small.** `public/assets/pack-cover.png` is drawn ~287px wide but used 3× per pack theater, so it is stored at 640px wide (~0.4MB). Don't replace it with a full-resolution original.
- `/assets/cards/*` and `/assets/sounds/*` are served with a day of `Cache-Control` (see `next.config.ts`) so OBS refreshes don't re-download the art.
- **Serial number on the reveal (ROADMAP 2.4)**: `POST /api/collection` also returns `uid` (the serial number of the copy just made) and `showSerial()` in `widget.js` reads it. Property `reveal.serialFormat` (Pack opening -> Number shown on the card): stored values stay `edition` (`#7`, the edition number, the default), `uid` (`#1023381`, the serial number) or `both` (the `#7` pill with a small `Serial #1023381` line under it, `.serial-print`). Without a `uid` (older server, untracked ledger) it shows the edition number. The menu calls the pill "Edition number on the card". The test panel's dry runs and the editor preview use a sample number. The chat show-off sends the lowest print's `uid` too (`prepareShowOff` -> queued `card` event -> `drawCard({ show })`).

## Special moments (Overlay Editor -> Special moments)
Three banners for pulls worth a cheer, in priority order, **one per pull, the highest wins** (`pickMoment` in `lib/overlay-moments.ts`, mirrored in `widget.js`; `scripts/check-overlay.mts` runs both over every combination):
1. **First-ever print** (edition #1 of that card in that version): on by default. Keeps its original keys `reveal.firstEver`, `reveal.firstEverText`, `reveal.firstEverHold` (only the group changed, no migration) plus `moment.firstEver.*`.
2. **A viewer's first pull** (`moment.firstPull.*`): they owned nothing in this collection before this pull. Off by default, text `Welcome, {username}!`.
3. **A new card for them** (`moment.newCard.*`): they did not have this card before. Off by default. (The small "new" label is still `variant.regular.labelText`.)
Each has the same controls (`momentProps` in `lib/overlay-props.ts`): text, a small line, banner colours (1 to 4, a gradient when more than one), text colour, size and font, position on the card (top / middle / bottom), sparkles and their colour, an optional sound (an asset address) and its volume, extra hold, and a reveal style override (`inherit` by default). The font select uses the card-back faces (`BACK_FONTS`). Site display is the default and leaves the banner's face alone; any other face loads that card-back file. `momentSpec` reads them and `momentBanner` draws the one banner (`.first-banner`, the stylesheet is the first-ever look and only differences are written inline, so the defaults are today's banner exactly). `{username}` and `{cardName}` work in the text lines.
- **Data**: `POST /api/collection` replies with `isNew` and `firstForViewer` (both from the collection as it was before the pull) besides `serial`. The moment is chosen when that reply arrives (label time), or from the overlay's own copy for dry runs.
- **Style override**: first pull and new card are known before the reveal, so their style applies at once. First-ever is only known after the save, so while `moment.firstEver.style` is not `inherit` that one real pull is saved first and played when the server answers (the `_pre` path in `drawCard`); at `inherit` nothing changes.
- **Preview**: the editor's **Moment: None / First-ever / First pull / New card** (next to "Show as") makes Play force that moment even when its switch is off; the `?dev` test panel has the same **Special moment** picker (and **First-ever pull [1]**).

## Show off look (Overlay Editor -> Show off)
Group `showoff`, all `show.*` keys; every default is the look the show-off always had. Sections: **Entrance and timing** (`show.style`, limited to the pack-less styles, and `show.hold`), **Label** (`show.showLabel`, `show.text` with `{user}` / `{username}` / `{cardName}` / `{variant}`, `show.ownLabelLook` + colours, size, `show.labelFont`, and an X / Y nudge as the position), **Edition number** (`show.showPrint`, `show.printFormat`: inherit / edition / uid / both), **Card and effects** (`show.cardScale` multiplies `reveal.cardScale`, `show.glow` / `show.sparkles`: inherit or off) and **Sound** (`show.sound` on / off / custom with `show.soundUrl`, `show.volume`).
- **How it is applied**: `showOffProps(P, variant)` in `widget.js` folds the show-off keys into a copy of the effective properties (card scale, the version's glow / sparkles, `reveal.showSerial`, `reveal.serialFormat`), so the shared drawing code has no show-off branches; `styleShowLabel` handles the label. The label keeps following the "got:" pill colours until `show.ownLabelLook` is on.
- **Preview**: the editor's View menu has **Show off** (a settled still with a sample viewer and print; **Play show off** runs one). Placement is the pack opening's (the Layout panel is unchanged).
