# OBS overlay

> Read this when you touch `public/widget.js`, `widget.css`, the Overlay Editor, scenes, overlay properties, the show-off command, quick actions or the only-when-live switches.

## OBS widget data flow
1. Widget calls `GET /api/seasons/active` on load → returns `{ season, packs: [{ pack, cards }] }`
2. Widget picks pack by weight, then card by probability
3. Widget calls `POST /api/collection` to save card number to legacy collection (duplicates allowed, pull count). A queued pull with `paid: true` (Mix It Up, see docs/admin.md) is saved with its `payId`; the reply may be `{ ok: true, revoked: true, owned }` when the payment failed, and the widget just resyncs `owned`.
4. Widget reads `GET /api/collection?name={collectionName}` to show mini-list with ×N badge for duplicates

The widget reads per-pack visual settings (accentColor, tearBorderColor, holoMinStars, cardTime, cooldownTime, soundVolume, coverImageUrl) directly from the pack object. Card sounds come from `card.soundUrl` (e.g. `/assets/sounds/1.mp3`).

## Overlay status & quick actions
- **Connection indicator**: each overlay page load picks a random id and sends a heartbeat every 10s (`lib/overlay.ts`, KV hash `overlay:clients`); a client counts as connected for 25s after its last heartbeat. `OverlayStatusProvider` (in the admin layout) polls `/api/admin/overlay-status` once every 5s and `OverlayStatus` (sidebar + dashboard header) and `QuickActions` read it. Open the overlay in a normal browser tab and it shows as "browser tab".
- **Live detection**: if OBS grants the browser source *Page permissions → "Read access to OBS status information"*, the widget calls `window.obsstudio.getStatus()` and reports `streaming`/`recording` (and re-reports on the `obsStreamingStarted/Stopped` events). Without that permission those stay `null` and the UI says only "connected". It cannot know the stream is live any other way.
- **Quick actions** (dashboard): `quickAction` in `actions.ts` dispatches on the submit button's `intent` (gift packs, show collection, grant card); `clearQueueAction` empties the overlay queue. Gift/show enqueue the same events the webhooks do (`enqueueEvent`) and are refused with a "queue anyway" option when no overlay is connected, so packs can't pile up unseen. They return an `ActionResult` shown inline via `useActionState`. Keep form fields controlled, React resets uncontrolled fields after a form action. `/admin?gift=<username>` prefills the viewer (the users list 🎁 link uses it).
- **Users list**: rows are one stretched link to `/admin/users/[username]` (profile editing lives there), sortable via `?sort=cards|pulls|active|name`; "last active" comes from the latest 500 activity events.

## Overlay layout (Overlay Editor → Layout)
The overlay is drawn on a fixed **design stage** (default 1280×720, `lib/overlay-layout.ts`) and scaled to fit the real OBS browser source, so a differently sized source never cuts the animation off (the pack opening spans about -425px..+208px around its centre, which `.pack-fit` re-centres). The browser-source size is shared, but **the pack opening and the collection view are placed independently**: `OverlayLayout = { width, height, pack: Placement, collection: Placement }` (`Placement` = `scale`, `offsetX`, `offsetY`, design px) in KV `overlay:settings.layout`; `sanitizeLayout()` upgrades the old single-placement shape (both views inherit it, so nothing moves). `GET /api/overlay/config` serves it and `widget.js` `applyLayout()` writes `--stage-scale` (the fit, on `.container`) plus `--pack-*` / `--col-*`; each theater wrapper gets `.is-pack` or `.is-collection`, which place themselves with the standalone `translate` / `scale` properties (so they stack with the animations' own `transform`s). The editor (the **Layout** category of `OverlayEditor`) has a Pack opening / Collection switch (each with size, X/Y, Center, Reset), drag-on-the-canvas + arrow-key nudging (one screen pixel = `1/fit` design pixels), browser-source size presets, and shows the real overlay in an iframe (`/overlay.html?preview`), pushing changes by `postMessage` (`layout`, `static`, `pack`, `collection`). While nothing animates the preview shows a **still** of the settled pack opening or of the collection view (`showStatic()` in `widget.js`, wrapper class `.static-preview`) so it can be sized and moved; **Play** runs the real animation and the still comes back when the queue goes idle. The editor re-sends the layout on every iframe `load` (an iframe starts as a blank page that already reads "complete", so a one-off ready flag races); **preview mode never touches the queue, heartbeat or collections** (no polling, no saving, no sound, fake `preview` user), keep it that way. `sanitizeLayout()` clamps everything, server-side too. The collection grid still wraps at 800px (`.card-wrapper { max-width: 800px }`).

## Overlay scenes (one overlay URL per OBS scene)
A **scene** is a preset (`OverlayPreset` in `lib/overlay-settings.ts`) that may also carry its own **layout** (stage size + pack / collection placement). Every preset has its own overlay URL, `/overlay.html?preset=<id>`: `widget.js` `loadLayout()` passes it to `GET /api/overlay/config?preset=<id>`, which returns the scene's layout (when it has one, else the global layout) and layers the scene's values over the global look and the season's look (pack overrides still win). An unknown id is just the global overlay. Use a different URL in each OBS scene, e.g. a vertical one. Caveats: the queue is shared, so whichever open overlay polls first plays a pull (OBS only keeps the visible scene's source running by default); a scene's values are overrides, so it follows later global changes except for what it sets itself.
- **Editing**: the Overlay Editor's **Editing** menu has a "Scenes" group (`scope = "scene:<id>"`), and the **Scenes** popover lists every preset with its URL (Copy / Open / Edit) and creates a new scene (Landscape = a copy of the global layout, Vertical = a 1080 × 1920 stage via `sceneLayout()`). A scene's values live beside the pack overrides in the editor state (`packVals["scene:<id>"]`, stored with `keepDefaults`, so one equal to the default still beats a global value) and its layout beside the global one (`layoutMap`); one Save posts `{ layout?, global?, packs, scenes: { id: { props, layout } } }` and `saveOverlayEditorAction` calls `updateScene`. The Layout panel offers vertical size presets (`VERTICAL_LAYOUT_PRESETS`), a Rotate button and, for a vertical stage, a hint with a one-click "4 cards per row" (`collection.perRow`), since the collection grid wraps to the stage width. Scenes are not part of saved versions (those cover the global look only). `scripts/check-overlay.mts` covers it.

## Show off a card (chat command)
A viewer types a chat command (e.g. `!show shiny gouda goat`); the streamer's bot calls `POST /api/webhooks/show-card` with `{ secret, username, card }` and the overlay shows that card. The command name is the bot's, not ours.
- **Parsing is pure** (`lib/showoff.ts`: `parseShowQuery`, `resolveCard`, `pickShowVariant`; `scripts/check-showoff.mts`): an optional version word (shiny / full art / reverse holo / regular…), then a card name or number; empty = their most valuable card. Owned cards win over unowned name matches; no version asked = the best owned version.
- **The server decides** (`lib/showoff-prepare.ts`, `prepareShowOff`): the card must be in the active season and owned by the viewer in that version, the serial sent is their lowest copy of it (with its serial-bonus multiplier), and the per-viewer cooldown (`showoff:cd:<user>`, 15 s) is taken LAST so a refused request doesn't spend it. The route answers 200 with `{ ok: false, error, message }` on refusals so bots can say `message` in chat; success returns `{ ok, message, card, variant, serial }` and queues a `card` event (`QueuedEvent`: `cardNumber`, `variant`, `serial`, `serialMult`). It goes through `liveGate('collection')` and logs a `trigger` activity (`kind: 'card'`, shown in the feed / dashboard / Discord).
- **Overlay**: `pollWebhookQueue` → `queueShowCard(user, ev)` → `drawCard(user, { show: ev })`: the card/variant are pinned, nothing is saved or added to the collection, the style is the pack-less `show.style` (default `drop`; a pack style falls back to `drop`), the strip is hidden, and the serial pill comes from the event. Props `show.style` / `show.hold` / `show.text` live in the registry (group Pack opening, section "Show a card (chat command)"). Test panel: **Show off card [W]** (dry, sample serial). `scripts/check-showoff-server.mts` (mock KV) covers ownership, cooldown, serial and the best-card default.

## Overlay properties (Overlay Editor)
Every adjustable aspect of the overlay's look is a **property** in one registry, `lib/overlay-props.ts` (`PROPS`, grouped by `PROP_GROUPS`): a dotted key (`collection.perRow`, `reveal.style`, `variant.shiny.holoSpeed`), a type (`number` / `boolean` / `select` / `color` / `colors` / `text`), default, limits, help text, optional `experimental`. **The defaults reproduce the original look exactly**, so an untouched install is unchanged. The editor UI, validation, reset, presets and import/export are all generated from the registry, to add a property: add one entry there, then consume it in `widget.js` (read it with `pv(P, key, fallback)`); add a `dependsOn()` rule in the editor if another switch turns it off.
- **Storage is sparse**: only values that differ from the default are saved (`sanitizePropValues`, which also drops unknown keys / invalid values). Global values: KV `overlay:settings.props`. **Per-pack overrides**: KV `overlay:packprops` (`{ [packId]: values }`, kept off the Pack object because pack forms rewrite the whole pack). These use `{ keepDefaults: true }` because an override equal to the default must survive when the global value isn't the default. Named presets: KV `overlay:presets` (max 30; saving an existing name replaces it). All in `lib/overlay-settings.ts`.
- `GET /api/overlay/config` returns `{ layout, defaults, props, packOverrides }`; the widget (`loadLayout()`) merges defaults → global → the pack's override in `effectiveProps(packId)`. The **collection view uses global values only** (it isn't pack-specific; the editor hides that group in pack scope). The config is read once at load, so OBS needs a browser-source refresh after saving (the editor says so).
- **Categories** (`PROP_GROUPS`): **Pack opening** (`reveal.*`: animation, card size, label incl. `labelOwned`, name/stars bar, "got:" line, start delay, pack size, and the row of cards under the revealed card. Its own `reveal.strip*` settings), **Variants** (`variant.regular|reverse|full|shiny.*`, each `PropDef` carries `variant`: label, a per-variant **reveal animation override**, holo, glow, pop, 3D tilt, rocking, **light burst** (on/off, strength, size, ray count, spin time, colour, hue cycle), sparkles, time and sound) and **Collection** (`collection.*`, the "show collection" view, global only). The strip and the collection view deliberately do NOT share keys. Group membership is metadata only, stored values are keyed by the dotted key, so regrouping never migrates data (note: `collection.*` card-look values saved before the strip got its own keys no longer affect the strip).
- **Reveal styles** (`REVEALS` in `widget.js`): classic (the original), simple (zoom), slide, flip (card back = the pack cover, `.card-back`, edge-on at 55% of the keyframes), and the experimental **rip-shake** (pack trembles, tear strip flies off, card bursts out) and **rip-peel** (tear strip peels back from one end). Each style names its keyframes plus when (seconds at 1×) the card is revealed / info / label appear; `reveal.speed` divides every duration *and* timeout. Hold time = `label time + 0.8s + pack.cardTime` (classic = the old `cardTime + 4s`). More styles: **rip-slice** (tear strip slides straight off sideways), **rip-explode** (pack swells, flashes white, bursts), and the pack-less **drop**, **spin**, **impact** and **deal**. `variant.X.style` (default `inherit`) overrides the pack opening's style per variant (e.g. Shiny always rips); `reveal.startDelay` adds seconds to every animation delay and timeout (`D` in `drawCard`); `reveal.packScale` uses the standalone `scale` on `.package-container`. The light burst is per variant: `burstSpec()` / `buildRays()` rebuild the rays (`--ray-step`) and size the container (`reveal.showBurst` / `reveal.burstOpacity` no longer exist; unknown keys are dropped on read, so old values vanish harmlessly).
- **Per-version looks are CSS variables** written on each theater wrapper by `applyLook()` (`--label-bg`, `--holo-*`, `--glow-*`, `--pop-*`, `--rock-amt`, `--burst-a/b`), and `mainCardAnimation()` composes the card's `animation` list from the generic keyframes (`variantPop`, `variantGlow`, `variantRock`, rock uses the standalone `rotate` so it layers on the pop). The old per-variant CSS rules are gone. Holo: `--holo-gradient` is built from up to 8 colours cycled into the original 8-slot geometry; loop mode uses `rainbowLoop` (slides exactly one gradient tile so it joins seamlessly). The website / Twitch panel holo is separate and unaffected.
- **Editor (a Photoshop-style workspace)**: the rail has **Layout** (stage size + per-view placement, global so it is hidden in pack scope; the canvas becomes drag-to-position while it is open) plus the registry categories. One **Save** posts only what changed (`saveOverlayEditorAction`, payload `{ layout?, global?, packs? }`). An options bar (scope: Everything / Override for pack X; Presets and Import/Export popovers; Revert/Save), a **canvas** that fits the whole stage into the available space both ways (never scrolls; View: Pack opening / Collection, "Show as" version, Play) and a **docked properties panel** (category rail, search across every setting; **Variants** opens a picker (one card per variant, "Previewing" marked) and then edits that variant under a `← Variants / Shiny` breadcrumb with "copy the look of…", collapsible sections with changed counts, per-property and per-section reset, `inherit` in pack scope). One `version` state drives both which variant is edited and which the preview shows. **Clicking an element in the preview opens its settings**: the widget (preview only) tags the still's elements with `data-edit` (card, label, bar, got, strip, heading, collection), highlights them on hover and `postMessage`s `{ type: 'select', target }`; the editor maps that to a category + section and scrolls it into view (the Layout drag surface covers the iframe, so clicks only reach it outside Layout). The workspace is `xl:h-[calc(100vh-4rem)]` and `main:has([data-workspace])` is `overflow: hidden` there so the page doesn't scroll; below `xl` it stacks. It **auto-collapses the admin sidebar** while mounted without touching the saved choice: it sets `window.__tcgSidebarForce` and fires a `tcg:sidebar` event that `AdminShell` listens for. the preview gets `postMessage` `props` (unsaved effective values + `packId`), `variant`, `static`, `pack`, `collection`.
- **Glow follows the art's silhouette**: a `.glow-layer` behind the card (inside `.main-card`, whose art is now the `.card-art` child) is a blurred copy of the art, blur on the OUTER element, the `--card-mask` thumbnail mask on the INNER `.glow-fill`s, because CSS applies `filter` before `mask` and masking the blurred layer would cut the halo at the edge. Rounded corners and holes in the artwork therefore stay clear; only opacity/transform animate (no per-frame blur). **3D tilt** animates the card box's standalone `rotate` (`variantTiltx|y|xy`, `perspective` on the wrapper via `.tilt-on`), so it doesn't fight the entrance transform or the 2D rock. `mainCardAnimation()` returns `{ anim, start }`; `--fx-start` delays glow/tilt until after the pop. Card-styling vars, collection `sort`, per-version `holdExtra` / `volume` / sparkle burst (`burstSparkles()`) are as before.
- **Editor v2 tools**: **Undo / redo** (Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y; a drag or slider burst is one step, 500ms-coalesced snapshots of global + pack + layout state, 60 deep; ignored while typing in text/number fields), **Review** (`lib/overlay-diff.ts`: every setting that differs from what is saved, old → new) and **Before / after** (flips the preview to the saved values). **Saved versions** (`lib/overlay-versions.ts`, KV `overlay:versions`, newest 20): every save snapshots the whole look with an optional note (the first save also records "Before versions were kept"); *Load* puts one into the editor as unsaved changes, Save makes it live. **Live refresh**: `overlay:reload` is a token returned by `POST /api/overlay/heartbeat`; the widget records the first value and reloads when it changes, but only while idle (`checkReload`, nothing animating or queued). The **Refresh overlay** button (`refreshOverlayAction`) bumps it, and the Save options popover can do it after every save (`OverlaySettings.autoReload`). **Guides / view**: thirds, 10% grid, safe areas, snapping while dragging Layout (centre, then 10 px; Alt = free), zoom, background (checker / dark / light / green / a local screenshot, never saved), and a preview pack + card picker (`postMessage` `props` carries `packId` and `cardNumber`; widget `previewCardNumber`). **Load rating** (`lib/overlay-perf.ts`, `variantPerf`): a rough per-version cost from the effects switched on (glow size, rays, sparkles, looping shimmer, 3D tilt), shown in the canvas bar, the variant picker and variant page; a guide, not a measurement. **Pack tools** (pack scope): copy this pack's overrides to other packs, replace them from another pack, list differences from global, clear. **Season looks**: `overlay:seasonlooks` maps a season to a preset; `GET /api/overlay/config` layers the ACTIVE season's preset over the global props (pack overrides still win), set from Presets → Season looks. `scripts/check-overlay.mts` (mock KV) covers versions, the token, season looks, diff and perf. Overlay actions re-check admin (`requireAdmin`).
- Testing tip: to inspect an animation at an exact moment, start a draw, then `document.getAnimations().forEach(a => { a.pause(); a.currentTime = ms })` and screenshot (set `PACKS[0].pack.cardTime = 120` first so the card stays up). Screenshots lag by a second or two, so don't time them against the live animation.

## Only-when-live switches
Settings → OBS Overlay has two checkboxes (KV `overlay:settings`, `lib/overlay-settings.ts`): ignore incoming **pack** triggers and/or **collection** triggers unless the stream is live. `liveGate(kind)` is called by `/api/webhooks/pull` and `/api/webhooks/collection` before enqueueing; blocked triggers are dropped (not queued) and answered `{ ok: true, ignored: true, reason }`. "Not live" = no overlay connected, or a connected overlay reports `streaming === false`. If OBS hasn't granted the browser source status permission, `streaming` is `null` and triggers are allowed (we can't tell). Dashboard quick actions deliberately bypass the gate. It fails open on any error.

## Overlay performance
The OBS overlay must stay smooth, so keep these rules when editing `public/widget.js` / `widget.css`:
- **The collection grid uses thumbnails, never the animated WebPs.** `/api/seasons/active` adds `thumbUrl` to every card (`cardThumbUrl()`); the widget maps it to `card.thumb` and `buildMiniList` uses it. `preloadThumbs()` decodes them all on load, and `drawCard` calls `warmImage(card.image)` as soon as a card is picked so the reveal doesn't hitch on decode.
- **Animate only `transform`/`opacity`.** The holographic shimmer slides a pre-painted `::before` layer with `translate3d` instead of animating `background-position` (which repaints every frame). No `filter: blur` on animated layers.
- **Keep images small.** `public/assets/pack-cover.png` is drawn ~287px wide but used 3× per pack theater, so it is stored at 640px wide (~0.4MB). Don't replace it with a full-resolution original.
- `/assets/cards/*` and `/assets/sounds/*` are served with a day of `Cache-Control` (see `next.config.ts`) so OBS refreshes don't re-download the art.
- **Print number on the reveal (ROADMAP 2.4)**: `POST /api/collection` also returns `uid` (the print number of the copy just made) and `showSerial()` in `widget.js` reads it. Property `reveal.serialFormat` (Pack opening -> Label): `edition` (`#7`, the default), `uid` (`#1023381`) or `both` (the `#7` pill with a small `Print #1023381` line under it, `.serial-print`). Without a `uid` (older server, untracked ledger) it shows the edition. The test panel's dry runs and the editor preview use a sample number. The chat show-off sends the lowest print's `uid` too (`prepareShowOff` -> queued `card` event -> `drawCard({ show })`).
