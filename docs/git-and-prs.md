# Git and PRs

> Read this before you push, open a PR, or merge one.

- Branch off an up-to-date `origin/main`, push, open a PR against `main`. **Every push to GitHub gets a PR**: open one straight away if the branch has none. Don't push to `main`.
- **PR bodies follow `.github/pull_request_template.md` exactly** (`## Changelog`, `## Summary`, `## Docs`, `## Test plan` in that order; Changelog is `none` or Audience, Tags and `- ` bullets only). The `PR description` check fails otherwise; test a body first with `gh pr view N --json body --jq .body | node scripts/check-pr-body.mjs`.
- **A PR that changes TCG Bridge needs a `## TCG Bridge` section.** Anything under `bridge/` (except `bridge/README.md`), `streamdeck/` or `obs-plugin/` (except its README) needs it, between `## Summary` and `## Docs`: only `- ` bullets written for the streamer, saying what changed in the app. The bridge release uses them as its notes and the app's What's new shows exactly those bullets for the version. `scripts/check-docs.mjs` (the `PR description` workflow) fails a bridge PR without a bulleted section. Other PRs leave the section out.
- **Docs, the staff wiki and the README are checked on every PR** (`scripts/check-docs.mjs`, run by the `PR description` workflow, so editing the PR body re-runs it).
  - `docs/doc-map.json` lists, per doc, the code globs it describes (`exclude` removes paths; `ignore` lists history docs such as `docs/archive/**`). Each `content/wiki/*.md` page owns its list in a `covers:` front matter line (comma-separated globs). If the PR changes a file a doc covers and does not change the doc, the check fails and prints the doc, the files and the line to add.
  - The `## Docs` section is required and says what you did: `Docs updated: docs/overlay.md, README.md`, and/or one line per doc that is still accurate: `No change needed: docs/overlay.md: only renamed an internal helper`. The reason must be at least three words; `all` in place of a path skips every doc (use it sparingly). The `claude-review` check reads the diff against these docs, so a skip that the diff contradicts gets flagged.
  - It also fails when a glob matches no file (the map rotted: fix or remove it) and when a `docs/**/*.md` or `content/wiki/*.md` file is neither mapped nor ignored (a new doc must be mapped in the same PR). PRs that touch only docs, `ROADMAP.md`, `HANDOFF.md` or the PR template pass.
  - Run it before pushing: `gh pr view N --json body --jq .body | node scripts/check-docs.mjs origin/main`.
- **Before pushing to a branch that has a PR, check whether that PR is merged.** If it is, start again from `origin/main` (rebase any unmerged commits onto it) and open a new PR; never stack new work on a merged PR.
- **Merging:** Opus may merge PRs and delete their branches when necessary (CI green, no open review asks). Sonnet and Haiku don't merge or close PRs unless the user asks.
- **Before merging, read all three comment lists**; the `claude-review` bot posts bugs as **inline** comments, which `gh pr view --json comments,reviews` does not show. Run `for k in pulls/N/comments pulls/N/reviews issues/N/comments; do gh api repos/JoshMiles/tcg/$k --jq '.[] | "\(.user.login) \(.path // "") \(.line // "")\n\(.body)\n---"'; done` (N = PR number) and fix or answer every finding first. A green `claude-review` check does not mean it found nothing.
- **One feature per PR, each branched from `main`.** Never stack PRs: merging them out of order drops commits. A fix that lands after its PR merged needs a new branch and PR.
- Commit messages and PR bodies end with the attribution lines the harness gives.
- CRLF warnings on Windows are harmless (`.gitattributes`). The pre-rewrite `Old/` folder and `olddata.txt` are only in git history now (gitignored).
