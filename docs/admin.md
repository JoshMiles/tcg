# Admin panel

> Read this when you touch an admin page, a wizard, the dashboard, the assets page, users admin, the Discord feed or admin UX conventions.

## Drafts & wizards
- `Pack.status` / `Season.status` are `'draft' | 'published'` (missing = published, via the normalizers). **Drafts are never drawn or activated**: `getActiveSeason` ignores draft seasons, `setActiveSeason` throws for one, `getActivePacksForSeason` skips draft packs, the public leaderboard hides draft seasons. A published season may have a draft pack attached; it just isn't drawn until published.
- The wizards create the draft record when the first step is completed (`createDraftPack` / `createDraftSeason`), rewrite the URL to `?draft=<id>` with `history.replaceState`, then **autosave** (`useAutosave`: ~0.9s debounce, serialised, `flush()` before navigating). Resume = open the same URL (the lists link to it). Publishing re-validates on the server (`validatePack` / `validateSeason`).
- **Don't add `revalidatePath` to autosave actions and don't put a changing `key` on the wizard element**, either re-renders/remounts the page mid-edit and bounces the user back to step 1. List pages are `force-dynamic` so they don't need it.
- `saveCards` replaces a pack's card list; existing cards **keep their numbers** (viewer collections point at them), new cards get the next free number, and the assigned numbers are returned to the editor.
- **Season lifecycle (`lib/season-wrap.ts`)**: a season can have `startsAt` / `endsAt` (set with the timezone-safe `DateTimeField`, stored as ms) and `autoStart`. **There is no background job**: `getActiveSeason()` in `lib/kv.ts` calls `applySeasonSchedule()` (via a dynamic import, to avoid a cycle) the first time anything asks after a date has passed, so the overlay, panel and site all trigger it. A due start activates the season (the latest due start wins) and clears `autoStart`; a due end ends the active season. **Activation always goes through `activateWithWrapUp(id)`** (the Activate buttons, the settings checkbox, publishing with "activate"): it wraps up the season it replaces first (`takeSnapshot`: final standings + awards saved at KV `season:<id>:wrap`, `endedAt` set, `tradingFrozen` set) and clears `endedAt` / the freeze on the one it starts, so **Reactivate** is also how an ended season returns. **End season** (`endSeason`, from the season page's Wrap-up panel) does the same without starting another; **Reopen** clears the ended mark and the freeze. `Season.tradingFrozen` makes `createTrade` / `acceptTrade` refuse for that season (cancelling still works). **Awards** (`buildAwards`, pure): Champion / Runner-up / Third by score, Completionist, Biggest collection, Most cards pulled, Shiny hunter, Full Art collector; they show on the ended season's leaderboard page (a Final standings box) and as badges on `/collection/[username]` (`getUserAwards` reads every season's snapshot). The Activate confirmation (`getActivationPreview`) names the season that will be wrapped up and lists warnings (no live packs, empty packs, cards with no image / 0 odds, an end date already past). **Duplicate** (`duplicateSeasonAction`) copies a season's packs into a draft with a fresh collection name. The season page has an Overview (`getSeasonStats`, a pulls-per-day chart from `lib/stats.ts`, top collectors), the pack **LineupEditor** (drag or arrows to reorder, inline draw weights with each pack's share of draws, weight is the PACK's own setting, shared by every season using it) and the Wrap-up panel. `scripts/check-seasons.mts` (needs the mock KV) covers awards, timing, the scheduler, wrap-up on activation and the trading freeze.
- Season `collectionName` must be unique across seasons (a clash would merge two seasons' viewer collections), validated live and on publish.
- Published packs can be moved back to drafts from the pack page (`unpublishPack`).
- Published **seasons** can be moved back to drafts from the season page (`unpublishSeason`, with a confirmation). It also deactivates the season (so the overlay / Twitch panel see "no active season" until another is activated) and hides it from the public site; viewers' collections, packs and settings are kept, and it is republished from `/admin/seasons/new?draft=<id>`.

## Admin routes
- `/admin`. The **widget dashboard** (see "Admin dashboard (widgets)"): stats, quick actions, top collectors, leaderboard, rarity mix, packs, card ownership, recent activity, trading, overlay status, activity pulse, variant mix, most valuable cards, cards nobody owns, stream status, shortcuts and notes, arranged by the admin
- `/admin/seasons`, season list (drafts first)
- `/admin/seasons/new[?draft=id]`, season wizard / resume a draft
- `/admin/seasons/[id]`, season settings + pack assignment
- `/admin/packs`, global pack library: search (matches season names too, `/` focuses it), status filters (All / Live / Inactive / Drafts) and sorting via `PackToolbar` (tiles opt in with `data-pack` + `data-*` attributes; it toggles `hidden` / CSS `order`, no re-render); each tile shows the seasons it is used in (a warning when a published pack is in none, so it can never be drawn), an Upgrades chip, a one-click Active/Inactive switch (`setPackActive`) and a link to that pack's overlay overrides (`/admin/overlay?scope=<id>`)
- **Pack library extras**: every published tile shows a **health** badge (`packHealth()` in the client-safe `lib/pack-health.ts`: no cards, 0-odds cards, missing images / names, duplicate card numbers, Full Art cards without art, Regular weight 0, duplicate names, no cover, not in any season; links to `/admin/packs/[id]#health`) and the pack's **usage** (`pulls · % of draws`, from the per-pack counters `p:<pack name>` in `lib/stats.ts`, so it counts from when tracking began and follows the pack's name). Tiles also have **Duplicate** (`duplicatePackAction`: a draft copy named "<name> (copy)" with the same settings and cards under new ids; card numbers are copied, so renumber if both packs go in one season) and **Archive / Restore** (`Pack.archived`: hidden under the Archived filter, never drawn, can't be switched on, its cards stay so collections keep working; restore brings it back inactive). The actions live in `app/admin/pack-actions.ts`.
- **Pack page extras**: header Duplicate / Archive, a Pack health panel, and an **Odds & simulator** panel (`OddsPanel.tsx`): edit every card's weight in one table with live chance / "1 in N", Normalize to 100, Balance by rarity (set the share of pulls per star tier; cards in a tier share it equally), a share-by-rarity chart, and a draw simulator (1,000 / 10,000 / 100,000 packs from the weights typed, saved or not, with the variant roll and a 300-trial estimate of the packs needed to find every card). Saving goes through `savePackOddsAction`.
- **Card editor** (`cards/[cardId]/CardEditor.tsx`): the form is client-controlled, with a live **preview** beside it (the card with its Overlay Editor holo and variant look, per allowed version, from `holoByStars` computed server-side because the holo's "auto" mode depends on the star rating) and real-time **checks** (name / number clashes, no image, unoptimised GIF, Full Art with no art, 0 or unusual odds, odds out of line with the rarity). It still posts to the same `updateCard` action.
- `/admin/packs/new[?draft=id]`, pack wizard / resume a draft
- `/admin/packs/[packId]/cards`, bulk card editor for an existing pack (explicit save)
- `/admin/packs/[packId]`, pack page: header actions (activate / overlay look), a "Used in" seasons panel, a searchable / rarity-filterable cards table (`CardFilter`, same data-attribute approach), pack settings with a sticky Save, move to drafts, and a danger zone (delete)
- `/admin/packs/[packId]/cards/[cardId]`, edit individual card
- `/admin/trades`, Trades: summary tiles, offers-per-day chart, top traders / cards, a searchable filterable log (`TradeLog`; click a row for the detail panel: both sides, points, flags, cancel / extend / block viewer; CSV export), bulk controls (`TradeControls`: per-season trading switch, extend all, cancel & refund by scope) and settings
- `/admin/users`. All collectors: summary tiles, search + filter chips (tags, complete, shiny, restricted, notes), sort, columns, CSV export, bulk gift / tag (`UsersList`)
- `/admin/users/[username]`, user detail: overview tiles, tags, notes, timeline, trades (admin cancel), per-season grids, multi-card grant, compare (`?compare=`), moderation, restore points, merge, audit trail, danger zone
- `/admin/activity`, live activity feed
- `/admin/assets`, media library (see "Assets page" under Admin UX conventions): card art / pack covers / sounds / Unused / Insights tabs, detail panel, bulk fix, replace-in-place, selectable cleanup
- `/admin/webhooks`, redirects to Settings → Webhooks (incoming/outgoing webhooks + Discord feed now live in that tab; the components are `app/admin/settings/WebhookConfig.tsx` / `DiscordConfig.tsx`)
- `/admin/overlay`. The **Overlay Editor** (layout + look in one workspace; `/admin/settings?tab=layout|look` redirect here)
- `/admin/sandbox`, create and enter sandboxes (isolated copies of the data for testing upgrades / trades); `/admin/sandbox/[id]`, test users, simulated pulls, grant exact copies, log in as a test user, reset / delete
- `/admin/settings`, **tabbed** (`?tab=overlay|scoring|webhooks|viewers|environment|about`, server-rendered via `PageTabs`) under a row of status tiles (environment, Twitch extension, scoring changes, webhooks, build). **OBS Overlay**: source URL, connection (`OverlayStatus`), a test trigger (`OverlayTest`, the dashboard's `quickAction` 'show'), the two "only when live" switches (`LiveGates`, saved on flip through `setLiveGateAction`) and the bot snippet (`CopyBlock`). **Scoring**: `ScoringForm` (client) with a live preview: `previewScoringAction` → `previewScoring()` (`lib/scoring-preview.ts`, pure) re-scores the active season with the typed numbers next to the saved ones (set value, top scores, bonuses, top 5, rank changes) before anything is stored; edits are flagged, out-of-range values show what they will clamp to, and leaving with unsaved edits warns (`beforeunload`). **Twitch & viewers**: the copyable extension checklist from `lib/twitch-setup.ts` (panel / mobile / video URLs, privacy + terms, fetch allowlist, OAuth redirect) plus secret chips. **Environment**: `lib/env-health.ts` (`checkEnv`, pure) lists which variables are set (never their values), required / recommended / optional and what each unlocks, flagging short secrets. Add a new variable to `ENV_SPECS`. Saves redirect back with `&saved=<key>` and show a banner; add new settings to the matching tab and a `SAVED_MESSAGES` entry. Every settings action calls `requireAdmin()`. `scripts/check-settings.mts` (pure) covers clamping, the preview, the environment list and the setup list.

## Users admin: tags, moderation, restore points, audit
- **Tags / flags** live on `UserProfile` (`tags`, `flags: { noTrading, hideFromBoard, reason, at }`); helpers in `lib/user-admin.ts`. `hideFromBoard` also maintains the KV set `users:hidden` (`getHiddenUsers()`), which the leaderboard, `ownersByCard` and `getRecentPulls` filter on; their own collection page still works. `noTrading` is enforced in the trade engine (`createInLock`, `acceptTrade`): a blocked viewer can't offer/accept and can't be offered to; cancelling still works.
- **Restore points**: `takeUserSnapshot` runs before reset season / reset all / delete / merge / restore (keys `user:<u>:snap:<id>`, 14-day TTL, newest 6). `restoreUserSnapshot` replaces each saved season collection and takes a point of what it overwrites. **Merge** (`mergeUsers`) moves all cards into another account, unions tags, deletes the old profile; refused while either has open trades.
- **Audit trail** (`lib/audit.ts`): `recordAudit` on every admin action on a viewer (`audit:user:<u>` 100, `audit:all` 500); best-effort. Add a call to any new admin user action. All user actions call `requireAdmin()` themselves (`app/admin/users-actions.ts`, `actions.ts`).
- `lib/stats.ts` keeps `stats:last` (last counted action per viewer) for "last seen". `scripts/check-users.mts` (mock KV) covers tags, restrictions, restore, merge.

## Admin user detail page (`/admin/users/[username]`)
- Fetches profile + all seasons + collections in parallel
- Shows per-season card grid: owned cards with image + rarity border, unowned as `?`
- ×N badge on cards pulled more than once
- Hover × button on owned cards to remove one instance (calls `removeUserCard` server action)
- Grant card select form per season

## Card art
Card images are animated WebP in `public/assets/cards/` (600px wide, ~1–4MB each) with a static first-frame thumbnail of each in `public/assets/cards/thumb/` (~15KB). The original 800px GIFs were 20MB+ each and were removed. `getPackCards` rewrites legacy stored URLs (`/assets/GIF/X.gif` → `/assets/cards/X.webp`) on read, so old KV data keeps working.

- **Grids use `CardTile`** (`app/components/CardTile.tsx`, client component): shows the thumbnail and loads the animated file only while hovered. Used on `/collection/[username]` and the admin user detail page. `cardThumbUrl()` in `lib/card-art.ts` maps an image URL to its thumbnail (returns the URL unchanged when none exists, e.g. external images).
- **The Twitch panel** (vanilla JS) does the same: `/api/twitch/season` returns a `thumbUrl` per card (from `cardThumbUrl()`), and `addCardImage()` in `panel.js` shows that static thumbnail, mounting the animated `imageUrl` as an overlay only while the card is hovered (skipped for `prefers-reduced-motion`). Never put full animated images directly in the panel grid, 25 of them at once makes the iframe crawl.
- **Processing** lives in `lib/card-image.ts` (sharp), shared by the CLI and uploads. To convert GIFs locally: `node scripts/optimize-cards.mjs <inDir> <outDir>` (Node ≥ 22.18). With no GIFs present it just regenerates thumbnails.
- **Admin GIF uploads** (`ImageUploadField`): the browser uploads the raw GIF straight to Blob via `/api/upload/token` (Vercel functions cap request bodies at 4.5MB), then `/api/upload/optimize` fetches it, stores `cards/<uuid>.webp` + `cards/<uuid>.thumb.webp`, and deletes the original. The `<uuid>.thumb.webp` naming is what lets `cardThumbUrl()` derive the thumbnail from the stored URL, keep `optimizedCardPaths()` and `cardThumbUrl()` in sync. Non-GIF uploads still go through `/api/upload` unchanged. Needs `BLOB_READ_WRITE_TOKEN`; the optimize route sets `maxDuration = 60`.

## User avatars
Admin pages (dashboard Top Collectors, users list, user detail) show each user's Twitch profile picture. `getAvatars(usernames)` in `lib/avatars.ts` batches Helix `users?login=…` lookups (`fetchTwitchAvatars` in `lib/twitch-helix.ts`, up to 100 per request) and caches results in the KV hash `twitch:avatars` (login → `{ url, at }`; 7 days for found, 1 day for "no avatar"). It never throws, without `TWITCH_CLIENT_ID`/`TWITCH_CLIENT_SECRET`, or if Twitch is down, users just get the initial-letter fallback, and a failed lookup is not cached. Logins that can't be Twitch names (e.g. `mrbeast#`) are skipped. Use `sizeTwitchAvatar(url, px)` to request the right size and the `Avatar` client component (`app/components/Avatar.tsx`) to render it; it falls back to the initial if the image fails to load.

## Live activity (`/admin/activity`)
An event log of everything that happens: widget pulls (new vs duplicate, copies, unique owned), card grants/removals (admin + webhook), resets/deletes, incoming webhook triggers, and "collection shown" notices. `recordActivity()` in `lib/activity.ts` appends to the KV list `activity:log` (newest first, capped at 500) and bumps the counter `activity:seq`; it never throws and must be `await`ed in serverless routes. Call it from any new code path that changes a collection.

The page is a server-rendered snapshot plus a client component (`ActivityFeed`) that polls `GET /api/admin/activity?after=<seq>` every 3s while the tab is visible (pausable). With nothing new that is one KV GET; new events come back with avatars. Polling rather than SSE because serverless functions can't hold long connections cheaply. **The page** (`ActivityFeed.tsx`, helpers in the client-safe `lib/activity-view.ts`): a summary strip (pulls per minute / hour, viewers, rare pulls, a 30-minute bar chart, and a "busy right now" banner when the last 2 minutes are at least 3× the usual, all computed from the loaded events), a search box (`plainText()` of each event) and a click-a-viewer filter, multi-select category chips plus More filters (rarity, version, pack, new-only), **Group bursts** (`groupEvents`: pulls by one viewer within 8s, or admin gifts to one viewer, collapse into one expandable row), **Notable moments** (`notableReason`: Shiny / Full Art / 5★ pulls, completed collections, upgrades to Full Art / Shiny, admin trade cancels and mass resets) highlighted and optionally pinned, a compact view, a sound chime (WebAudio, no asset) and desktop notifications for notable events that arrive while the page is open, and CSV / JSON export of the filtered events. Clicking a row opens `EventDetail` (side panel: the full record plus Gift packs, Grant again, Remove a copy via the existing `quickAction` / `removeUserCard` actions, open the viewer). Filters, view and alert choices persist in `localStorage` `tcg_activity_prefs`. History is still the latest 500 events (export keeps what is shown); for longer history use the dashboard's time-series counters (`lib/stats.ts`). `pull` events come from the unauthenticated `/api/collection` POST (the widget's payload), so treat their contents as untrusted display text.

## Admin UX conventions
- **Page titles & tab bars**: every admin page exports `metadata = { title: '<Page> · Admin', robots: { index: false } }` (the root layout's template adds the site name, so browser tabs are distinguishable). Sideways-scrolling tab bars (`PageTabs`, the trade and profile tab bars) use `no-scrollbar overflow-x-auto overflow-y-hidden`: without `overflow-y-hidden` the `-mb-px` active border makes a 1px vertical overflow and a stray scrollbar appears. Never nest a link inside a link (React hydration error): make the row's main element a stretched link (`after:absolute after:inset-0`) and give inner links `relative z-10`.
- **Shared admin building blocks live in `app/admin/components/ui.tsx`**: `Tile` (headline number, optional icon / tone / link), `Panel` (titled card, optional `id` scroll target), `PageHeader` (title, subtitle, back link, actions), `Narrow` (centred max width for forms), `EmptyState`, `Chip`, and the `fieldClass` / `selectClass` strings. Use them instead of declaring another local `Tile` / `Panel` / `h1` block. Route-level states: `app/admin/loading.tsx` (skeleton), `app/admin/error.tsx` (a crashed page keeps the sidebar and offers Try again) and `app/admin/not-found.tsx`. Keyboard focus on links / buttons gets one yellow ring (`globals.css`).
- **Command palette and keyboard shortcuts** (`AdminKeyboard`, mounted once in `app/admin/layout.tsx`; the sidebar's Search button opens it): Ctrl/⌘+K searches pages, actions and (fetched from `GET /api/admin/palette` when it opens, sandbox-aware) packs, seasons and viewers; `g` then a letter goes to a page; `?` lists the shortcuts; `/` focuses a list's search box through the shared `useSlashFocus` hook (don't add another per-page handler). **The page list is `lib/admin-nav.ts`**. The sidebar, the palette and the shortcut letters all read it, so add a page there (with an unused `key` letter). Ranking is `lib/palette.ts`, the sequence logic `lib/shortcuts.ts`; both pure. `scripts/check-admin-shell.mts` verifies every nav / palette link is a real page, shortcut letters and ids are unique, the sequence timing and the ranking.
- **Long admin pages are tabbed with `PageTabs`** (`app/admin/components/PageTabs.tsx`): server-rendered links driven by `?tab=` (`pickTab()` falls back to the first tab), no client state. Used on the pack page (Cards / Odds & simulator / Overview / Settings), season page (Overview / Pack lineup / Settings / Wrap-up; Overview and Wrap-up only when published), user page (Profile / Collection / Trades / Grant / Admin), Trades (Overview / Offers & log / Controls & settings), sandbox detail (Setup / Simulate / Card values / Reset & delete) and Settings. Server actions that redirect back must include the right `tab` (see `back()` in `app/admin/sandbox/actions.ts`); deep links use `?tab=…` (e.g. pack health: `?tab=overview#health`). Top-level page `h1`s are `text-3xl font-bold text-white`.
- **Destructive actions use `ConfirmButton`** (`app/admin/components/ConfirmButton.tsx`): wrap the submit button of a `<form action={serverAction}>` and it opens a confirmation dialog first, then calls `form.requestSubmit()`. Never ship a bare delete/reset button. For a button outside its form, pass `formId`.
- **Tiny card icons use `cardThumbUrl()`**, never the animated `imageUrl` (a 28px icon should not download 2MB).
- **Assets page** (`lib/assets.ts`, `lib/asset-fix.ts`, `lib/asset-insights.ts`, `app/admin/assets/`, `app/admin/asset-actions.ts`): groups by purpose (card art / pack covers / sounds / unused / insights, tabs via `PageTabs` so `?tab=` and `?issues=1` deep-link), not file type. Flags `legacy-gif`, `missing`, `no-thumbnail`, `heavy`. Sizes come from the Blob `list()` for Blob files and same-origin HEAD requests for bundled `/assets/…` files. Every `LibraryAsset` has an `id` (`assetId()` of its `AssetKey` = kind + pack + card) and `sharedWith` (other places using the same file). **Views**: grid / compact / list (remembered in `localStorage` `tcg_assets_view`), search (`/` focuses it), sort, Needs attention, checkbox selection. **Detail panel** (`AssetDetail`, portal; ←/→ browse, Esc closes): big preview, dimensions (measured in the browser), where it's used, problems with hints, replace drop zone. **Fix** (`fixAsset` in `lib/asset-fix.ts`): GIF or oversized card art → `storeOptimizedCard` and repoint, missing thumbnail → regenerated; `missing` files and sounds are never auto-fixed. The UI calls `fixAssetAction(AssetKey)` once per file (sequential, with progress; the page sets `maxDuration = 60`) and the server re-reads the current URL itself, so a request can never name an arbitrary file. **Replace** (`replaceAsset`, `useReplace`): drop a file on a tile or the panel → browser upload (`uploadImageFile` / `uploadAudioFile`) → `replaceAssetAction`; URLs must be our Blob store or `/assets/…` with the right media type; the old file is left to appear under Unused. **Unused** = Blob files no card/pack references (a card's companion thumbnail counts as referenced; files under 10 minutes old are hidden in case they're mid-optimize); select rows or "older than 7/30/90 days" then delete. `deleteUnusedBlobs()` re-verifies on the server through `pickDeletable()`. It only deletes files that are in our store and unreferenced, so a stale page or crafted form can't delete live art; the delete action also calls `requireAdmin()`. **Insights** (`computeInsights`, pure): weight by type and pack, heaviest files, GIF savings estimate (`GIF_SAVINGS`, a rough 90%). `scripts/check-assets.mts` (mock KV) covers deletability, replace guards, fix guards, insights and the age filter. **Optimisers**: pack covers are shrunk on the server (`optimizeCover` in `lib/asset-fix.ts` via `optimizeCoverAction`: `toCover` in `lib/card-image.ts` re-encodes as WebP at 640 px wide, saved to Blob as `covers/<uuid>.webp`, the pack is repointed, the old file is deleted only if unreferenced; a cover that would not shrink by 10% is left alone, so it is safe on everything; bundled `/assets` covers are optimised into Blob too). Sounds are re-encoded **in the browser** (`lib/audio-encode.ts`: Web Audio decode, mono mix-down, MP3 at 64-160 kbps via `@breezystack/lamejs` (LGPL), loaded on demand; there is no audio encoder on the serverless side): the detail panel's `SoundOptimiser` compresses, plays the result next to the original and only replaces on "Use this version" (through the normal replace flow); "Optimise sounds" on the Sounds tab does the whole list with the chosen quality, one at a time, replacing a sound only when the new file is at least 15% smaller. `useOptimise` (in `app/admin/assets/`) drives both bulk runs and their progress; sounds keep their length (the encoder adds ~30 ms of padding) and are not trimmed or normalised, so overlay timing and volume are unchanged. Like Replace, the old files stay in storage and show under Unused.
- The users list has a client-side search (`UserSearch`, press `/`); rows opt in with a `data-search` attribute.

## Admin dashboard (widgets)
The dashboard is a 12-column grid of widgets the admin can add, remove, drag to rearrange and resize ("Customize dashboard"). **Registry and layout model**: `lib/dashboard.ts` (client-safe), `WIDGETS` (title, icon, description, default span, allowed spans), `DashboardLayout = { widgets: { type, span }[] }`, `sanitizeLayout()` (known types only, each at most once, spans snapped to the widget's allowed set), `DEFAULT_LAYOUT` and `SPAN_CLASS` (spelled out for Tailwind; everything stacks on phones, spans ≤ 6 pair up on tablets). **Storage**: one layout per staff member in KV `admin:dashboard:user:<login>` (read falls back to the shared `admin:dashboard`, the layout from before layouts were per person, then `DEFAULT_LAYOUT`; saving writes the person's own key; the emergency password login uses the shared key; `layoutKeyFor` / `loginForLayout`), team layouts (presets) shared in `admin:dashboard:presets` with who saved each, and the shared `admin:dashboard:notes` (a team scratchpad, the widget says so); all sandbox-namespaced like everything else; server actions in `app/admin/dashboard/actions.ts` re-check the admin cookie and re-sanitise. **Data**: `loadDashboardData(season, packs, needs)` in `lib/dashboard-data.ts` computes only what the widgets in the saved layout need (the leaderboard, activity log, trades and live status cost extra reads). **Rendering**: `renderWidget(type, data)` in `app/admin/dashboard/widgets.tsx` (server components, each wrapped in `Panel`); `DashboardGrid.tsx` (client) receives the rendered nodes and owns edit mode, HTML5 drag and drop (drag a widget, or one from the library, onto another: it lands before / after depending on which half you hover), ↑ ↓ / ◀ ▶ buttons as the keyboard and touch route, ✕ remove, Reset to default, Save / Cancel. A widget added in edit mode has no node yet, so it shows a placeholder until the layout is saved and the page refreshes. **Season and range**: `/admin?season=<id>&range=24h|7d|season` (the `DashboardControls` pickers) choose which published season the widgets describe (default: the active one) and the time range for the chart / pulse / viewers widgets (default: Season; the Viewers widget's per-day strip is always the last 7 days); non-active seasons use all of their published packs. **Built-in layouts** (`BUILTIN_PRESETS` in `lib/dashboard.ts`: Stream night, Season overview, Trading desk, Minimal; checked by `scripts/check-dashboard-presets.mts`; `applyBuiltinPresetAction` copies one into the person's own layout, with a second click to confirm) are listed above the team layouts. **Presets (shown as "Team layouts")**: named layouts in KV `admin:dashboard:presets` (max 12); `Customize` has a Presets bar (save the current draft under a name, apply, delete) and view mode shows the preset names as chips that switch the saved layout. **Resizing**: drag a widget's right edge in edit mode (the span snaps to the widths the widget allows; the card's `draggable` is switched off for the gesture). **Time series (`lib/stats.ts`)**: `recordActivity` also calls `recordStats`, which bumps hourly counters (`pull`, `newCard`, `newViewer`, `upgrade`, `trade`, `grant`, `v:reverse|full|shiny`) in the hash `stats:h:<collection>` (field `<UTC hour>|<metric>`) and adds the viewer to the day's set `stats:u:<collection>:<UTC day>`; `getSeries()` aggregates them into 24 hourly or up to 90 daily buckets and the widgets compare with the previous equal period. The activity log (500 events) cannot answer "per day this season", hence the counters; they only count from `stats:since:<collection>`, and the widgets say so. **Needs attention** (`computeAttention` in `lib/dashboard-data.ts`) is a list of plain checks (live but no overlay, queue backlog, no active packs, published packs in no season, Full Art without art, trading paused, expiring trades, drafts, missing Twitch credentials). Add a check there. **Overlay controls** flips the two "only when live" switches (`setLiveGateAction`). **To add a widget**: add its type to `WIDGET_TYPES` and `WIDGETS`, render it in `renderWidget`, and (if it needs extra data) compute that in `loadDashboardData` behind `needs.has(...)`.

## Admin responsiveness
Lists, dashboards, tables and workspaces use the full width of the page (no `max-w-*` caps on their wrappers; use responsive grids such as `xl:grid-cols-2` instead of narrowing them). **Forms and wizards are the exception: they are centred with a readable maximum width**. The pack wizard `max-w-5xl` (its Cards / Review steps are `max-w-7xl`), the season wizard `max-w-3xl`, the card editor `max-w-5xl`, the bulk card editor `max-w-6xl` (or wrap in `Narrow` from `app/admin/components/ui.tsx`). The admin works on phones: below `lg` the sidebar is a drawer opened from a top bar (closes on navigation, Esc or the backdrop) and `main` has smaller padding and top padding for the bar; on desktop the sidebar collapses to an icon rail. Wide tables scroll horizontally inside `main` (`overflow-auto`). The Assets and pack detail pages are the known examples. The Overlay Look tab is full width (`max-w-none`): a big sticky preview on the left and a 24rem scrollable properties panel on the right at `xl`, stacked (preview first) below that. A collapsed desktop sidebar **expands over the page on hover or keyboard focus** (`peek` in `AdminShell`; the sidebar is `lg:fixed` and `main` carries the margin, so nothing reflows).

## Discord activity feed
Settings live in KV `discord:settings` as `{ enabled, channels: DiscordChannel[] }` (max 8; edited in Settings → Webhooks). A channel is one webhook with its own On switch, category boxes and pull filters (min rarity, new-only); `enabled` is the master switch. The first version stored one webhook at the top level: `normalize()` in `lib/discord.ts` reads that as one channel called "Activity" with the same settings, so there is no migration. `recordActivity()` forwards every event via `after()` to `notifyDiscord()`, which builds the embed once (rarity colour, static card thumbnail, link to the viewer's collection) and POSTs it to every enabled channel whose `shouldSend(e, channel)` passes, in parallel with each failure isolated. Only real discord.com webhook URLs are accepted (the server POSTs to the stored URL; a plain `http://localhost` stand-in is accepted outside production for testing); `allowed_mentions` is empty and names are Markdown-escaped because event text comes from unauthenticated endpoints. Browser-safe types, presets and the "Deploys & code" steps live in `lib/discord-config.ts`, client components must import from there, not `lib/discord.ts`. The form (`DiscordConfig`) sends the whole settings object as one JSON field; `discordAction` validates it with `cleanDiscordInput`, and each channel's Test / Send-last-activity buttons use the channel as currently typed, so it can be verified before saving. `scripts/check-discord.mts` runs the whole thing against a local fake webhook endpoint. **Categories** per channel: pulls, cards (grants / removals), upgrades, trades, stream, resets, **admin**, **system** (a channel saved before upgrades and trades had boxes gets them ticked wherever `cards` was). Upgrade and pull embeds link to the print (`copyHrefFor`). **The admin log is the one place staff names appear in Discord** (the form says to keep that channel private): it gets every activity event with `e.staff` (built with `showStaff`, other channels get the nameless message) plus `notifyAdminLog()` from `recordAudit`, the staff change log, season activation / publishing, pack publishing, scoring changes and trading paused / resumed / closed (audit entries that have an activity twin, such as a grant or removal, are skipped so nothing posts twice). **System** notices come from `notifySystem()`: backup result and data-health crossing (`lib/system-notices.ts`, called by the nightly cron and the manual backup), sandbox created / deleted, the stream going live / offline (`lib/twitch-live.ts`, noticed when the cached status flips). Both are silent in a sandbox and post after the response. **Delivery log**: every send goes through `deliver(channel, body, kind)`, which keeps the last 20 results (time, kind, HTTP status, Discord's error text) in KV `discord:log:<channelId>`; the channel card shows a red dot when the last send failed and a "Recent sends" list. A channel whose last 20 sends all failed (a deleted webhook answers 404) is switched off (`offReason` on the channel, cleared when it is ticked On again), the admin log hears of it and the dashboard's Needs attention panel lists it (`autoDisabledChannels`).

**Stream recap** (category `recap`, off for existing channels): `lib/twitch-live.ts` stores `twitch:live:since` (from Twitch's `started_at`) whenever it sees the channel live. When it sees it offline, `finishStream()` reads that marker (none means the transition was missed: no recap), takes a 60s KV lock `twitch:recap:lock`, deletes the marker so the stream is never recapped twice, then builds the recap with the pure `buildStreamRecap(events, from, to)` in `lib/stream-recap.ts` from the activity log (capped at 500 events, so a very long stream is marked as minimums). A stream with no pulls posts nothing. It holds packs opened, different cards, collectors, new collectors (a viewer's first card), first-ever pulls (print 1 of a card), the rarest pull linked to its print, the top puller and trades completed; the biggest rank climb is left out because the log cannot replay leaderboards cheaply. The latest recap is kept in `stream:recap:latest` for the dashboard's **Last stream recap** widget and the channel card's **Send test recap** button (sample numbers when there is none). Silent in a sandbox. The recap is only noticed when someone causes a live lookup (site visit, dashboard), same as the live indicator. `scripts/check-stream-recap.mts` covers it.

**Weekly digest** (category `digest`, off for existing channels, preset "Weekly digest"): the weekly cron (`app/api/cron/weekly`) calls `digestOncePerWeek()` in `lib/weekly-digest-store.ts` right after the print of the week is picked. It takes `digest:week:<yyyy-Www>` (NX, 21 days; released if building fails so a retry can run), builds the digest with the pure `buildWeeklyDigest()` in `lib/weekly-digest.ts` and posts it with `postDigest()` (awaited, not `after()`). Numbers: the last 7 days of the season's `stats:h:` counters (pulls, `newViewer`, upgrades, trades); the top 3 and the movers come from `getSeasonLeaderboard`, which already leaves out hidden and private collectors, and from the snapshot `digest:ranks:<seasonId>` (`{ user: [rank, points] }`) that EVERY run saves, even a skipped week; the first run has none and says "Movers start next week". Most traded cards are counted from accepted trades in `trades:history` (400 kept: when it is full and its oldest trade is newer than the week start the heading says "at least"); most wanted is the biggest `watch:idx:<card>` set (`watcherCounts`, set sizes only). A week with no pulls and no trades is skipped (no post, no `digest:latest`). The last posted digest is kept in `digest:latest` and shown by the **Weekly digest** dashboard widget; a channel with the box ticked gets a **Send test digest** button (made-up numbers from `sampleDigest()`). Check: `scripts/check-weekly-digest.mts`.
- **Shared admin / mod UI rules found in review**: a client component that prints dates must use a fixed locale (`en-GB`), because the server (en-US on Vercel) and the browser otherwise print different text and hydration fails; a client component that shows relative times starts from the server's clock (`ActivityFeed` takes `serverNow`); a two-panel page grid uses `grid-cols-1 lg:grid-cols-2` so a wide child cannot widen the page; `ArmedButton` (`app/admin/components/`) is the "Sure?" second click for an action that is not a form submit (use `ConfirmButton` for forms).

- **Season settings are validated on the server** (`updateSeason` runs `validateSeason`, the same checks as the wizard, and redirects back to `?tab=settings&error=...`). A browser `required` is never the only check. `ConfirmButton` takes `tone="primary"` for a confirmation that is not destructive (activating a season). Form labels need `htmlFor` / `id` (`useId` in client components). Dates rendered on the server should be fixed-format and say UTC.

- **Pack and card forms are cleaned on the server** with `lib/pack-clean.ts` (`cleanPackInput` for packs, `cardProblems` for a card: name, stars 1-5, odds >= 0, a whole number below 1,000,000 unique within the pack). The wizard autosave, `updatePack`, `addCard` and `updateCard` all use it; a problem redirects back with `?error=` and a "Not saved" banner. A new pack or card field goes through it too. Deleting a card or pack that viewers hold is the data risk to warn about; archiving keeps the cards.
- **A card number that a viewer holds is fixed** (`heldCardNumbers` in `lib/card-held.ts`): the card editor shows it read-only and `updateCard` refuses to change it. New cards still get the next free number.
- **Risky bulk actions get a stronger confirmation**: `ConfirmButton typeToConfirm="..."` for what cannot be undone and hits everyone (Reset All), a summary dialog before bulk gifts, `ArmedButton` for inline removals. A server action that receives a collection name must check it is a season collection (`requireSeasonCollection`). Completion totals on admin lists use the leaderboard's set (published packs, by card number), never every attached pack.
- **Dates in client components print UTC**: `toLocaleString('en-GB', { ..., timeZone: 'UTC' })`. A client component is rendered on the server first, and the server is UTC while the visitor is not, so a date in the browser's own zone is a hydration mismatch. `scripts/check-locale.mts` enforces both the locale and the zone.
- **Anything the server calls out to is checked first**: outgoing webhook addresses go through `lib/webhook-clean.ts` (public http(s) only) when saved and again when sent; Discord addresses must be real discord.com webhooks. Secrets are compared in constant time.

**Still frame of animated cards** (`Card.stillUrl`, `Card.fullArtStillUrl`): the static image of an animated card is its first frame (`toThumb`), which is sometimes blank. The card editor and the wizard's card rows have **Choose still frame** (`app/admin/components/FramePicker.tsx`): a slider with a live preview plus eight suggested frames. `GET /api/admin/card-frames?url=<art>` (admin only; `isFrameSourceUrl` allows only `/assets/cards/<name>.webp` and `cards/<name>.webp` in this project's Blob store) returns `{ frames, delayMs }`, or with `n=<k>` frame k as a webp; `renderStillAction` (`app/admin/still-actions.ts`) cuts that frame at thumbnail size and stores it in Blob as `cards/<uuid>.still-<k>.webp` (a new name each time, so a CDN never serves an old still) and returns the URL. The URL rides in the card form (`stillUrl` / `fullArtStillUrl` hidden fields) or the draft row, so it is saved by Save Card / the wizard autosave (`updateCard`, `saveCards`); a new upload of the same image slot drops its still, and `updateCard` posts a "Card still frame chosen / reset" line to the admin log. **Showing it:** `cardStill(card, 'art' | 'fullArt')` and `stillFor(card, url)` in `lib/card-art.ts` (fall back to `cardThumbUrl`); `CardTile` / `AnimatedArt` take a `still` prop. Already used by the card dex, the profile collection grid and binder, Discord embeds, the overlay's `/api/seasons/active` thumbnails, home pulls, site search and the stats page; other places still call `cardThumbUrl()` directly and show the first frame (profile widgets, account, trade views, share images, admin lists): switch them to `stillFor` when the card is in scope. Asset cleanup counts stills as referenced (`collectReferenced`). Check: `scripts/check-card-still.mts`.
