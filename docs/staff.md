# Staff: admin and mod panels

> Read this when you touch staff roles, Twitch sign-in for the admin / mod panels, the mod panel or who-did-it attribution.

## Staff: admin and mod panels (Twitch login)
Staff sign in with **Log in with Twitch** (the same OAuth as viewers) and get a role from the staff list. **Roles** (`lib/staff-core.ts`, pure and edge-safe): `super` (the owner, hard-coded by Twitch ID in `SUPER_ADMINS` plus any IDs in `SUPER_ADMIN_TWITCH_IDS`; matched by ID, never by name; can't be removed or changed), `admin` (whole admin panel; can add / change / remove mods) and `mod` (the `/mod` panel only). Only the super admin can add or remove admins (`canManage`, `roleCan`). The staff list is the KV hash `staff:members` (login -> `StaffRecord`) with a capped log `staff:log`, stored with `prodKv` so it is the same inside a sandbox (`lib/staff.ts`: `addStaff` / `setStaffRole` / `removeStaff` / `touchStaffLogin`, all enforcing the rules and logging who did it). A record is bound to the account's Twitch ID the first time they sign in (or from their viewer profile when added) and then only that ID matches, so a renamed or re-claimed login can't inherit access.
- **Sign-in flow**: login page (`/login`) -> `/auth/twitch?returnTo=/admin` -> middleware sees a viewer session but no staff cookie -> `/auth/staff` (`app/auth/staff/route.ts`) looks the account up and issues the one-hour signed `tcg_staff` cookie (`lib/staff-token.ts`, Web Crypto HMAC with `SESSION_SECRET`, edge-safe) -> the panel. The same route silently renews the cookie hourly while the role stays valid, and turns a removed person away (`/login?error=not-staff`). `requireStaff` and `hasStaffCapability` also slide the cookie forward (re-issued with the live role when under 30 minutes are left, never past 12 hours after the first issue, `iat`), so an open activity feed keeps working; on a 401 the feed calls `/auth/staff?silent=1` (JSON, no redirects) and retries once, else shows "Sign in again". A fresh Twitch sign-in and website logout clear the staff cookie.
- **Enforcement (defence in depth)**: `middleware.ts` (matcher `/admin`, `/mod`) reads only the signed cookies and sends admins/super to either panel, mods to `/mod` only, strangers to `/login`. The authoritative check is `getStaff()` / `requireStaff(cap)` in `lib/staff-guard.ts`, which re-reads the live staff list: both panel layouts, every server action (`requireAdmin()` = `requireStaff('admin')`) and every `/api/admin/*` route (`isAuthenticated()` / `hasStaffCapability`) call it, so removing someone stops their changes at once and their page views within the hour. Mods may use only: `saveTagsAction`, `saveFlagsAction`, `cancelUserTradeAction` (`app/admin/users-actions.ts`), `cancelOneTradeAction`, `blockViewerTradingAction` (`app/admin/trade-actions.ts`), `updateFeedbackAction` (the feedback inbox) and read `/api/admin/activity`; those call `requireStaff('mod')`. **A new admin action must call `requireAdmin()`; give it `requireStaff('mod')` only if mods should be able to use it.**
- **Emergency password**: the old `ADMIN_PASSWORD` login still works as a break-glass super admin (shown as "(password)") unless `ADMIN_PASSWORD_LOGIN=off` (`isPasswordLoginEnabled` in `lib/admin-token.ts`; the middleware and `getStaff` both honour it).
- **Who did it (attribution)**: anything a staff member does to a viewer names them. `currentStaffLogin()` (`lib/staff-actor.ts`, never throws, null outside a panel request) feeds: the audit trail (`AuditEntry.by`, `recordAudit`), the activity log (`ActivityEvent.staff`, set in `recordActivity` only for events staff cause, `isStaffAction`: admin grants, removals, resets, deletes, admin-sent packs and admin cancels of offers, never a viewer's own pull / upgrade / trade even if that viewer is staff), cancelled trades (`Trade.staff`, set in `closeTrade` when `resolvedBy === 'admin'`; shown in the trade log detail) and a viewer's restrictions (`flags.by`). `plainText()` appends "(by <login>)" so the feed, search, CSV and the user timelines show it. The staff login is staff-only: the public profile Activity tab, Discord posts and viewer trade pages don't render it. A new admin action that records activity or audit gets this for free; one that stores its own record should save `await currentStaffLogin()` alongside it.
- **Panel link on the public site**: `SiteShell` calls `staffPanelLink(session)` (`lib/staff-guard.ts`: the signed-in viewer is looked up in the staff list, so staff see it without having opened a panel; a password-only admin is recognised from their cookie) and passes `staff` to `SiteNav`, which shows a purple **Admin panel** (admins and the super admin) or **Mod panel** (mods) button in the top bar, the account menu and the phone menu. Nobody else sees it. It is only a convenience link (`prefetch={false}`): clicking it goes through the middleware and `/auth/staff`, and the panels check access again themselves.
- **Staff page** (`/admin/staff`, nav key `f`; `app/admin/staff/` + `staff-actions.ts`): the fixed super admin(s), a table to add by Twitch name (autocompletes viewers), change role and remove, and the change log. The audit trail (`recordAudit`) now records who (`by`) made each change, shown on a viewer's audit panels.
- **Mod panel** (`/mod`, `app/mod/`): its own slim layout (`ModNav`), Overview, **Activity** (the admin `ActivityFeed` with `mod` = read-only: no gift / grant / remove, viewer links go to `/mod/users/...`), **Viewers** (search, restricted-only filter, a viewer page with restrictions, tags, trades with cancel and refund, recent activity and the staff audit; reuses `ModerationPanel` / `TagsEditor` / `TradesPanel` from `app/admin/users/[username]/UserPanels.tsx`) and **Trades** (the admin `TradeLog` with `mod` = no Extend; data from the shared `loadTradeAdminData()` in `lib/trade-admin-data.ts`, which the admin Trades page uses too). `/mod` is noindex and disallowed in robots. `scripts/check-staff.mts` (mock KV) covers roles, the ID binding, the signed cookie and the staff list rules.
- **Deletion requests are admin-only**: `deleteViewerForRequestAction` and `declineDeletionAction` call `requireAdmin()`, and `updateFeedbackAction` (the one mod action on the feedback inbox) calls `requireAdmin()` as well when the item is a deletion request.
- **Guard audit** (`scripts/check-staff-guards.mts`, part of `npm run check`): reads the source and fails if any exported admin server action does not call `requireAdmin()` / `requireStaff()` (directly or through a helper in its file), if a viewer action does not read the session, if an `/api/admin/*` route has no staff check, or if the set of actions / routes a mod may use differs from the documented list (`saveTagsAction`, `saveFlagsAction`, `cancelUserTradeAction`, `cancelOneTradeAction`, `blockViewerTradingAction`, `reverseTradeAction` (reverse a completed trade, ROADMAP 9.2), and the activity feed route). Server actions are public POST endpoints, so the page middleware is not a substitute. Adding a mod action means updating `DOCUMENTED_MOD_ACTIONS` in that check on purpose.
- **Back to the public site (mod panel)**: the top bar has a Public site link (`/`). The admin sidebar footer has the matching pair, **Public site** and **Mod view** (`/mod`), so an admin can move between the panels and the site (`app/admin/layout.tsx`; the mod bar links back to the admin panel for admins).
- **Staff wiki** (`/admin/wiki`, sidebar and dashboard link, shortcut `g` then `k`): topics rendered from `content/wiki/*.md`. It sits in the admin layout, so only an admin or the super admin can open it. Mods stay on `/mod` and have no link.

## Middleware matcher (closed alpha / beta)
The middleware matcher covers the whole site (`'/((?!_next/|assets/|brand/|icons/|twitch-panel/|.*\..*).*)'`), not just the panels. The order in `middleware()` matters: `/api/twitch/*` and `/api/version` return `extensionCors` first and never meet the access gate (Twitch panel freeze); `/admin` and `/mod` keep the staff gate above; everything else goes through `publicGate` (see "Closed alpha / beta" in docs/public-site.md). A valid staff cookie, or the emergency password cookie, passes the access gate in every mode. `scripts/check-access.mts` runs the matcher against every exempt and gated path, so change `isExemptPath` and that check together.

## Staff badges on public pages (ROADMAP 17.1)
`lib/staff-badge.ts`: pure `staffBadgeFor(login, staff, settings, superLogins)` (Streamer = the channel's own login (`CHANNEL_LOGIN`, staff or not), super admins show Admin, then the staff list's Admin / Mod; null when `UserSettings.hideStaffBadge`) and `getStaffBadges()` (React `cache`, one live read of `listStaff()` per request, login -> badge). Shown by `app/components/StaffBadge.tsx` in `ProfileHeader`, the leaderboard `Board` rows (shield only) and `/trade/<id>` next to each named user. A staff member hides their own in Settings ("Show my staff badge", shown only to staff). Never in the Twitch panel (freeze). Check: `scripts/check-staff.mts`.
