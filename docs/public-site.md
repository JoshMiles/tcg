# Public site

> Read this when you touch any public page: home, profile, collection, binder, card dex, leaderboard, account, settings, search, SEO, login or sessions.

## Public site (The Cheesy TCG)
The product is branded **The Cheesy TCG** (icon: `public/brand/icon.png`, also `app/icon.png` / `app/apple-icon.png` for the favicon; `BrandMark` renders it). Every public page sits inside `SiteShell` (`app/components/site/`: sticky `SiteNav` with a mobile menu, plus a footer with Privacy/Terms). Existing sections get it from a small `layout.tsx` (`collection`, `leaderboard`, `privacy`, `terms`); the new pages live in the `app/(site)/` route group, which shares the same shell. The admin area keeps its own layout and password login.
- Theme: the dark card-table look plus cheese accents, `.cheese-hero`, `.cheese-holes`, `.rind`, `.cheese-float` in `globals.css`.
- **Install the app**: `/install` (`InstallGuide`: steps for iPhone / Android / computer, opens on the visitor's device via `lib/install-detect.ts`), a phone-only dismissible hint on the home page (`InstallHint`), a footer link and an **install icon in the top bar** (`InstallButton` in `SiteNav`). The browser's one-shot `beforeinstallprompt` is caught early by `app/components/site/install-store.ts` (loaded with the page's scripts, before hydration) and shared: the icon opens the browser's own install dialog where there is one (Chrome, Edge, Android), otherwise links to `/install` (iPhone, iPad and Android browsers without a prompt); it is hidden once installed (standalone), inside another app's browser and on a computer whose browser can't install. The manifest, icons and offline page are in `app/manifest.ts`, `public/icons/` and `public/sw.js`.
- **FAQ upkeep**: when a public feature changes, update the FAQ in the same PR (it now has Your profile, serial numbers (`#serials`), trading matches / notices, privacy download and shortcuts), plus Privacy / Terms when data or rules change (serials, settings, score history are listed there). Bump `LEGAL_UPDATED` when you do.
- **Changelog**: `/changelog` ("What's new", indexed) lists the generated entries followed by the hand-written history in `lib/changelog.ts` (`{ date, title, items, tags?, pr? }`, written for players). Generated entries come from the `## Changelog` section of each merged PR: `scripts/build-changelog.mjs` runs before `next build`, reads merged PRs into main through the GitHub API (`GITHUB_CHANGELOG_TOKEN`, fine-grained, Pull requests: read; owner / repo from `VERCEL_GIT_REPO_OWNER` / `VERCEL_GIT_REPO_SLUG`, else the git remote) and writes the gitignored `.next-changelog.json`. It never fails a build: no token, no network or an API error writes `[]`. Parsing lives in `scripts/changelog-parse.mjs`: the section stops at the next heading, a `---` or a line starting with the robot emoji or "Generated with"; `Title:` on the first line overrides the PR title; an `Audience:` line (players, the default; staff, shown only on `/admin/changelog` and `/mod/changelog` through `StaffChangelog`; or both) splits `CHANGELOG` (public, never staff-only entries) from `STAFF_CHANGELOG`; a `Tags:` line (new / improved / fixed) or the same PR labels become the pills; only the bulleted list is published (prose around it is skipped, the first plain line after it ends it) and markdown is turned into plain text; `none` on the first line or no section leaves the PR out, and so does a PR whose title starts with ROADMAP; items are capped at 500 characters; commit messages are never read; any line or title naming a tool or author is dropped, and an entry with an em dash is left out with a warning. `npm run typecheck` and `npm run check` create an empty file first (`--ensure`) so a fresh clone works. PRs no longer edit `lib/changelog.ts`. The footer and mobile menu link (`ChangelogLink`) shows a dot while the newest entry is newer than the date the viewer last opened the page (`localStorage` key `tcg_changelog_seen`). `scripts/check-changelog.mts`; `check-words` also scans the file for em dashes and old print wording.

It reads the current season, so upgrade costs, version odds and the per-card value table are always live (`app/(site)/faq/page.tsx`); link to anchors like `/faq#points`. The home page and the leaderboard only carry short pointers to it. If the rules change (costs, odds, scoring), check the FAQ wording too.

- **Live indicator**: a red pulsing **LIVE** pill in the nav plus a banner on the home page (title, game, viewer count, Watch button) whenever the channel is live. `getLiveStatus()` (`lib/twitch-live.ts`) asks Helix `streams?user_login=` with the existing app token (no new env vars; needs `TWITCH_CLIENT_ID/SECRET`), cached in KV (`twitch:live`, reused for ~45s across instances, expires after 5 min) so traffic never maps 1:1 to Twitch calls. `SiteShell` reads it server-side and `LiveProvider` (`components/site/Live.tsx`) polls `GET /api/live` every 60s (and when the tab becomes visible), with `cache: 'no-store'`, because the route's `stale-while-revalidate` otherwise lets the browser show an old answer. Unconfigured/unreachable Twitch = no indicator, never an error. The channel login is `CHANNEL_LOGIN` in `lib/site.ts`.
- **Website login ("Log in with Twitch")**: OAuth authorization-code flow with **no scopes** (reads only the public profile: ID, login, display name, picture). `GET /auth/twitch` stores a random `state` (+ safe `returnTo`) in the short-lived `tcg_oauth` cookie and redirects to Twitch; `GET /auth/twitch/callback` checks the state, trades the code for a token (`lib/twitch-oauth.ts`), reads the profile, **revokes the token immediately (never stored)**, runs `ensureUserProfile` (the same record the Extension creates, so web and panel share one identity), and sets the `tcg_session` cookie. `POST /auth/logout` clears it. Failures land on `/auth/error?reason=…`.
- **Sessions (`lib/session.ts`)**: a signed cookie (HMAC-SHA256 with `SESSION_SECRET`, no database): `{ username, twitchId, displayName, exp }`, 30 days, httpOnly, SameSite=Lax, Secure in production. It is readable but not forgeable. `getSession()` in server components; state-changing endpoints also call `isSameOrigin()`. `SESSION_SECRET` is a random string you invent (NOT the Twitch client secret); changing it logs everyone out.

## Public top bar (`SiteNav`) and search
- **Search** (`SiteSearch`, mounted in `SiteShell`): press `/` or Ctrl/⌘+K (or the Search button; the phone menu has an entry) to find a collector, a card or a page. Pure logic in `lib/site-search.ts` (`cleanQuery`, `buildEntityItems`, `rankSearch` with a cap per kind; pages match only by name / word / keyword, never by scattered letters). Pages are matched in the browser; collectors and cards come from `GET /api/search?q=` (`lib/site-search-data.ts`, active season only, the collector list cached 30 s and the card list 60 s per server instance and sandbox). **Collectors an admin hid from public boards (`users:hidden`) are never returned.** Enter on a no-match opens `/collection/<typed>` directly. Cards link to `/cards?card=<number>`, which opens that card in the dex (`CardDex` `initialOpenId`). A new public page should be added to `PUBLIC_PAGES`.
- **Rank chip**: `SiteShell` looks the signed-in viewer up in the shared (20 s) board and passes `rank` to `SiteNav`; the chip shows `#N`, a ▲ / ▼ with the places gained or lost since they last opened the account menu (remembered in `localStorage` `tcg_rank_seen:<username>`, this browser only) and a tooltip with points. The chip is a nice-to-have: any failure just hides it.
- **Menus**: the account dropdown is a real menu (focus moves in, arrows / Home / End via `nextMenuIndex` in `lib/menu-nav.ts`, Esc returns focus to the button, Tab closes); the phone menu closes on Esc or a tap outside and returns focus. `scripts/check-site-search.mts` covers the search and menu logic.

## Public site foundations (SEO, sharing, errors, speed)
- **Titles**: the root layout's template adds ` · The Cheesy TCG`, so a page's `metadata.title` must NOT repeat the site name (`scripts/check-public-meta.mts` fails if one does). Every public page exports `metadata` / `generateMetadata` (the home page uses the default); dynamic ones: `/collection/[username]` ("alice's collection") and `/leaderboard/[seasonId]` (the season name). `/login` is the admin sign-in and is `noindex` via `app/login/layout.tsx`. Signed-in and utility pages (`/account`, `/trade`, `/trade/new`, `/auth/error`) are `noindex`.
- **Search lists** live in `lib/seo.ts`: `INDEXED_PATHS` (in the sitemap), `NOINDEX_PATHS`, `DISALLOWED_PATHS` (robots), and `buildSitemap()` (fixed pages + one leaderboard per published season). `app/sitemap.ts` / `app/robots.ts` / `app/manifest.ts` use them. **A new public page must be added to `INDEXED_PATHS` or `NOINDEX_PATHS`** or the check fails.
- **Share images** (next/og `ImageResponse`): `app/opengraph-image.tsx` (default) and `app/u/[username]/opengraph-image.tsx` (name, rank, points, progress for the active season). `lib/og.tsx` loads the brand icon from disk, falls back to fetching it, and degrades to no icon. In `ImageResponse` markup every `div` with more than one child needs `display: 'flex'` (interpolated text counts as several children, so use a template string).
- **Frames and states**: `app/not-found.tsx` (adds the site frame itself) vs `not-found.tsx` inside `(site)`, `collection` and `leaderboard` (no frame, because those layouts already provide it, otherwise the nav would appear twice); `NotFoundBody` is the shared content (with a find-a-collector box). `app/error.tsx` (no nav, since the nav may be what failed) and a `loading.tsx` skeleton (`SiteSkeleton`) per section. `SiteShell` has a "Skip to content" link and `<main id="main">`.
- **Leaderboard cache**: `getSeasonLeaderboardCached()` (`lib/leaderboard.ts`, built on the pure `createTtlCache` in `lib/ttl-cache.ts`) shares one board for ~20 s between visitors of the PUBLIC pages (home, stats, card dex via `getSeasonOverview`, the leaderboard page). It is per server instance, keyed by sandbox + season, shares in-flight work, never caches failures, and its result is read-only. Use `getSeasonLeaderboard` directly wherever a viewer has just changed their own cards (their collection, My Stats, upgrades, trades) and in the admin.
