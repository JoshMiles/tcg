# Hosting, environment, backups and data health

> Read this when you touch deployment, environment variables, the build stamp, nightly backups or data health.

## Environment variables
| Variable | Purpose |
|----------|---------|
| `ADMIN_SECRET` | No longer signs the emergency cookie. It used to be that cookie's HMAC key and the secret on `GET /api/admin/import-legacy`. Rotate it if that URL was ever requested, then remove it. A leaked value cannot mint a cookie |
| `ADMIN_COOKIE_SECRET` | Signs the emergency password cookie (16+ characters, not `ADMIN_SECRET` and not `SESSION_SECRET`). Without it the password login cannot start a session. Set it on Production, and a different value on Preview if the password is used there. Twitch staff sign-in does not need it. Password attempts are still limited to 10 wrong ones per address every 15 minutes |
| `ADMIN_PASSWORD` | Password checked by `/api/auth/login` (the emergency login) |
| `ADMIN_PASSWORD_LOGIN` | Optional. `off` switches the emergency password login off |
| `SUPER_ADMIN_TWITCH_IDS` | Optional. Extra super admins (comma-separated numeric Twitch IDs); joshmiles is hard-coded |
| `KV_URL`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`, `KV_REST_API_READ_ONLY_TOKEN` | Vercel KV credentials |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob credentials |
| `BACKUP_ENCRYPTION_KEY` | 16+ character password the nightly backups are encrypted with; without it no backup is written. Keep a copy: backups cannot be read without it |
| `CRON_SECRET` | 16+ character random string; Vercel sends it to `/api/cron/backup` and `/api/cron/weekly`, which refuse any other caller |
| `TWITCH_EXTENSION_SECRET` | Base64 Extension Secret for JWT verification |
| `TWITCH_CLIENT_ID` | Twitch OAuth app Client ID (for Helix API) |
| `TWITCH_CLIENT_SECRET` | Twitch OAuth app Client Secret (for Helix API and website login) |
| `SESSION_SECRET` | Random string (16+ chars, ideally 48+) used to sign website login cookies. Generate your own, e.g. `openssl rand -base64 48`; not a Twitch value. Website login is hidden/unavailable without it |
| `SITE_URL` | Optional. Public base URL (default `https://cheesytcg.app`); the OAuth redirect URI is built from it, so set it if the domain changes |
| `GITHUB_CHANGELOG_TOKEN` | Recommended. Fine-grained GitHub token for this repo only, Pull requests: read-only; add to Production and Preview. The build reads merged PRs with it to make the What's new page (`scripts/build-changelog.mjs`). Without it the generated part is empty and the build still succeeds |
| `RESEND_API_KEY`, `EMAIL_FROM`, `RESEND_WEBHOOK_SECRET` | Recommended. Email notifications through Resend (needs `SESSION_SECRET` too): the API key, the sender (default `The Cheesy TCG <alerts@cheesytcg.app>`, on a domain verified in Resend with SPF, DKIM and DMARC records) and the webhook signing secret (`whsec_...`) for the endpoint `<site>/api/webhooks/email` (events `email.bounced`, `email.complained`). Without the key the Email option is hidden. `RESEND_API_URL` is for local fakes only and ignored in production |
| `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_BOT_TOKEN` | Recommended. Discord direct message alerts (needs a Discord bot invited to the Cheesygidds server): OAuth client credentials (scope `identify`) and the bot token. Without them the Discord direct messages option is hidden |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Recommended. Web Push alerts: generate the pair with `npx web-push generate-vapid-keys`, subject is `mailto:` the legal contact address. Without them the alerts option is hidden |
| `LEGAL_OPERATOR_NAME`, `LEGAL_CONTACT_EMAIL`, `LEGAL_GOVERNING_LAW` | Optional. Name the operator, a privacy contact email, and governing law on `/privacy` and `/terms`; neutral wording is used when unset. **Set these before submitting the extension for review** |

## Build version
Every build is stamped so you can tell which deployment you are looking at. `next.config.ts` bakes `BUILD_VERSION` (from `package.json`), `BUILD_COMMIT`/`BRANCH`/`ENV`/`REPO` (from Vercel's `VERCEL_GIT_*` and `VERCEL_ENV`, falling back to `git` locally) and `BUILD_TIME` into the bundle; `lib/version.ts` (`getBuildInfo()`) reads them. It shows as `v1.1.0 · 75fdb70` in the admin sidebar (`BuildBadge`, links to the commit on GitHub, with a `DEV`/`PREVIEW` pill outside production), in a **Build** section on `/admin/settings`, and in the top-right corner of the Twitch panel (fetched from the public `GET /api/version`). The semver is manual, bump `version` in `package.json` for releases; the commit changes automatically every build.

## Backups (nightly)
The project's **first scheduled job**: Vercel Cron (`vercel.json`, 04:00 UTC) calls `GET /api/cron/backup`, which checks `Authorization: Bearer ${CRON_SECRET}` (closed when unset) and runs `runBackup()` (`lib/backup.ts`). It refuses outside production (`VERCEL_ENV`) and inside a sandbox. It SCANs the raw production keyspace, skips everything on the deny-list in `lib/backup-core.ts` (`DENY_PREFIXES`: `sbx:`, `sandbox:`, `stats:`, `twitch:`, `activity:`, locks, cooldowns, queues, `watch:idx:`, per-viewer restore points; **a new key is backed up by default**, add a prefix there only for something rebuildable), reads each key by type (string / hash / list / set, 25 at a time) and writes **one encrypted file** `backups/<YYYY-MM-DD>.json.gz.enc` to Blob (a second run the same day replaces it; the newest 14 are kept, anything not named like a backup is never deleted). **Encrypted on purpose**: the Blob version in use (0.27) only stores public files and a backup holds Twitch IDs and webhook secrets, so the file is AES-256-GCM with a key derived from `BACKUP_ENCRYPTION_KEY` (scrypt, fresh salt; format in `encryptBackup`) and no backup is written without that variable. Keep a copy of the key somewhere safe: without it a backup cannot be read. `scripts/restore-backup.mts <file>` decrypts and, by default, restores into a **sandbox namespace** (`--sandbox <id>`, registered so it opens in Admin → Sandbox); `--raw --i-mean-production` puts keys back where they were (replacing each key, not merging). Admin → Settings → Environment has a **Backups** panel (newest backup, size, red when older than 36 hours, **Back up now**, production only). Pure parts and the format are tested in `scripts/check-backup.mts`; the mock KV tracks key types and supports `type` / `rpush` for it.

**Weekly job** (`vercel.json`, Sundays 20:00 UTC): `GET /api/cron/weekly` (`app/api/cron/weekly/route.ts`), same `CRON_SECRET` check, does nothing outside production or in a sandbox. Each step runs once per ISO week and a failing step does not stop the next. Today's only step is the print of the week (`pickOncePerWeek`, docs/serials.md); ROADMAP 6.3's digest goes at the marked hook in the route. To re-run a week by hand delete `potw:week:<yyyy-Www>`, or use **Pick again now** on Admin -> Prints.

## Data health
`lib/data-health.ts` measures how big the stored data is, so a storage redesign (roadmap 3.2: per-viewer storage) is decided by numbers. A season's collection is ONE JSON value (`tcg_<name>`) read and rewritten whole under a lock on every pull, trade and upgrade; `trades:open` and `trades:history` are single values too. Pure: `jsonBytes`, `formatBytes`, `healthLevel` (ok below `BLOB_WARN_BYTES` = 512 KB, warn from there, high from `BLOB_HIGH_BYTES` = 2 MB), `summarizeCollection`, `sizeAttention`. Server: `loadDataHealth()` per published season (collection bytes, viewers, entries, largest holder; the serial ledger's `idx` / `ret` / `n` hash sizes and the per-viewer ledger hashes for up to 500 viewers; drafts skipped), trade blob sizes, closed offers still marked escrowed (`stuckEscrow`: a refund that failed partway, or a flag left set after the prints moved, see docs/trading.md; shown as a red alert with **Return prints**) and the activity log length. Shown as the **Data health** panel on Admin → Settings → Environment (`DataHealthPanel`) and as a dashboard **Needs attention** line (`data-size`) when the dashboard's season collection passes 512 KB (`computeAttention` gets `jsonBytes(collection)`, so it costs no extra read). The measurement writes nothing. Return prints is the one action on that panel. `scripts/check-data-health.mts` (mock KV) covers it.

## Hosting & deploys
- **Vercel** project `tcg` (team `joshmiles-projects`, Next.js, Node 24.x), connected to the GitHub repo `JoshMiles/tcg`. Pushing a branch builds a **Preview** deployment; merging to `main` deploys **Production** at `https://cheesytcg.app` (moved from `tcg-khaki.vercel.app`; on a domain change update `SITE_URL`, the Twitch OAuth redirect URL and the extension URLs / allowlist, and the overlay URL in OBS) (also aliased `tcg-git-main-joshmiles-projects.vercel.app`). That URL is hardcoded in the Twitch panel setup, the settings page and the overlay URL pasted into OBS. Don't rename the project/domain without updating them. **Vercel SSO protection is on for deployments**, so a Preview URL asks for a Vercel login: it works in your own browser but not as an OBS browser source or from the Twitch panel, test the overlay/panel locally or on production. `vercel.json` is just `{ "version": 2 }`; there is no `.vercel` link in the repo and nothing here needs the Vercel CLI.
- **Storage** is Vercel KV (Upstash Redis, Storage tab → one store feeding `KV_URL`, `REDIS_URL`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`, `KV_REST_API_READ_ONLY_TOKEN`) and Vercel Blob. Env vars live in Vercel → Project → Settings → Environment Variables and are **scoped per environment**. State when last checked (2026-10): the KV vars are on Production + Preview + Development; `ADMIN_SECRET`, `ADMIN_PASSWORD`, `TWITCH_CLIENT_ID/SECRET` and `TWITCH_EXTENSION_SECRET` are Production + Preview only (stored as sensitive); a Vercel Blob store was attached on 2026-10-10 (`BLOB_READ_WRITE_TOKEN`, `BLOB_STORE_ID`, `BLOB_WEBHOOK_PUBLIC_KEY`, Production + Preview only, no Development, so local dev has no Blob and the Assets page says "not connected" there; image uploads need a real deployment). Before that, uploads and the Assets Blob inventory reported "Blob storage isn't connected" because the variable didn't exist. The KV vars show Vercel's "Needs Attention" because the integration stores them as readable rather than sensitive; that's cosmetic. **Env var changes only apply to new deployments, redeploy after editing them.** Never paste secret values into chat, commits or docs.
- **Previews are walled off inside the production store** (see "Preview deployments" under Sandbox): a preview deployment reads and writes only its own `sbx:preview:*` namespace and starts empty; Admin → Settings → Environment has a Preview data panel to copy the live setup in or wipe it. It still holds the production KV credentials, so `lib/db.ts` (and the `check-kv-imports` guard) is what keeps it safe. The Blob store is shared: uploads on a preview are real files (they show under Unused).
- Build: `next build` (Node, Next 15). `next.config.ts` stamps the build version/commit and sets cache headers for card art. Tailwind is 4 (`@tailwindcss/postcss`, theme in `app/globals.css`) with daisyUI 5's `cheesy` theme. `@vercel/blob` is on 2.x (moved from 0.27 in October 2026, which also cleared the `undici` / `@fastify/busboy` advisories; the code needed no changes). Upload, optimise, replace and cleanup only run against a real Blob store, so after any further major bump test them on a Preview deployment first.
- Static files in `public/` (overlay, widget, Twitch panel, card art, sounds) are served as-is by Vercel, no build step. The overlay/widget are cached by OBS, after a deploy, right-click the browser source → **Refresh cache of current page**.
- **Twitch Extension** is configured at dev.twitch.tv (see "Twitch Extension Panel"); it loads the panel from the production URL, so panel changes only reach viewers after a production deploy, and Twitch's iframe can cache the old JS for a short while.

## GitHub and Vercel changes in Discord
No server code: GitHub posts these itself, and Vercel reports every deployment to GitHub as a deployment status, so one GitHub webhook covers both. The same steps show in Settings → Webhooks → "Deploys & code".
1. In Discord make a webhook for the channel (Channel settings → Integrations → Webhooks → New Webhook → Copy Webhook URL).
2. In the GitHub repository: Settings → Webhooks → Add webhook. Payload URL: the Discord webhook URL with `/github` added on the end. Content type: `application/json`.
3. Choose individual events: Pushes, Pull requests, Releases and **Deployment statuses**.
