# Live activity and the dashboard

> Read this when you touch the live activity feed or the widget dashboard.

## Live activity (`/admin/activity`)
An event log of everything that happens: widget pulls (new vs duplicate, copies, unique owned), card grants/removals (admin + webhook), resets/deletes, incoming webhook triggers, and "collection shown" notices. `recordActivity()` in `lib/activity.ts` appends to the KV list `activity:log` (newest first, capped at 500) and bumps the counter `activity:seq`; it never throws and must be `await`ed in serverless routes. Call it from any new code path that changes a collection.

The page is a server-rendered snapshot plus a client component (`ActivityFeed`) that polls `GET /api/admin/activity?after=<seq>` every 3s while the tab is visible (pausable; after 10 minutes with no mouse, key, scroll or touch input it stops by itself and shows an "Idle, resume" chip, and any input resumes it; with sound or desktop alerts on it never goes idle, since the tab is then an alarm). With nothing new that is one KV GET; new events come back with avatars. Polling rather than SSE because serverless functions can't hold long connections cheaply. **The page** (`ActivityFeed.tsx`, helpers in the client-safe `lib/activity-view.ts`): a summary strip (pulls per minute / hour, viewers, rare pulls, a 30-minute bar chart, and a "busy right now" banner when the last 2 minutes are at least 3× the usual, all computed from the loaded events), a search box (`plainText()` of each event) and a click-a-viewer filter, multi-select category chips plus More filters (rarity, version, pack, new-only), **Group bursts** (`groupEvents`: pulls by one viewer within 8s, or admin gifts to one viewer, collapse into one expandable row), **Notable moments** (`notableReason`: Full Art Holo / Full Art / 5★ pulls, completed collections, upgrades to Full Art / Shiny, admin trade cancels and mass resets) highlighted and optionally pinned, a compact view, a sound chime (WebAudio, no asset) and desktop notifications for notable events that arrive while the page is open, and CSV / JSON export of the filtered events. Clicking a row opens `EventDetail` (side panel: the full record plus Gift packs, Grant again, Remove a copy via the existing `quickAction` / `removeUserCard` actions, open the viewer). Filters, view and alert choices persist in `localStorage` `tcg_activity_prefs`. History is still the latest 500 events (export keeps what is shown); for longer history use the dashboard's time-series counters (`lib/stats.ts`). `pull` events come from the unauthenticated `/api/collection` POST (the widget's payload), so treat their contents as untrusted display text.

## Admin dashboard (widgets)
The dashboard is a 12-column grid of widgets the admin can add, remove, drag to rearrange and resize ("Customize dashboard"). **Registry and layout model**: `lib/dashboard.ts` (client-safe), `WIDGETS` (title, icon, description, default span, allowed spans), `DashboardLayout = { widgets: { type, span }[] }`, `sanitizeLayout()` (known types only, each at most once, spans snapped to the widget's allowed set), `DEFAULT_LAYOUT` and `SPAN_CLASS` (spelled out for Tailwind; everything stacks on phones, spans ≤ 6 pair up on tablets). **Storage**: one layout per staff member in KV `admin:dashboard:user:<login>` (read falls back to the shared `admin:dashboard`, the layout from before layouts were per person, then `DEFAULT_LAYOUT`; saving writes the person's own key; the emergency password login uses the shared key; `layoutKeyFor` / `loginForLayout`), team layouts (presets) shared in `admin:dashboard:presets` with who saved each, and the shared `admin:dashboard:notes` (a team scratchpad, the widget says so); all sandbox-namespaced like everything else; server actions in `app/admin/dashboard/actions.ts` re-check the admin cookie and re-sanitise. **Data**: `loadDashboardData(season, packs, needs)` in `lib/dashboard-data.ts` computes only what the widgets in the saved layout need (the leaderboard, activity log, trades and live status cost extra reads; **Top collectors** ranks the top eight by points from that same leaderboard load, so it matches the site's order and leaves out hidden players, and `bestPct` feeds the Overview's "% best"). **Read order**: the page reads the active season, the person's layout and the team layouts together (seasons are listed once per request: `listSeasons` is memoised), and `loadDashboardData` reads the collection, then every other widget input in one `Promise.all`. **Rendering**: `renderWidget(type, data)` in `app/admin/dashboard/widgets.tsx` (server components, each wrapped in `Panel`); `DashboardGrid.tsx` (client) receives the rendered nodes and owns edit mode, HTML5 drag and drop (drag a widget, or one from the library, onto another: it lands before / after depending on which half you hover), ↑ ↓ / ◀ ▶ buttons as the keyboard and touch route, ✕ remove, Reset to default, Save / Cancel. A widget added in edit mode has no node yet, so it shows a placeholder until the layout is saved and the page refreshes. **Season and range**: `/admin?season=<id>&range=24h|7d|season` (the `DashboardControls` pickers) choose which published season the widgets describe (default: the active one) and the time range for the chart / pulse / viewers widgets (default: Season; the Viewers widget's per-day strip is always the last 7 days); non-active seasons use all of their published packs. **Built-in layouts** (`BUILTIN_PRESETS` in `lib/dashboard.ts`: Stream night, Season overview, Trading desk, Minimal; checked by `scripts/check-dashboard-presets.mts`; `applyBuiltinPresetAction` copies one into the person's own layout, with a second click to confirm) are listed above the team layouts. **Presets (shown as "Team layouts")**: named layouts in KV `admin:dashboard:presets` (max 12); `Customize` has a Presets bar (save the current draft under a name, apply, delete) and view mode shows the preset names as chips that switch the saved layout. **Resizing**: drag a widget's right edge in edit mode (the span snaps to the widths the widget allows; the card's `draggable` is switched off for the gesture). **Time series (`lib/stats.ts`)**: `recordActivity` also calls `recordStats`, which bumps hourly counters (`pull`, `newCard`, `newViewer`, `upgrade`, `trade`, `grant`, `v:reverse|full|shiny`) in the hash `stats:h:<collection>` (field `<UTC hour>|<metric>`) and adds the viewer to the day's set `stats:u:<collection>:<UTC day>`; `getSeries()` aggregates them into 24 hourly or up to 90 daily buckets and the widgets compare with the previous equal period. The activity log (500 events) cannot answer "per day this season", hence the counters; they only count from `stats:since:<collection>`, and the widgets say so. **Needs attention** (`computeAttention` in `lib/dashboard-data.ts`) is a list of plain checks (live but no overlay, queue backlog, no active packs, published packs in no season, Full Art without art, trading paused, expiring trades, drafts, missing Twitch credentials). Add a check there. **Overlay controls** flips the two "only when live" switches (`setLiveGateAction`). **To add a widget**: add its type to `WIDGET_TYPES` and `WIDGETS`, render it in `renderWidget`, and (if it needs extra data) compute that in `loadDashboardData` behind `needs.has(...)`.
