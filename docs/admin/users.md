# Users admin

> Read this when you touch tags and moderation, restore points, the audit trail, the user detail page, avatars.

## Users admin: tags, moderation, restore points, audit
- **Tags / flags** live on `UserProfile` (`tags`, `flags: { noTrading, hideFromBoard, reason, at }`); helpers in `lib/user-admin.ts`. `hideFromBoard` also maintains the KV set `users:hidden:admin` (`getHiddenUsers()`; hiding or showing one viewer is a single `sadd` / `srem`, so two staff cannot lose each other's change; the older `users:hidden` JSON array is still read and is folded into the set the first time anyone is hidden or shown), which the leaderboard, `ownersByCard` and `getRecentPulls` filter on; their own collection page still works. `noTrading` is enforced in the trade engine (`createInLock`, `acceptTrade`): a blocked viewer can't offer/accept and can't be offered to; cancelling still works.
- **Staff edits run safely in parallel and refuse unknown viewers**: `saveTags` / `saveFlags` first call `knownViewer()` (a clean Twitch login with a profile or cards in any season; otherwise they return an error and create nothing), then change the profile through `patchUserProfile` (`lib/kv.ts`: read, change and save under a per-viewer lock; also used by `ensureUserProfile` and the bulk tag action), so a tag save, a restriction save and a sign-in backfill on one profile all land. `scripts/check-staff-edits.mts` covers both.
- **Restore points**: `takeUserSnapshot` runs before reset season / reset all / delete / merge / restore (keys `user:<u>:snap:<id>`, 14-day TTL, newest 6). When the season is numbered, each saved collection also stores `prints` (one copy id per entry). `restoreUserSnapshot` replaces each saved season collection and takes a point of what it overwrites. It is refused while that viewer is on an open offer (the same check as merge). With `prints`, the same prints are put back (retired ones are revived) and the restore is refused if a saved print is held by someone else or sits in an offer, so a second print is not minted. An older point with no ids revives prints this viewer had removed before any new ones are minted. **Merge** (`mergeUsers`) moves all cards into another account, unions tags, deletes the old profile; refused while either has open trades.
- **Move aside** (`moveAside` in `lib/account-move.ts`, button in the user page's Tools panel): re-keys a viewer's whole account to `<login>~<n>` so the login is free for whoever really owns it. Journalled and resumable (`acct:moves`; Data health lists unfinished moves with **Finish move**, and finished ones from `acct:aside`). A restore point is taken first, open trades are cancelled and refunded, the moved account is hidden from rankings, a staff record with no Twitch ID is pinned to the profile's ID, and the tester record and opaque links are dropped. Refused for a `~` login, a login with no account, or when the target already holds one. `scripts/check-account-move.mts` injects a failure after each step and resumes.
- **Audit trail** (`lib/audit.ts`): `recordAudit` on every admin action on a viewer (`audit:user:<u>` 100, `audit:all` 500); best-effort. Add a call to any new admin user action. All user actions call `requireAdmin()` themselves (`app/admin/users-actions.ts`, `actions.ts`).
- `lib/stats.ts` keeps `stats:last` (last counted action per viewer) for "last seen". `scripts/check-users.mts` (mock KV) covers tags, restrictions, restore, merge.

## Admin user detail page (`/admin/users/[username]`)
- Fetches profile + all seasons + collections in parallel
- Shows per-season card grid: owned cards with image + rarity border, unowned as `?`
- ×N badge on cards pulled more than once
- Hover × button on owned cards to remove one instance (calls `removeUserCard` server action)
- Grant card select form per season
- Danger zone: Reset All Seasons (wipes all collection entries) + Delete User (wipes collections + profile, redirects to `/admin/users`)
- 404 if no cards and no profile found

## User avatars
Admin pages (dashboard Top Collectors, users list, user detail) show each user's Twitch profile picture. `getAvatars(usernames)` in `lib/avatars.ts` batches Helix `users?login=…` lookups (`fetchTwitchAvatars` in `lib/twitch-helix.ts`, up to 100 per request) and caches results in the KV hash `twitch:avatars` (login → `{ url, at }`; 7 days for found, 1 day for "no avatar"). It never throws, without `TWITCH_CLIENT_ID`/`TWITCH_CLIENT_SECRET`, or if Twitch is down, users just get the initial-letter fallback, and a failed lookup is not cached. Logins that can't be Twitch names (e.g. `mrbeast#`) are skipped. Use `sizeTwitchAvatar(url, px)` to request the right size and the `Avatar` client component (`app/components/Avatar.tsx`) to render it; it falls back to the initial if the image fails to load.
