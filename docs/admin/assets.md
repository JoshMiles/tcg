# Card art and the Assets page

> Read this when you touch card image processing, GIF uploads, thumbnails, the Assets page.

## Card art
Card images are animated WebP in `public/assets/cards/` (600px wide, ~1–4MB each) with a static first-frame thumbnail of each in `public/assets/cards/thumb/` (~15KB). `getPackCards` rewrites legacy stored URLs (`/assets/GIF/X.gif` → `/assets/cards/X.webp`) on read, so old KV data keeps working.

- **Grids use `CardTile`** (`app/components/CardTile.tsx`, client component): shows the thumbnail and loads the animated file only while hovered. Used on `/collection/[username]` and the admin user detail page. `cardThumbUrl()` in `lib/card-art.ts` maps an image URL to its thumbnail (returns the URL unchanged when none exists, e.g. external images).
- **The Twitch panel** (vanilla JS) does the same: `/api/twitch/season` returns a `thumbUrl` per card (from `cardThumbUrl()`), and `addCardImage()` in `panel.js` shows that static thumbnail, mounting the animated `imageUrl` as an overlay only while the card is hovered (skipped for `prefers-reduced-motion`). Never put full animated images directly in the panel grid, 25 of them at once makes the iframe crawl.
- **Processing** lives in `lib/card-image.ts` (sharp), shared by the CLI and uploads. To convert GIFs locally: `node scripts/optimize-cards.mjs <inDir> <outDir>` (Node ≥ 22.18). With no GIFs present it just regenerates thumbnails.
- **Admin GIF uploads** (`ImageUploadField`): the browser uploads the raw GIF straight to Blob via `/api/upload/token` (Vercel functions cap request bodies at 4.5MB), then `/api/upload/optimize` fetches it, stores `cards/<uuid>.webp` + `cards/<uuid>.thumb.webp`, and deletes the original. The `<uuid>.thumb.webp` naming is what lets `cardThumbUrl()` derive the thumbnail from the stored URL, keep `optimizedCardPaths()` and `cardThumbUrl()` in sync. Non-GIF uploads still go through `/api/upload` unchanged. Needs `BLOB_READ_WRITE_TOKEN`; the optimize route sets `maxDuration = 60`.

## Assets page

- **Assets page** (`lib/assets.ts`, `lib/asset-fix.ts`, `lib/asset-insights.ts`, `app/admin/assets/`, `app/admin/asset-actions.ts`): groups by purpose (card art / pack covers / sounds / unused / insights, tabs via `PageTabs` so `?tab=` and `?issues=1` deep-link), not file type. Flags `legacy-gif`, `missing`, `no-thumbnail`, `heavy`. Sizes come from the Blob `list()` for Blob files and same-origin HEAD requests for bundled `/assets/…` files. Every `LibraryAsset` has an `id` (`assetId()` of its `AssetKey` = kind + pack + card) and `sharedWith` (other places using the same file). **Views**: grid / compact / list (remembered in `localStorage` `tcg_assets_view`), search (`/` focuses it), sort, Needs attention, checkbox selection. **Detail panel** (`AssetDetail`, portal; ←/→ browse, Esc closes): big preview, dimensions (measured in the browser), where it's used, problems with hints, replace drop zone. **Fix** (`fixAsset` in `lib/asset-fix.ts`): GIF or oversized card art → `storeOptimizedCard` and repoint, missing thumbnail → regenerated; `missing` files and sounds are never auto-fixed. The UI calls `fixAssetAction(AssetKey)` once per file (sequential, with progress; the page sets `maxDuration = 60`) and the server re-reads the current URL itself, so a request can never name an arbitrary file. **Replace** (`replaceAsset`, `useReplace`): drop a file on a tile or the panel → browser upload (`uploadImageFile` / `uploadAudioFile`) → `replaceAssetAction`; URLs must be our Blob store or `/assets/…` with the right media type; the old file is left to appear under Unused. **Unused** = Blob files no card/pack references (a card's companion thumbnail counts as referenced; files under 10 minutes old are hidden in case they're mid-optimize); select rows or "older than 7/30/90 days" then delete. `deleteUnusedBlobs()` re-verifies on the server through `pickDeletable()`. It only deletes files that are in our store and unreferenced, so a stale page or crafted form can't delete live art; the delete action also calls `requireAdmin()`. **Insights** (`computeInsights`, pure): weight by type and pack, heaviest files, GIF savings estimate (`GIF_SAVINGS`, a rough 90%). `scripts/check-assets.mts` (mock KV) covers deletability, replace guards, fix guards, insights and the age filter. **Optimisers**: pack covers are shrunk on the server (`optimizeCover` in `lib/asset-fix.ts` via `optimizeCoverAction`: `toCover` in `lib/card-image.ts` re-encodes as WebP at 640 px wide, saved to Blob as `covers/<uuid>.webp`, the pack is repointed, the old file is deleted only if unreferenced; a cover that would not shrink by 10% is left alone, so it is safe on everything; bundled `/assets` covers are optimised into Blob too). Sounds are re-encoded **in the browser** (`lib/audio-encode.ts`: Web Audio decode, mono mix-down, MP3 at 64-160 kbps via `@breezystack/lamejs` (LGPL), loaded on demand; there is no audio encoder on the serverless side): the detail panel's `SoundOptimiser` compresses, plays the result next to the original and only replaces on "Use this version" (through the normal replace flow); "Optimise sounds" on the Sounds tab does the whole list with the chosen quality, one at a time, replacing a sound only when the new file is at least 15% smaller. `useOptimise` (in `app/admin/assets/`) drives both bulk runs and their progress; sounds keep their length (the encoder adds ~30 ms of padding) and are not trimmed or normalised, so overlay timing and volume are unchanged. Like Replace, the old files stay in storage and show under Unused.
