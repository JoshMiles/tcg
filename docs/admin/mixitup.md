# Mix It Up

> Read this when you touch paid pulls, webhook grants or Mix It Up chat commands.

## Mix It Up paid pulls (Mix It Up page)
Viewers can pay a currency (Brie Bucks) for a pack. Settings live in KV `mixitup:settings` (`lib/mixitup-core.ts`, pure; `lib/mixitup.ts`, KV and calls; page `app/admin/mixitup/` (tabs Paid pulls, Log; Commands), form in `MixItUpConfig.tsx`, actions in `mixitup-actions.ts`). Off by default; while off nothing below happens. Design and decisions: ROADMAP Track 12.
- **Flow**: `POST /api/webhooks/pull` reserves the pull (`reservePaidPull`: viewer's pulls this stream, then a `balance` request to Mix It Up, counting pulls already in flight) and queues it with `paid: true`. The overlay sends the event id back as the pull's ticket; `POST /api/collection` claims the ticket and then the payment (once each; a reused payment = 409, nothing saved), adds the print, sends a `deduct` request with the custom message and, if Mix It Up does not confirm, **revokes** the print (`revokePrint`: removed and retired in the ledger, note "payment failed") and tells the System Discord channel. Refusals queue nothing and answer `{ ok: true, ignored: true, reason, message }` (`insufficient_balance | limit_reached | mixitup_unavailable | bad_balance`) so the Mix It Up command can post `message` to chat.
- **Mix It Up answers in the HTTP reply** (a Webhook Response action). Balance: JSON with a number at the balance field. Deduct: any 2xx counts unless the body sets `ok`, `success` or `applied` to false.
- **Limit per stream**: Paid pulls has a number for regular, subscriber, VIP, moderator and broadcaster (all 0, no limit, until staff change them). The old single `limit` is the fallback when a role has no number, so a save from before role limits keeps working. The pull webhook may send `role` (`regular | subscriber | vip | moderator | broadcaster`); missing or unknown counts as regular, and `CHANNEL_LOGIN` is always the broadcaster. The site does not ask Twitch which role someone is. A gifted sub earns a pack and does not change a limit. A viewer's own limit (`user:<name>:pulllimit`, user page → Admin tab → Pull limit) replaces the role, and their temporary bonuses still add (ROADMAP 12.4). A base of 0 stays unlimited. **This stream, everyone:** Set / Clear on the same tab stores `{ amount, streamKey, by, at }` at `pulls:stream-buff`. It adds for every viewer only while `currentStreamKey()` still matches, and amount 0 deletes it. Counter `mixitup:cnt:<stream>:<viewer>` where the stream is the live Twitch stream's start (`getLiveStatus`), else the UTC day. Raised on reserve, lowered when a reservation fails or a pull is revoked. In-flight pulls: `mixitup:pending:<viewer>`; reservation `mixitup:pay:<id>` (1 h).
- Gifts from the dashboard, the extension and sandboxes never charge. Addresses go through `checkWebhookUrl` (public http(s) only); the last 20 requests are in KV `mixitup:log` and shown on the Log tab. `scripts/check-mixitup.mts` covers it with a fake Mix It Up. **Copy setup** (`paidPullSetup` in `lib/mixitup-setup.ts`) shows the balance and deduct bodies from the saved settings, the addresses, which action should answer `{ "balance": n }` (the saved balance field), and which action takes the currency. An empty deduct address is the balance address, told apart by `action`.
- **Add address** (`addUrl`, optional): the Mix It Up command that gives currency, used only by the `currency-grant` buff (Buff Editor). `grantCurrency` in `lib/mixitup.ts` sends `{ action: 'add', secret, username, amount, currency }` and, like a deduct, counts a 2xx unless the body sets `ok`, `success` or `applied` to false; it is logged as `add`. **Chat viewers address** (`viewersUrl`, optional): answers `{ users: string[] }` (or a bare array); `fetchChatViewers` sends `{ action: 'viewers', secret, currency }`, lowercases, drops @, dedupes and caps at 5000. Community `score-bonus` and `currency-grant` buffs go to those viewers (players with no cards included, who have no leaderboard row until they pull) and fail with a clear error when Mix It Up is off, the address is empty, or the call fails. A `currency-grant` writes a record `buffgrant:<id>` first (user to pending/paid/failed), pays one viewer at a time saving after each, and never pays a viewer marked paid; unpaid grants are listed in `buffgrants:open` and shown on the Buff Editor with **Retry unpaid** (`runGrant`, `retryGrantAction`). The trigger (card) is spent once; a partial result tells the player some are unpaid. The buff refuses to apply (and the Buff Editor warns) while Mix It Up is off or `addUrl` is empty; sandboxes never call it.
- `/api/collection` is locked down by server-rolled pulls (docs/overlay.md, ROADMAP 13.1).

## Webhook grants look like pulls
A card granted by the grant-card webhook (a Mix It Up reward) is recorded as `grant` with `source: 'webhook'` plus the facts of a pull (name, stars, pack, new or not, copies, collected, edition). It counts as a **pull** in the Live Activity categories and the Discord Pulls category (with the star and new-only filters), reads "X pulled Y (granted by webhook)" in the live feed and on the dashboard's Recent activity, and posts the same embed as a pull with a "Granted by webhook" line (`pullEmbed` in `lib/discord.ts`). The Live Activity numbers, the stream recap (`asPullEvent` in `lib/activity-view.ts`; there it is listed as a reward rather than a pack opened) and the stats counters behind the weekly digest and the dashboard charts (`recordStats`, from the day this shipped) count it as a pull too. Admin grants are unchanged (Grants & removals, the Cards Discord category, the `grant` counter). Events recorded before this change lack the extra facts and still post, with the card's stars looked up.

## Mix It Up chat commands (Mix It Up page, Commands tab)
ROADMAP 19.2. One incoming webhook, `POST /api/webhooks/command` (`{ secret, command, username, args? }`, the incoming secret), answers every chat command: `{ ok, message, vars }` plus each variable at the top level for Mix It Up's "JSON to special identifiers". A refusal is `{ ok: false, message }` with the command's own error text; an unknown or switched-off command is `{ ok: false, message: '' }` (silent). `/api/webhooks/show-card` still works unchanged.
- **Pure core** `lib/commands-core.ts`: the `ChatCommand` shape, the fixed action registry `COMMAND_ACTIONS` (each action's variables, sample values and error kinds: `showoff`, `card-stats`, `my-stats`, `collection`, `leaderboard`, `pulls-left`, `text`), `matchCommand` (name or alias, without the `!`), `interpolate` (unknown placeholders dropped), `tidyReply` (no Markdown marks, 400 characters), `cleanCommands` (max 30, unique names). **KV** `lib/commands.ts`: commands in `mixitup:commands` (the defaults `!showoff` and `!stats` are seeded on first read), run counts in `mixitup:cmdstats`, the last 20 runs in `mixitup:cmdlog` (shown on the Log tab, never posted to Discord), cooldowns `cmd:cd:<id>` and `cmd:ucd:<id>:<viewer>` with a TTL. `runCommand` is used by the webhook and by Try it.
- **Dry run**: Try it (the builder) runs the editor's draft with `dry`: no overlay event, no cooldown spent, no log line. `showoff` calls `prepareShowOff(user, args, { dry })`. A sandbox never queues an overlay event either.
- **Privacy**: hidden and private collectors (`getHiddenUsers`) show as "a private collector" in `topHolder` / `firstPulledBy`, are left out of `collectors`, and `my-stats` for them answers "This collector keeps their stats private" unless they ask about themselves.
- **FAQ**: the "Chat commands" section lists the enabled commands from `getCommands()`, then a fixed `!pack` line (it asks the stream to open a pack, and it is set up in Mix It Up rather than the command builder). `scripts/check-commands.mts` covers the builder. **Copy setup** (`commandSetups` in `lib/mixitup-setup.ts`) lists every switched-on command: the `!` name, `POST /api/webhooks/command`, the JSON body (the real incoming secret, `$username`, `$allargs`) and the `message` field for the Chat Message.

**Stream start / end** (`POST /api/webhooks/stream`, `{ secret, event: 'live' | 'offline' }`, the incoming secret): wire Mix It Up's Stream Start and Stream End events to it. `setLiveFromHint` (`lib/twitch-live.ts`) marks the stream live or offline at once (System notice, stream-start marker, recap on offline) and stores `twitch:live:hint`; for 5 minutes a Helix answer that disagrees is overridden, since Twitch's API lags a stream's start and end. The minute cron keeps checking Helix as a fallback.
