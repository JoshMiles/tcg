# Review batch P4: Rankings

Pages: `/leaderboard`, `/leaderboard/[seasonId]` (the board, its metric switch, search, Complete only, rows that open to a points breakdown, the "You are #N" jump, rank movement, an ended season's Final standings) and `/stats` (tiles, pulls by rarity, variants, pulls per day, the Every card table). Reviewed 2026-10-15 against the seeded review data (`docs/review.md`).

## Method

- Sweep (`node scripts/sweep-public.mjs --as=alice /leaderboard /leaderboard/season2 "/leaderboard/season2?how=1" /leaderboard/season1 /leaderboard/nope /stats "/stats?season=season1" "/stats?season=nope"`) at 390, 768 and 1280 px, signed in and out: clean.
- Hand pass with screenshots: the board at 1280 and 390 px, an ended season's board with its Final standings, the stats page at 1280 px, the rank-movement arrows.
- Interaction checks: the four ranking metrics, Complete only (4 of 311), search (match, no match), Show 25 more, a row's breakdown (cards + completion bonus + complete-set bonus adds up to the total), the "You are #6" jump (scrolls the row into view), rank movement against an hour-old stored baseline (arrows show and the baseline refreshes), the Every card table (show all, search by name and `#3`, no match, sorting by every heading), an ended season's stats.

## Findings

### Bugs (fixed)

- **Copy counts on the board had no thousands separator** ("3000 copies" next to "71,154 points"). Now grouped like every other number.
- **Stale doc**: `docs/variants-and-scoring.md` said the leaderboard opens with an expandable that `?how=1` opens. It is now a link to the FAQ's points section and `?how=1` does nothing; the doc says so.

### Improvements (for you to pick)

1. **An ended season's board can disagree with its own Final standings.** The Final standings box is the snapshot saved when the season was wrapped up; the board underneath is recomputed live. In the review data (and so, probably, in Season 1 in production) the champion in the box is `smoky_crab` with 2,119 points while the board's first place is `golden_raven` with 3,676, because serial numbers were assigned after the wrap-up and now add bonuses, and a later change to the scoring settings would move it too. Showing the saved standings as the board for an ended season (and saying "final") would keep the page consistent; the snapshot has the standings but may hold only the top of the board, so this needs a planning pass before building.
2. **An unknown season in the address (`/leaderboard/<unknown>`) answers HTTP 200** with the "not found" content (the same loading-skeleton trade-off P3 fixed for copy pages). The leaderboard is a heavy page where the skeleton matters, so it is a design call.
3. **Stats table headings only sort when the label itself is clicked**, not the rest of the heading cell; making the whole cell the button is a small touch-target improvement.

## Follow-up: the three improvements, done (2026-10-15)

1. **An ended season's board is its saved final standings.** The list under "Final standings" now comes from the snapshot, so it agrees with the champion and the awards (in the review data the board's first place is now `salty_raven` with 1,904 points, the same as the champion). The header says "Final" instead of "Ended" and the box says the list is the final ranking. Snapshots now also keep the bonus split and per-version counts (`SnapshotRow.completionBonus`, `setBonus`, `variants`, optional) so the breakdown and the RH / FA / SH chips still work; an older snapshot (for example Season 1 in production, taken before this) shows the bonuses as one "Bonuses" lump, no version chips and no Shinies ranking. Collectors who have since hidden themselves or gone private are filtered out of the list and the awards at read time. A season with no snapshot keeps the live board. This adds optional fields to the saved snapshot; nothing is migrated, and it is only written when a season is wrapped up.
2. **Real 404 for an unknown leaderboard season**, with the skeleton kept: `app/leaderboard/[seasonId]/layout.tsx` checks the season before the page's `loading.tsx` (moved next to the page), so `/leaderboard/<unknown>` answers 404 while a real board still shows its skeleton. The `/leaderboard` index redirects (307) and needs none.
3. **The whole stats heading cell sorts**, not just its label.
