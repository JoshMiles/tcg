## Bugs (fixed)

1. **Outgoing webhooks accepted any address and any field list.** The server POSTs to the stored address on every pull, but `saveOutgoingWebhook` stored whatever was typed: `http://localhost:3000/x`, `http://169.254.169.254/...`, `file:`, `javascript:` or a private-network address (the server would call it), and a bad paste into the hidden fields JSON threw an unhandled error (a 500). The sender did not check either. New pure `lib/webhook-clean.ts` (`checkWebhookUrl`, `cleanWebhookFields`, `isPrivateHost`): the address must be http(s) on a public host (no loopback, private, link-local or `.local` / `.internal` names, no credentials in the address), the fields are a list of at most 20 well-formed rows; a problem goes back to the tab with a red "Not saved: ..." banner (new on the settings page), an empty address saves as "not set up" and cannot be enabled; and `fireOutgoing` checks the address again, so an address stored earlier is also refused. Verified in the browser: a localhost address is refused with the reason, a public one is saved and persists. `scripts/check-webhook-clean.mts` covers the rules and that the form and the sender use them.
2. **The incoming webhook secret was compared with `===`**, which leaks how many leading characters matched; it is a constant-time comparison now.
