# Review batch A8: shell

Scope: the admin frame (sidebar as phone drawer, collapsible desktop rail with hover peek), the command palette and keyboard shortcuts, the loading / error / not-found states, and the phone layout of every admin page end to end. Walked by hand in a browser at phone (390), tablet (768) and desktop (1280) widths, with a full `scripts/sweep-admin.mjs` run over every admin and mod page at all three widths.

## Hand pass

- **Sidebar:** the drawer opens from the top bar, closes on Esc, the backdrop or choosing a page, and works at tablet width too; the desktop rail collapses, remembers its state across a reload and expands over the page on hover; the Overlay Editor still forces it collapsed without touching the saved choice.
- **Palette and shortcuts:** Ctrl/Cmd+K opens it with the input focused; pages, actions and viewers (fetched on open) are found, an empty search says "Nothing matches", Enter opens the result (from any page), Esc closes; `g` then a letter navigates, `?` lists the shortcuts, `/` focuses the page's search box, and typing in a text box never triggers a shortcut. The sidebar's Search button opens the palette on a phone.
- **States:** the loading skeleton, the error screen (forced with a throwing test page: it keeps the sidebar, shows the reference and offers Try again and Dashboard; no overflow at 390 px) and the not-found screen.

## Bugs (fixed)

1. **On a phone the closed drawer was still reachable by keyboard and screen readers.** The sidebar is slid off-screen with a transform, so Tab walked through its invisible links (5 of the first 6 Tab presses landed inside it) and assistive technology read it. It is now `inert` while closed below `lg` (tracked with `matchMedia`, so rotating or resizing a window works) and not inert on desktop or while open.
2. **No way past the sidebar for a keyboard user.** There is now a "Skip to content" link (the first Tab stop; it is visible only when focused) that moves focus to the main area (`#admin-main`).
3. **Opening the drawer left focus on the button behind it.** Focus now moves to the drawer's Close button, and returns to the Open menu button on Esc or Close.
4. **The not-found screen had no heading** (`h1`), so the page had no title element for a screen reader; `EmptyState` takes `asH1` for a whole-page empty state and not-found uses it.

## Checked and fine

The keyboard shortcut letters, the nav list and the palette ranking (`scripts/check-admin-shell.mts`, which now also asserts the three accessibility rules above), the sidebar footer buttons added in A1 on all three layouts, and the loading skeleton's shape.

## Left for planning / later

- The browser tab title on the error and not-found screens is the site name only (the page-level `metadata` of the route that failed, or none). Next.js does not let those screens set their own title reliably, so it is left.
- Unknown ids still answer 200 with the not-found screen, because the admin pages sit under a `loading.tsx` (a skeleton is sent before the page runs). That is harmless for an admin area (the public site's pages use the `(entity)` route group for real 404s).

## Not verified

A screen reader (VoiceOver / NVDA) walkthrough of the drawer, the palette's behaviour with a real IME, and the hover peek with a touch screen.
