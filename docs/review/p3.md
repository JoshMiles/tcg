Pages: `/cards` (Card Dex and its card dialog), `/cards/[card]/copies`, `/copy/[seasonId]/[copyId]` (journey, engraved flip card, share, pin) and `/c/[uid]`. Reviewed 2026-10-15 against the seeded review data (`docs/review.md`).

## Findings

### Bugs (fixed)

- **The first-copies list in the card dialog said "pulled by" for every copy.** A copy numbered later (the backfill, which is every copy of a season that started before serials) was not necessarily pulled, so "#1~ pulled by @x" was a guess presented as fact; a gifted or forged first copy had the same problem. The dex-card API now returns each first copy's origin and the dialog words it by origin (pulled by, given to, forged by, "first held by" for a numbered-later copy). The same wording rule is `ORIGIN_BY` in `lib/serials-core.ts`, checked in `scripts/check-flip-back.mts`.
- **The engraved back of the flip card said "Created".** Its history lines now read "Pulled by @x" / "Given to @x" / "Forged by @x" (or "First recorded") by origin, the same words as the journey (the request behind the P1 copy-page change). The staff-only admin copy page keeps "Created".

### Visual (fixed)

- **Dialog stat labels were cut off on a phone** ("COPIES OUT ..." for "Copies out there"). The labels now wrap.
- **Journey summary tiles were cut off on a phone** ("never left the first coll...", "In a collecti..."). The values and notes now wrap.

### Improvements (for you to pick)

1. **Closing a deep-linked dex dialog leaves `?card=<n>` in the address**, so a refresh or the Back button reopens it. Dropping the parameter on close would make the dex behave like the grid-opened dialog.
2. **Not-found copy, uid and card pages answer HTTP 200** (with `noindex` and the "That page isn't here" content). It is how Next.js streams a page that has a loading skeleton: the status is sent before `notFound()` runs. Harmless for people and search (noindex), but monitors and link checkers see a 200. Fixing it means dropping the loading skeleton for those routes or checking existence in a layout, so it is a design call.
3. **The dex dialog's First copies rows repeat the person** when the first copy's first and current holder are the same ("first held by @x ... held by @x"); the second mention could be dropped.

## Follow-up: the three improvements, done (2026-10-15)

1. **`?card=` no longer lingers**: closing a dex dialog that was opened from a link removes `card` from the address (other parameters such as `season` stay; a grid-opened dialog never touched it).
2. **Real 404s**: `/copy/...`, `/c/<uid>` and `/cards/<card>/copies` moved into a new route group `app/(entity)/` that has the same frame but no `loading.tsx`, so a missing copy, uid or card answers HTTP 404 (it was 200 with `noindex`) with the same "That page isn't here" content and frame. A found `/c/<uid>` is now a real 307 redirect. The skeleton shown while these pages load is gone (they are quick lookups). The guard audit (`check-staff-guards.mts`) now also covers `(entity)` viewer actions.
3. **First copies**: when the first holder still holds the copy, the row reads "first held by @x · 15 Oct · still holds it" instead of naming them twice.
