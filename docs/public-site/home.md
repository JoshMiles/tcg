# Home page and live indicator

> Read this when you touch the home page or the live indicator.

- `/` home: hero + collection search (a purple **Log in with Twitch** button when signed out), a **Your standing** card for signed-in viewers (rank, points, points to pass the collector above, cards progress, waiting trade offers, My profile / My stats; `viewerStanding()` in the pure `lib/home-data.ts`, which also has `seasonCountdown()`), a "New here?" pointer to the FAQ (only when there is no standing), a season snapshot row, top 8 (the viewer's row highlighted, or appended as "You" when outside the top 8), recent pulls (from the activity log, filtered to the season; card names link to the dex), rarest cards (link to the dex). **Layout and live bits**: a compact hero (the username search only for signed-out visitors, since the top bar has search), then Your standing, then the live grid (snapshot, top collectors, **Recent pulls**), then the **Card of the week** (`app/components/site/PrintOfWeek.tsx`, only when `potw:current` points at a print that still exists; see docs/serials.md), then New here?, then the rarest cards with how many collectors hold each and who holds the most (`ownersByCard`, hidden / private collectors left out). **Recent pulls** is the client `RecentPulls` (`components/site/`), starting from the server list and polling the public `GET /api/recent-pulls` every 45s while the tab is visible (short CDN cache; items built by `recentPullItems` in `lib/home-pulls.ts`, which never includes admin-hidden collectors; **pulls and granted cards** (admin gifts, the grant webhook) are both listed, a grant reading "was given" with its card name and stars taken from the season, found by `getRecentCardArrivals` in `lib/site-data.ts` which reads the whole activity log because a run of triggers, collections shown and trades can bury pulls in a shorter window; `scripts/check-recent-pulls.mts`); Full Art Holo / Full Art / 5★ pulls are highlighted (`notableReason` in `lib/home-data.ts`). When the season has ended (`endedAt`) or none is running, a **How <season> ended** podium (top 3 from the saved wrap-up snapshot, link to the final standings) is shown. The season pill shows the name plus the countdown or "in progress" (never "live now": that word belongs to the real LIVE indicator). `scripts/check-home.mts` covers the helpers. `/stats` season stats (`computeStats` in `lib/site-data.ts`), `/cards` card dex (rarity filter / search / sort; **click a card** for its details: pull chance, copies and collectors out there, per-version odds / counts / points, and the **top collectors of that card** ranked by copies via `ownersByCard()` in `lib/site-data.ts`; logged-in viewers also get Everything / Collected / Missing filters and ✓ badges). Season pickers use `?season=<id>`; `lib/site-seasons.ts` `getActive()` resolves it and hides drafts.
- **Live indicator**: a red pulsing **LIVE** pill in the nav plus a banner on the home page (title, game, viewer count, Watch button) whenever the channel is live. `getLiveStatus()` (`lib/twitch-live.ts`) asks Helix `streams?user_login=` with the existing app token (no new env vars; needs `TWITCH_CLIENT_ID/SECRET`), cached in KV (`twitch:live`, reused for ~45s across instances, expires after 5 min) so traffic never maps 1:1 to Twitch calls. `SiteHeader` (streamed with the nav) reads it server-side and hands it to `LiveProvider` through `LiveSeed`; `LiveProvider` (`components/site/Live.tsx`) polls `GET /api/live` every 60s (and when the tab becomes visible), with `cache: 'no-store'`, because the route's `stale-while-revalidate` otherwise lets the browser show an old answer. Unconfigured/unreachable Twitch = no indicator, never an error. The channel login is `CHANNEL_LOGIN` in `lib/site.ts`.
