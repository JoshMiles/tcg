# Closed alpha / beta

> Read this when you touch the closed alpha / beta gate, testers or the alpha / beta label.

## Closed alpha / beta

- **Closed alpha / beta (ROADMAP Track 16)**: an admin can lock the public site to a testers list (Settings → Access). Settings are KV `access:settings` `{ mode: 'open' | 'beta' | 'alpha', label: 'none' | 'alpha' | 'beta', message?, v }` (`v` rises on every save), testers the hash `access:testers` (login -> `{ tier, addedBy, addedAt, note? }`, max 500), changes are in `access:log`. All of it lives in `prodKv` like the staff list, so a preview deployment cannot change it. Mode `open` (the default) behaves exactly as before. Pure parts are in `lib/access-core.ts` (`canEnter`, `isExemptPath`, cleaning), the signed `tcg_access` cookie in `lib/access-token.ts`, the middleware's decision in `lib/access-gate.ts` (`gateDecision`) with its cached mode read in `lib/access-edge.ts` (30 s; on a database error it keeps the last good copy, and fails open only on an instance that has never read it), the KV side in `lib/access.ts`. Two layers: the middleware (cookie + cached mode; no cookie and signed in -> `/auth/access`, signed out -> `/closed`, a gated API -> `403 { ok: false, error: 'closed' }`) and the authoritative re-check, `requireSiteAccess()` in `SiteShell`'s `Gate` (covers every public layout; the page is rendered inside it) and `siteClosedResponse()` in the signed-in APIs (trades, account, notifications, feedback). The FAQ is closed too (it is for testers). Someone without access sees privacy and terms in `ClosedShell` (name, page, legal links; no nav, search or site links): `requireSiteAccess()` returns false for them and `OpenPageShell` (privacy, terms, not-found) switches. Because the frame is prerendered, `Gate` redirects after the response has started: someone whose access cookie still passes the middleware but who has just lost access (a tester removed under an hour ago) can get that page's data in the stream before the browser is sent to `/closed`. This is within the "lose access within the hour" the admin is told; the middleware is what keeps everyone else out. The layouts skip the check on the paths that stay open (the middleware passes the path in an `x-tcg-path` request header). `/auth/access` issues the one-hour cookie from the live staff and tester lists, so removing a tester or changing the mode (`v`) reaches everyone within the hour. **Always open:** `/privacy`, `/terms`, `/closed`, `/login`, `/auth/*`, `/admin`, `/mod`, `/api/twitch/*` (still answered by `extensionCors`, never gated), `/api/version`, webhooks, cron, overlay, collection, `/api/seasons`, account export / deletion, and any path with a file extension (static files, the overlay, robots.txt). Add a path to the allow list in `isExemptPath` and the check, never in the middleware alone. While not open, `robots.ts` disallows everything except the two open pages and the sitemap lists only them. `/closed` (noindex) says who can get in, shows the admin message, **Log in with Twitch** or "signed in as @x but not on the tester list" with Log out. Testers (16.2): adding one writes the permanent `special:alpha-tester` / `special:beta-tester` achievement straight into `user:<u>:ach` (pseudo-season `special`, kept by `syncAchievements`, listed first with a gold-purple style, never taken back); the tester record is in the data export and removed on account deletion. Mods can read the list at `/mod/testers`; the user admin page's Admin tab has a Tester picker. Check: `scripts/check-access.mts`.

- **Alpha / beta label (ROADMAP 16.3)**: when the KV key `access:settings` (ROADMAP 16.1, Settings → Access) has `label: 'alpha' | 'beta'`, `SiteShell` renders `BetaBanner` (client, a thin strip above the nav: the admin `message` or the default text, a **Report a problem** link to a prefilled GitHub issue (`reportProblemUrl(path)`), dismissible for the session via `sessionStorage` key `tcg_beta_banner`) and `SiteNav` shows an ALPHA / BETA pill next to the logo (not dismissible). The admin layout shows a small "Site: closed beta / open beta" note. `lib/site-label.ts` reads only `label`, `mode` and `message` (so it works without the 16.1 code); the label is independent of the lock mode. Check: `scripts/check-site-label.mts`.
