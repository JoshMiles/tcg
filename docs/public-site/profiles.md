# Profiles, collection and binder

> Read this when you touch the profile page, its widgets and layout, the collection grid, the binder, the card dialog, accents, share my stats, find a collector.

- **Profile Collection tab tools** (`lib/collection-view.ts`, pure; used by `CollectionGrid`): search (name or #), a Show filter (collected / everything / missing / duplicates / special versions), rarity, sort (number / rarity / points / copies / name, with a reverse button), clickable **per-pack progress** bars (also a pack filter; only shown when the season has 2+ packs), and **Compare with me**: when a signed-in viewer looks at someone else's collection the page passes `mine` (their copies per card, from the season collection already loaded) and the grid adds a summary line plus the filters They have, I lack / I have, they lack / We both have. `applyView` returns indexes so the card detail still steps through the visible, collected cards. `scripts/check-collection-view.mts` covers it.
- **Binder (Collection tab layout)**: a **Grid / Binder** switch above the Collection tab's filters (remembered in `localStorage` `tcg_collection_layout`; the server render is always the grid). The binder (`app/u/[username]/Binder.tsx`, pure layout in `lib/binder.ts`: `buildBinderPages`, `buildSpreads`, `spreadOfPage`, `clampSpread`; `scripts/check-binder.mts`) shows a leather cover, then pages of 3x3 pockets, a pack at a time in set order (card number), with an empty "#14 Angrygidds" pocket for every card still to find (names are public in the Card Dex). Wide screens (>= 1024px) show two pages like an open book that open on the cover and turn with a 3D leaf (`.bn-leaf-*`, 0.7 s; forward / back; one spread per turn, a longer jump lands directly); phones show one page with a short fade and turn it with a horizontal swipe (touch or pen, 50 px and mostly sideways; a swipe never counts as a tap on a pocket; the binder has `touch-action: pan-y` so the page still scrolls). Reduced motion (device or the site's Motion setting) swaps pages with no animation. Arrow keys on the focused binder, Back / Next buttons and per-pack jump chips turn pages; a collected pocket opens the same card dialog as the grid (`onOpen`), and carries the holo, version mark and x N badge. The filters and the uncollected toggle apply to the grid only. CSS `.bn-*` in `globals.css`.
- **Profile experiments** (opt-in in Settings → Experimental; they change the OWNER's public profile): `showcase` (their 3 most valuable copies in the header, `topCopies()` in `lib/profile-data.ts`), `wishlist` ("Looking for": up to `WANTED_MAX` = 6 card numbers in `UserSettings.wanted`, shown on the Collection tab; a visitor who owns one gets a one-click trade offer). `ProfileBase.settings` carries the owner's settings; `showcase` is only computed when the experiment is on.
- **Profile Overview widgets** (the default tab of `/u/<name>`; tabs are now Overview / Collection / Stats / Trades / Activity, `profileHref(name)` is the Overview and the collection is `?tab=collection`): a 12-column grid of widgets the OWNER arranges on their own profile. Registry + sanitizer in client-safe `lib/profile-widgets.ts` (`PROFILE_WIDGETS`: stats, showcase, rarity, progress, rarest, recent, activity, trades, awards, wishlist, collection; allowed spans per widget; `DEFAULT_PROFILE_LAYOUT`), stored in `UserSettings.profileLayout` (null = default; an empty array is a deliberately empty profile). Widgets are server components in `app/u/[username]/widgets.tsx` (`renderProfileWidget`; a visitor gets null when a widget has nothing to show, the owner always gets a panel with a hint), `OverviewTab` renders them (the owner gets every widget rendered so an added one shows real content at once) and `ProfileGrid` (client) owns **Customize profile**: drag to reorder, drag a right edge / arrows to resize (snaps to allowed spans), remove, add from the library, Save / Reset / Cancel, through `saveProfileLayoutAction` / `resetProfileLayoutAction` (viewer from the session). To add a widget: type + def in the registry, a case in `renderProfileWidget`, and `loadWidgetData` if it needs extra reads. Showcase and Looking for are widgets (the wanted-card picker is in Settings → Profile, `UserSettings.wanted`), `accent` remains the one profile experiment. The account menu says **My profile**.

- **Prints-first card dialog (profile Collection grid and binder, `CardDetail` in `app/u/[username]/CardDetail.tsx`)**: opening a card shows **its prints first**: one small tile per owned print grouped by version (Regular, RH, FA, SH; edition ascending, newest last) with the holo, the `SerialChip` edition (gold with the bonus) and `Print #uid`. Choosing a tile opens **the print**: the `FlipCard`, "Edition #7 of 31 made", the print number, points (with the edition bonus), a three-line journey (origin + date, then `GridCard.copies[].j`: the last two events after minting, worded by `histText` in `lib/flip-back.ts` with private collectors masked; only present for prints that have moved), and the buttons **Open print page**, **Share this print** (Web Share, else copies the print page link), **Pin to my profile** (owner, `pinnedUid` from `b.settings.pinned`), **Offer a trade** (visitor, `?want=<card>.<variant>`) and **Upgrade** (owner, where the card allows it; it spends the newest prints, not the one shown). **Back to all prints** returns to the tiles; a card with exactly one print opens straight on it; Esc closes, the arrow keys step to the next card. The card-level information (value, pull chance, per-version table, the working) sits under the **Card details** disclosure. Layout is the pure `copiesForDialog` in `lib/collection-view.ts` (`scripts/check-collection-view.mts`): tiles capped at 60 with **Show all N**; a season that does not track prints shows one tile per version with `x N`. The prints are already in the page payload (nothing is fetched).

- `/collection`, **Find a collector**: a search box that suggests collectors as you type (`CollectorFinder`, the same `/api/search` source) plus the top collectors. Every collection is now a profile (below).

- `/u/[username]`, **the profile page** (no auth): header (`ProfileHeader`: avatar, name, Complete badge, awards, rank / points / cards, progress, Trade / Share / Leaderboard buttons; the owner also gets a link to My Stats) and four tabs as `?tab=` links (`ProfileTabBar`, `lib/profile-url.ts`): **Collection** (the former collections page: rarity tiles + `CollectionGrid`, click a collected card for details; uncollected hidden by default, toggle remembered in `tcg_hide_uncollected`), **Stats** (points breakdown, versions owned, most valuable copies; `computeUserStats(..., { upgrades: false })` so the costly upgrade projections are skipped), **Trades** (their open board listings with the usual take-this-trade actions, plus a completed-trade count) and **Activity** (their pulls, upgrades and completed trades only: `PUBLIC_ACTIVITY_TYPES`, never admin grants / resets / declined offers; empty for collectors an admin hid). Data for all tabs comes from `lib/profile-data.ts` (`loadProfileBase`: the owner viewing their own profile skips the 20 s shared leaderboard so a fresh upgrade shows at once; `buildGridCards` only runs for the Collection tab). A name nobody has used shows a "We haven't seen X yet" page rather than an empty grid. **Always build profile links with `profileHref()`.** **`/collection/<name>` permanently redirects here** and must keep doing so (Discord posts, the Twitch panel, bookmarks); `scripts/check-profile.mts` fails if any internal link still uses the old form. The collection-tab behaviour described next is unchanged:
  - Shows owned cards with ×N badge for duplicates and total pull count when it exceeds unique count. **Clicking a collected card opens a detail view** (`CardDetail.tsx`, client, opened from `CollectionGrid.tsx`): art (click a variant row to preview it), rarity, pull chance, per-variant copies / pull odds / points each, the card's total value and share of the viewer's score, and a serial-bonus note. Uncollected cards stay a `?` and don't open; a **Hide uncollected / Show uncollected** toggle above the grid. **Uncollected cards are hidden by default** (also in the server render, so no flash); choosing "Show" is remembered per device (`tcg_hide_uncollected` = `0`). With nothing collected yet the placeholders stay visible and the toggle is hidden. All values are precomputed server-side from `getSeasonLeaderboard`.

- **Layout presets (ROADMAP 8.7)**: the layout editor's **Start from a preset...** menu applies one of `PROFILE_PRESETS` in `lib/profile-widgets.ts` (Collector = the default, Showcase, Trader, Minimal) to the draft only; the owner still presses Save, and Cancel restores the saved layout. `scripts/check-user-settings.mts` checks that every preset sanitizes to itself.
- **Profile accent and the inline editor (ROADMAP 8.4, 8.5)**: the owner's header has an **Edit profile** button (`ProfileBasicsEditor`, a client component in `app/u/[username]/`) that opens the bio and header colour in place; **Save** calls the server action `saveProfileBasics` (`actions.ts`: the viewer comes from the session, the values go through `sanitizeUserSettings`, then `revalidatePath`). Settings has the same two fields. A stored `accent` experiment id is dropped harmlessly. `UserSettings.accent` is one of the 12 named `ACCENTS` or a custom `#rrggbb`; `AccentPicker` (`components/site/`) offers the swatches, a colour input and a hex field. A custom colour is lightness-clamped to 35% to 70% on save and again when read (`clampAccent` in `lib/accent.ts`; note `lib/palette.ts` is the admin command palette, so the colour maths lives in its own file). Checks: `scripts/check-collection-view.mts`.
- **Share my stats image (ROADMAP 8.10)**: the My Stats button builds a stats card, not a card collage: `ShareSpec.statsCard` (`StatsCardShare` in `lib/share-image.ts`) holds the rank, the score and six figures (different cards with a progress bar, prints, progress bonus, best edition, rarest print with its version and "1 in N", trades completed), and `spec.cards` is the strip of their three most valuable prints. `buildStatsCard` / `rarestPrint` in `lib/share-stats.ts` work the figures out (pure); `statsLayout()` places the parts for a post or a story; `drawStatsCard` in `app/components/ShareImage.tsx` draws it, with the rarest print's rarity colour as the accent. The profile Share menu and Share tab images are unchanged. `scripts/check-share-stats.mts` covers the figures and the layout.
- **Closed binder and the visitors' default view (ROADMAP 8.8, 8.9)**: in two-page mode the binder with the cover showing is drawn as one page, centred at single-page width like a closed book (`data-state` on `.bn-cover-wrap`: `closed`, `opening`, `closing`, `open`; the leather is clipped to its middle half and the book slid a quarter left, both animated by `bn-wrap-open` / `bn-book-open` and switched off for reduced motion; phone / one-page mode is unchanged and the share image never includes the cover). `UserSettings.collectionView` (`'grid'` default, or `'binder'`) is the view the owner's collection tab opens in; it is set in Settings and in the binder editor ("Show visitors the binder first", `saveCollectionViewAction`). A visitor's own choice wins: `?view=grid|binder` in the URL, then the view remembered on their device (`tcg_collection_layout`), then the owner's default. Included in the data export with the rest of the settings.
