# TCG Bridge

A small Windows app for the stream PC. Mix It Up's Developer API only listens on that PC (`http://localhost:8911`), so the TCG site, which runs in the cloud, cannot reach it. TCG Bridge sits in the tray, asks the site for jobs (balance, take or give currency, chat viewers, a chat line), runs them against Mix It Up and posts the answers back. Site side and job details: [docs/admin/mixitup.md](../docs/admin/mixitup.md).

The current version is 0.30.0 (`package.json` is the source of truth, and the app's About page shows the one that is running). The feature sections below say which version added each part. The app has its own semver, separate from the site's `<major>.<PR number>`; see "Version rule" and "Releases" under Develop.

## Install and pair

1. On the site open Admin > Mix It Up and press **Download TCG Bridge** (or take the newest `bridge-v*` release from [GitHub releases](https://github.com/JoshMiles/tcg/releases?q=bridge-v&expanded=true)). Run `TCG-Bridge-Setup-<version>.exe`.
2. **The installer is not code-signed.** Windows SmartScreen says it "protected your PC": press **More info**, then **Run anyway**.
3. In Mix It Up switch the Developer API on: Services > Developer API > Connect.
4. On the site press **Pair TCG Bridge** and type the code into the app (the site address is `https://cheesytcg.app`). The app turns green when the site and Mix It Up both answer.

It starts with Windows and lives in the tray; closing the window keeps it running. Quit from the tray menu. The window (0.27.0, ROADMAP 59.2) opens at 1280 x 800 (smallest 960 x 620) and remembers its size, place and maximised state in `settings.json` (`window`; the saved spot is used only if its title bar is still on a screen, otherwise it opens centred at the default, and the size is clamped to that screen; logic in `src/winstate.ts`). When it is wide, the cards on the Home, Controls, Buttons and hotkeys pages sit in two columns. The window has its own title bar: minimise, and close (which only hides it to the tray). **Sidebar grouped by job (0.29.0, ROADMAP 59.4).** The sidebar on the left is a nav of buttons (the active one carries `aria-current`) in groups: **Live** (Home), **Stream tools** (Controls, Feed and history), **Staff** (Viewers and cards, This stream; only on a staff PC), **Setup** (Connections, Overlay and OBS, Buttons and hotkeys, Notifications, App) and, on its own at the bottom, **About** (version, updates and What's new). The footer shows "Paired as <name>" and the PC name. The app opens on Home, or on the pairing screen when it is not paired. Below 1100 px wide the sidebar folds to icons (each keeps its name for screen readers and a tooltip). Icons are inline SVG. Cards were moved, not redesigned: the Site, Mix It Up, OBS, Stream Deck plugin and Unpair cards are on Connections, and every "Fix" jump from the status pill lands on the page that holds the card. The Site, Mix It Up and OBS links are cards, each with a coloured dot and a one-line state in words. **Status pill (0.28.0, ROADMAP 59.3).** The title bar has one pill: "All good" (green dot) or "N things need you" (amber dot). Pressing it opens a short list, one row per item with a reason and a button: update ready (**Restart**), couldn't check for updates (**Try again**, which runs Check for updates), not paired, the site unreachable or no longer accepting this PC, Mix It Up not connected or its Developer API off, OBS switched on but not connected (**Fix**, which opens the page and card that fixes it). From the keyboard, Tab reaches the pill and the buttons, Escape or a click outside closes the list. The items are built by a pure function from the app state (`src/status.ts`); no new service state. "Updated to x.y.z" is a toast at the bottom right for a few seconds with **See what changed** (opens What's new), shown once. **Card style (0.28.0).** Every page uses one card header (a plain title, with a status line under it on the Connections cards), one yellow button at most per card, a dashed "empty" box wherever a card can have nothing to show, one result line per card, and a small **How?** toggle for long help text (rules in the comment above `.card` in `renderer/style.css`). **Home dashboard (0.30.0, ROADMAP 59.5).** Home fits 1280 x 800 without scrolling. Across the top are connection chips (TCG site, Mix It Up, OBS only when it is switched on, Stream Deck plugin only when it is installed): a dot and a short state, and a click opens that card on Connections. The left column (about 340 px) is for doing: **Pulls** (Open or Paused and one big **Pause pulls** / **Resume pulls** button, the reason when a scene paused them), **Happy hour** (three presets, **Custom...** which jumps to the Custom happy hour card on Controls, the countdown and **End now**) and **Pull queue** (the first 4 rows, "and N more", **Skip next**, **Clear queue** and the refund line). The right column is for watching: a **This stream** strip (pulls, big pulls of 4 stars and up, Brie Bucks spent, top puller), one **Live feed** (pulls, event rewards and Mix It Up jobs merged, newest first; each row has time, a badge P/E/J or ! for refused or failed, viewer, text and a tag; filter chips All, Pulls, Events, Jobs, buttons with `aria-pressed`, the list has an accessible name) and **Ready to go live** (one line "All N checks passed at 19:28" plus **Run again** when the last run passed, otherwise only the failing lines; the Mix It Up command check is one line inside it). The numbers and the feed are built by pure functions (`src/home.ts`, checked in `scripts/check-home.ts`). The pulls come from the live feed sink (55.11), which the app now always records; the site is told the window is "open" (`bridge:feed`) while the main window is shown or the pull feed window is open, so pull details keep arriving. The pull counts therefore cover what reached the app while it ran; a restart mid-stream starts them again. **Feed and history (0.30.0)** is in the sidebar for everyone: the same feed with the same filters and a longer list (100 rows); the dashboard's Activity part (55.13) shows below it on a staff PC only. The Controls page keeps the Custom happy hour card.

The three tray icons differ by badge shape as well as colour: a dot for connected, a half-filled ring for partly connected, a cross for offline.

## Start-up and updates (0.5.0)

Every start opens a small start-up window first (also when Windows starts the app minimised, where it then leaves only the tray). It checks the latest GitHub release: "Checking for updates", then "Downloading update x.y.z" with a bar, then "Installing update" (the app restarts by itself) or "Starting". With no internet, or a check slower than 8 seconds, it starts anyway and the status pill lists "Couldn't check for updates" (with **Try again**). A download that fails (or stalls for 30 seconds) starts the current version and is tried again at the next start. Updates download and install only in the start-up window, never on quit. While the app runs it checks every 6 hours (and on **Check for updates**); a newer version is not downloaded, the status pill lists "Update x.y.z is ready" with **Restart**, and the About page says "Version x.y.z is available. Restart TCG Bridge to install it." and offers **Restart to update** (also in the tray menu), which quits the app the normal way and starts it again, and the start-up window then downloads and installs the update. The start-up logic is `src/startup.ts`, a small state machine with no Electron imports (`npm run check` covers it).

## OBS (optional)

The app can also watch OBS on the same PC: it tells the site when the stream starts and stops, which scene is on air and whether the TCG overlay browser source is in that scene and visible, and the site's **Refresh overlay in OBS** button (Admin > Settings > OBS Overlay) presses "Refresh cache of current page" on it.

1. In OBS (28 or newer) open Tools > WebSocket Server Settings, tick **Enable WebSocket server** and copy the **Server Password**.
2. In the OBS card on the Connections page tick **Talk to OBS**, check the address (`ws://127.0.0.1:4455` is the OBS default), paste the password and press Save. The password is stored encrypted on this PC and is never sent to the site, and only `ws://localhost` and `ws://127.0.0.1` addresses are accepted.

**Big pulls (0.6.0).** A pull rule on the site can also save a clip, switch to a scene for a few seconds, or show a source while a pack opens. The app does only those three things, only with scene and source names it reported itself. A clip needs the OBS replay buffer running (Settings > Output > Replay Buffer in OBS); if it is off, the site's log says so. Tick **Start the replay buffer when the stream starts** in the OBS card to have the app start it for you (off by default).

**Control from the PC (0.7.0).** The **Home** page has a switch to pause pulls (also in the tray menu), the **Buttons and hotkeys** page a list of Stream Deck buttons with **Copy** and three global hotkeys (empty by default; a clash is shown next to the field), and the **Controls** page a **Pull queue** section with **Skip next pull** and **Clear queue** (a skipped paid pull is refunded). The buttons are web addresses on `127.0.0.1:47653` with a random key in the path, answered only to GET without a browser Origin: in the Stream Deck app add a "Website" action, paste the address and tick "GET request in background". If another program holds the port the page says so. The queue is read only while its section is open, at most every 5 seconds.

**Happy hour from the app (0.15.0).** Home has the three presets and **End now**, and the Controls page has a **Custom happy hour** card (0.30.0): minutes (1 to 240), free or a percent off (1 to 99), **Start** and **End now**. The tray menu has a **Happy hour** submenu with three presets (15 minutes free packs, 30 minutes 50% off, 60 minutes 25% off) and **End now**. Starting while one runs replaces it, the same as on the site's Paid pulls tab. The site does the work (the same functions as the page and the Stream Deck), so the numbers are checked there, and the audit log and the Discord admin log show it as done by TCG Bridge. While one runs, Home, the Controls page and the tray tooltip show "Happy hour: free packs, 12:34 left", counted down from the end time the site sent. The app asks the site again every 30 seconds and after every start or end, so a happy hour started or ended on the page shows up here too; the app never decides by itself whether one is running.

**Event feed (0.19.0).** Event rewards are rows in the Home live feed (0.30.0 merged the old Events and Jobs lists into it), and the live pull feed window an **Event rewards** section, listing the last 30 event rewards newest first: time, event (gifted subs, bits, raid, channel point redeem), viewer, amount, and what it earned or why it was ignored (the same lines as the site's Mix It Up log). The app asks the site every 5 seconds while either window is open and every 30 seconds otherwise.

**Live stats in OBS (0.17.0).** Overlay and OBS page, **Live stats in OBS** (off by default): pick an OBS text source (GDI+ or FreeType, from the list OBS reported) for each stat you want: packs this stream, last big pull (4 stars or more), top puller, happy hour countdown, pack goal progress (0.18.0, "Label: 37 / 50", set on the site's Mix It Up page), queue length. The app writes the text into that source, at most once a second and only when it changed, and never touches a source you did not choose; setting a stat back to "Not shown" leaves the source's text as it is. A stat with nothing to show (no big pull yet, no happy hour) empties its source. On a very long stream the pack and puller numbers may undercount, because the site keeps its last 500 pulls.

**Pause pulls on scenes (0.14.0).** Overlay and OBS page, **Pause pulls on scenes** (off by default): switch it on and tick the OBS scenes (the list OBS reported) that should stop pulls. While one is on air the app pauses pulls through the same switch as the Home page, with the reason "scene <name>" (the Home page and the site's Mix It Up page say "Paused by scene: <name>"); chat `!pack` and paid pulls get the usual "Packs are paused, back soon". Switching to any other scene opens pulls again, but only a pause a scene made: a pause you set by hand (site page, Home page, tray, Stream Deck) is never lifted by a scene change, and a hand pause made while a scene has paused takes over and stays until you lift it. When the app starts, or OBS connects again, the rule is applied once to the scene on air. If the site cannot be reached the app tries again on the next scene change or after 30 seconds. If OBS drops while a chosen scene is on air, pulls stay paused until OBS returns or you resume by hand.

**Chat and Brie Bucks (0.8.0).** Everything here is switched on from the site's Mix It Up page (Chat and Brie Bucks tab, and a rule's "Say in chat" line) and is off until then. The app posts the lines the site sends to chat (the start and end of a stream, and a big pull's shout, which the site sends on the card reveal). It can save every viewer's Brie Bucks to a CSV at the start and end of a stream, in `Documents\TCG Bridge\backups`, keeping the newest 30; **Open backups** on the App page opens the folder. It also keeps a ledger of every charge and refund it ran (`ledger.json` in its data folder, the last 2000), which the site asks for at the end of a stream to compare with its own record; balances are not compared. Viewers are read from Mix It Up's top-users list, which leaves out bots.

The overlay is the browser source whose address is `<paired site>/overlay.html?...`; only its name is reported, never the address or key. An overlay inside a nested scene is not seen; an overlay inside a group is.

## Alerts, tests and the log

- **Alerts.** A Windows notification when the site link, Mix It Up or OBS drops while OBS says the stream is live (or any time OBS is switched off in the app), and one when it comes back. A part must be down 15 seconds first, and a part alerts at most once every 2 minutes. The "Alert me when a link drops while live" switch in the window turns the notifications off.
- **Checklist** (0.13.0; the Ready to go live card on Home, which since 0.30.0 is one "All N checks passed at 19:28" line with Run again when the last run passed and shows only the failing lines otherwise, and "Checklist" in the tray menu, which answers with a notification). Looks at everything at once, one green or red line each with the reason in words: the site answers, Mix It Up (found, the chosen currency exists, a balance can be read for the channel name), OBS (grey "Not used" when Talk to OBS is off), the TCG overlay is in the scene on air and visible, an active season, packs that can be opened, the pull queue empty, pulls not paused, and the happy hour (shown, never red). It changes nothing: no chat message, no charge. Each check gets 5 seconds, so one slow part never hangs the list. The window keeps the last result, and the app reports it to the site (`report` with `type: "checklist"`), which shows it with "ran N minutes ago" on the Mix It Up Overview tab. The season, packs, queue, pause and happy hour come from `GET /api/bridge/checklist`. The wording is in `src/checklist.ts`.
- **Tests** (buttons in the window, each answers in words): **Test Mix It Up** (Developer API, version, the chosen currency by id and name, a balance for a Twitch name, prefilled with the channel name), **Send test chat message**, **Check OBS**.
- **Start Mix It Up.** When Mix It Up is not found the window offers **Start Mix It Up**. It launches only `MixItUp.exe` from the path you chose with **Choose MixItUp.exe...**, else from Mix It Up's default install folder (`%LocalAppData%\MixItUp`). The **Start Mix It Up with TCG Bridge** switch (off by default) does it when the app starts.
- **Streamer tools (0.9.0).** All off by default, on the Notifications and App pages.
  - **Live pull feed window**: a second, resizable window (optionally always on top) with one line per pull as its card is revealed: viewer, card image, rarity and edition. It plays a short chime for a pull at or above the chosen rarity, with a volume and a mute switch. It is fed by the `pull-event` reveal job; while the window is open the app tells the site (`POST /api/bridge/report` with `{ type: "feed", on }`, on open, close, connect and every 6 hours) and the site then adds the pull's details to that job for every reveal, not only rule matches. Closing the window turns the switch off. A card image loads only from the paired site's own origin or a Vercel Blob host (`*.public.blob.vercel-storage.com`) over https; any other address is dropped and the line shows no image.
  - **End of stream summary**: when the site builds the stream recap it queues a `summary` job (packs, big pulls, top pullers, Brie Bucks taken and refunded, from the recap and the charge record, nothing recounted). With the switch on the app shows a Windows notification and a summary window; **Copy for Discord** copies it as plain Markdown.
  - **Start OBS with TCG Bridge**: like Start Mix It Up, it launches only a file named `obs64.exe`, from the path chosen with **Choose obs64.exe...**, else `C:\Program Files\obs-studio\bin\64bit\obs64.exe`, with that folder as the working directory, and not when OBS is already running.
  - **Uptime history**: while the app is paired it also reports Mix It Up's state (`{ type: "mix", found }`, on change and every 60 s) so the site can keep up and down changes of the bridge, Mix It Up and OBS per stream (Overview tab).
- **Staff tools (0.10.0).** Off by default, per PC: an admin turns on **Staff tools on this PC** on the site's Mix It Up page, and the Staff group (Viewers and cards, This stream) appears in the sidebar (Feed and history is there for everyone since 0.30.0; staff PCs get its Activity part). It can gift packs, grant a card, show a collection or a card, look up a viewer (copies, rank, recent pulls and refusals, Brie Bucks read from Mix It Up), open the viewer in admin, set extra pulls for this stream, switch the OBS scene (also in the tray), pause trading (also in the tray, with a confirm) and block or unblock a viewer from pulls. Every action is audited on the site as done via this PC. Revoking the PC ends it.
- **Staff notices and shortcuts (0.11.0).** On a PC with staff tools on, the site sends Windows notifications: Needs attention (a Discord channel switched off, a failed backup, data health), New reports and feedback, Paid pull refusals (at most one a minute for each reason, never for not enough Brie Bucks) and Deploys (a new build is live, with its changelog lines). Each kind has its own switch under Notifications, Staff notices (all on once staff tools are on). Clicking a notice opens its page in your browser; the app opens a link only when it is on the paired site's own address. A notice sent while the app is closed or offline is dropped, not shown later. The tray has Admin links (Dashboard, Mix It Up, Overlay Editor, Users); the This stream page has Back up now (the same backup as Admin Settings, audited) and a Quick search for a viewer, card or pack that opens its admin page; the Activity part of the Feed and history page shows recent pulls, grants and trades while it is open.
- **Preview overlay (0.23.0).** On a PC with staff tools on, the This stream page has a **Preview overlay** card (and the tray a **Preview overlay** item) that opens a window showing the site's overlay page at your OBS canvas size (OBS's base size when connected, else 1920 x 1080), scaled to fit. It has **Test pull** (the same simulated free chat pull as the site's Test pulls, for the first test viewer; if no overlay is connected it asks before queuing it anyway), **Show a card** (type a viewer name; their best card) and **Reload**. The window gets its own key from the site that only watches: it expires after 2 hours (Reload gets a new one), is never the OBS overlay key, and cannot take a pull from the queue, so OBS still plays every real pull. Test pull and Show a card are queued for the live overlay too, so OBS plays them as well. The window can only load the paired site's overlay page.
- **Log.** One file a day in the app's logs folder (**Open log folder**), kept 7 days: connects, drops, jobs (kind, result, time) and errors. It never holds the pairing token, the OBS password, the pair code or the overlay key. **Copy diagnostics** copies the versions, the statuses and the last 20 jobs as text, redacted the same way, for a bug report.
- **Mix It Up commands (0.4.0).** The app lists your enabled Mix It Up commands to the site (on start, every 5 minutes and when Mix It Up comes back) so a rule on the Mix It Up page can pick one, and it runs a command for a big pull only if it is in that list. The command gets the viewer, card, rarity and version as arguments.
- **Command check (0.20.0).** The site compares those commands with the ones it expects (`!pack`, the chat commands that are switched on, the Stream Deck buttons, the event commands) by name, and the Home page's Ready to go live card has a **Mix It Up commands** line: "N Mix It Up commands missing" with the names, or "Every command the site expects was found". The pre-stream checklist gets one grey **Commands** line. The app only lists switched-on commands and no Web Request address, so a missing command and a switched-off one look the same. It only shows the answer: nothing in Mix It Up is changed.
- **Error reports (0.21.0).** When something fails the app sends the site a short report (`report` with `type: "error"`: the part, a message of up to 300 characters redacted like the log and Copy diagnostics, the app version and commit). The parts are a job that failed (`job`, with Mix It Up or OBS named when the message says so), a Mix It Up call (`mixitup`), an OBS call (`obs`) and OBS still not reachable after several tries (`reconnect`). A viewer without enough Brie Bucks is not an error. At most one report per part per minute, and a report is dropped, never saved for later, while the site cannot be reached. Reporting never throws and a failed report is not reported again (`src/errors.ts`). The site shows them on the Mix It Up Connection tab.
- **Updates.** The About page shows the version and the commit it was built from (0.12.0), and a **Check for updates** button. After an update a toast says "Updated to x.y.z" once, and the first time the window is shown after an update the About page opens (once) at its **What's new** part with the release notes of every version since the last one seen, newest first, up to 20 (0.22.0). The notes come from the public GitHub releases (`bridge-v*`, fetched by the app, cached 6 hours in the app's data folder; if they cannot be loaded the page says so and links to the releases page). Each version shows "Version x.y.z" and only the bullets of that release's `## TCG Bridge` section (written in the PR for the streamer, 0.25.0); a release without that section shows its title line only, never the commit, PR or installer lines. Everything is shown as text. The cache is used only while it is under 6 hours old and holds a release for the running version, so an update published after the last fetch is found; when the range is still empty the page says "Release notes for this version are not published yet" with an **All releases** link. The What's new part's **Refresh** button deletes the cache file (`releases-cache.json`) and fetches again, and the About page's **Clear cached release notes** link deletes it ("Cleared"). The toast's **See what changed** opens that part of the About page, and its **All releases** button opens the releases page (`src/releases.ts`). The site's admin dashboard (staff who can see the Mix It Up page) shows the newest release next to the connected app's version and commit, and says "Out of date" when they differ; the app sends its version and short commit with its `hello` for that (ROADMAP 56.2).

**Stream Deck plugin (0.26.0, ROADMAP 57.13).** The Connections page has a **Stream Deck plugin** card, off by default. **Install Stream Deck plugin** switches the link on and opens `TCG Bridge.streamDeckPlugin` (built from `streamdeck/` and packed into the installer), which the Stream Deck app then installs; it says "Stream Deck app not found" when `Elgato\StreamDeck\StreamDeck.exe` is not in Program Files and no plugin of ours is installed. After an update, when the installed plugin's manifest version (`%APPDATA%\Elgato\StreamDeck\Plugins\tv.cheesygidds.tcgbridge.sdPlugin`) differs from the app's, the card offers **Update the Stream Deck plugin** once per app version. While the switch is on, a WebSocket server listens on `127.0.0.1` only (port 47654, or the next free one up to 47658) and writes the port and a fresh random token to `streamdeck.json` in the app's data folder; the plugin reads it and sends the token first, and anything else (wrong token, a browser Origin, another Host, no hello within 5 seconds) is closed. The Connections page shows connected or not. The plugin has seven keys: **Buff** (pick any Stream Deck buff or quick action), **Last buff again**, **Pause pulls** (shows paused, including a scene pause), **Happy hour** (three presets or custom; it counts down from the app's happy hour, and ending one takes a 1 second hold), **Test pull**, **Show a card** and **Stat**. Test pull and Show a card run the same staff actions as the Preview overlay window (57.10), so they work on a staff PC only: on any other PC the key shows its alert and the log says "Staff tools are off for this PC". Show a card uses the viewer named in the key's settings; the app does not know who pulled last (the stats' last big pull is not the last puller), so there is no "last puller" option. A **Stat** key (picked in its settings) shows the queue length, the packs this stream or the pack goal progress and does nothing when pressed, except the queue key: its first press shows "Press again to skip" and a second press within 3 seconds skips the next pull. The plugin tells the app which stats are on a deck (`stats` message); the app asks the site for them (the 57.4 `stats` action, every 5 seconds) only while such a key is visible or an OBS text source is mapped and OBS is connected, and pushes them to the keys in the state. Each key runs through the same code as the Controls page (or the staff pages), so the site's audit log shows TCG Bridge; a refusal shows the key's alert and the reason is in the log. Buff keys show the buff name only: the app has no active or cooldown data for buffs. The Mix It Up Stream Deck buttons above keep working. The plugin's version is always the app's, and a change under `streamdeck/` raises the app's minor version like one under `bridge/`. Code: `src/deck.ts`, `src/deckinstall.ts`, `src/deckprotocol.ts` (the same file as `streamdeck/src/protocol.ts`; a check keeps them identical).

## Develop

```
cd bridge
npm install
npm run typecheck   # tsc --noEmit
npm run check       # fake Mix It Up, fake OBS and fake site, no Electron needed
npm start           # build, then run the app
npm run deck        # build and pack the Stream Deck plugin into ../streamdeck/dist/ (npm run dist does this first)
npm run dist        # build the installer into release/ (not committed)
npm run icons       # redraw the app icon and tray PNGs from the site's icon (public/brand/icon.png)
```

`npm start -- --demo-startup` (ignored in the installed app) walks the start-up window through its states, then shows the window with made-up data; add `--shots=<folder>` to save a PNG of each and quit. `src/demo.ts` holds it and is left out of the installer.

`TCG_BRIDGE_DATA=<folder>` keeps the app's settings in that folder instead of the real user data folder, which is handy against a local site (`http://localhost:3000` is allowed as a site address; anything else must be https).

- `src/site.ts`, `src/mixitup.ts`, `src/obs.ts`, `src/jobs.ts`, `src/service.ts`, `src/settings.ts`, `src/alerts.ts`, `src/selftest.ts`, `src/launch.ts`, `src/log.ts`, `src/diagnostics.ts`, `src/buildinfo.ts`, `src/update.ts`, `src/startup.ts`, `src/control.ts`: plain TypeScript with no Electron imports, so the checks run under Node.
- `src/main.ts`, `src/preload.ts` and `src/splash-preload.ts`: the Electron glue (tray, windows, auto start, updates, encrypted token).
- `renderer/`: the main window (`index.html`, `style.css`, `renderer.js`) and the start-up window (`splash.*`), plain HTML, CSS and JS with no framework and no network fetches. Colours are the site's cheesy theme as CSS variables. Fonts are the site's own, Fredoka and Nunito, bundled in `renderer/fonts/` (SIL OFL 1.1, licence files beside them). Icons are Lucide as inline SVG; licences in `renderer/LICENSES.txt`.
- `scripts/make-icons.ts` writes the app icon and the tray icons from the site's own icon, `public/brand/icon.png`, adding the status badge to each tray icon (the installer turns `build/icon.png` into the Windows icon).

**Version rule.** A pull request that changes anything under `bridge/` (except this README) must raise the minor version in `package.json` above `main`'s, with patch 0 (0.11.0 to 0.12.0), and `package-lock.json`'s two version fields must say the same (`npm install --package-lock-only`). The PR job of `.github/workflows/bridge.yml` runs `scripts/check-version.ts` and fails with the reason in words; try it with `npx tsx scripts/check-version.ts origin/main`.

**Releases need no hand tag.** When a push to `main` changes the version in `package.json`, the workflow builds the installer on `windows-latest` and creates the tag `bridge-v<version>` and the GitHub Release itself, with `TCG-Bridge-Setup-<version>.exe`, its blockmap and `latest.yml` (the feed the app updates itself from). The notes are the bullets of the merged PR's `## TCG Bridge` section, then `## Details` with the PR title, the PR link, the commit link and the installer note (a PR without that section falls back to its Changelog bullets, else the title alone). If that release already exists the run skips with a notice. Pushing a `bridge-v<version>` tag by hand (it must match `package.json`) still builds and publishes the same way, for a release that failed.

**The commit on the About page.** `npm run dist` first runs `scripts/stamp.mjs`, which writes `build-info.json` (gitignored: the commit from `GITHUB_SHA` or `git rev-parse HEAD`, the UTC build date and the PR number from the commit subject `(#N)`) into the app. The About page reads "Version 0.12.0, built from abc1234 (PR #5) on 2026-10-28", the sha opening the commit on GitHub; a run without the file (`npm start`) reads "Version 0.12.0, dev build". **Copy diagnostics** has the same text, and the app sends the short sha as `commit` with its `hello` so the site knows it too (`src/buildinfo.ts`).
